# `kelpc doc`

A documentation generator over comments the lexer already keeps as trivia; the parser and AST are untouched.

- **Syntax.** A run of `///` lines directly above a `fun`, `datac`, `enum`, `trait`, `pd`, `const`, `static`, `extern type`, an enum variant, a `datac` field or a trait method documents it. A `//!` block before the first declaration (only `impl "..."` lines may precede it) documents the module. `////` is an ordinary comment. A `///` or `//!` attached to nothing is a `kelpc lint` warning, never an error (so the older "a `//!` above a declaration" use in `tests/fixtures/documentation_comment.kp` still compiles, and lint now warns about its second block).
- **Command.** `kelpc doc <file.kp|project dir>... [-o dir] [--format md|html] [--private] [--check]` and `kelpc doc --std`. One page per module plus `index`; default output directory `doc`. A project directory documents `src/`; module ids are paths relative to `src/`. Output is sorted and has no timestamps.
- **What is listed.** Only `pub` items (all with `--private`), their signature as `kelpc fmt` prints it collapsed to one line, the doc text, fields, variants, trait items, receiver methods of a public type, and the `impl Trait for Type` blocks found for each type. `unsafe` is shown on the item; so is a `requires capability` note for the domain a gated std module holds and for any gated import the function body names directly (not transitively). Backticked names that match exactly one type or trait in the set are linked. A shipped std module has no `pub`, so `--std` lists everything but `extern fun`s.
- **Machine output.** `kelpc doc <files or project dir> --format json` writes one JSON document to stdout: `schema`, `modules` (sorted by id, each with `file`, `doc`, `items`, `imports`, `trait_impls`) and `builtins` (every entry of the compiler's `BUILTINS` table, sorted by key). Items and members carry `kind`, `name`, `name_span` (byte offsets of the name), `line`, `end_line`, `sig`, `doc` and `is_pub`; an import carries its `path` and its `alias`, which is the dependency rule of `resolve.rs` (`default_alias`). `--text` reads one file's source from stdin in place of the file, as `check --text` does. `kelpc stdlib --json --dir <dir>` writes each shipped std source to `<dir>/<build-id>/` and prints the module list with SHA-256 per file and the synthetic `std/thread` calls; the build id is the SHA-256 of the compiler version and the whole stdlib table.
- **`--check`** writes nothing and exits 1 when a listed item, field, variant or trait method lacks a doc (associated types and impl methods are exempt).
- **Implementation.** `kelpc/src/doc.rs` scans the token stream (not the AST: aliases rewrite spans and the AST has no comments), steps over bodies by balancing braces, and takes signatures from `fmt::format_after_resolve` when the formatted file has the same shape. `lint.rs` calls `doc::orphan_findings`.
- **Known limits.** Fields written on the same line as their `datac(` cannot carry their own doc (put one per line to document them). Capability notes are direct references only.
- **Std.** The twelve modules `str list option result fs io net http sync time math env` have a `//!` header and a doc on every function; the `//` blocks that were already above declarations became `///`. Tests: `kelpc/tests/doc.rs`, fixtures and expected pages in `kelpc/tests/docs/`.
