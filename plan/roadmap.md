The critical path, the MK/S/M naming scheme, the marks at a glance, the open items, the features Kelp needs, and (in its last part) the backlog: everything the plan has named and not scheduled. This file is the record and the plan.

## Current state

The compiler exists and runs. `kelpc/` implements the language end-to-end (lexer → preprocess → parser → type check → move/borrow check → LLVM and C-oracle code generation), and the milestone record in `done.md` reflects commits, not hopes. This file is now the sole living status doc (`PASSDOWN.md` was deleted once the plan absorbed it; do not recreate it).

### 26.10.0: current state and the next work

**`v26.10.0` is the current release (2026-10-04).** It completes the critical
path below and is the release that announces the LLVM flip. The user-facing
compiler builds through LLVM; the C backend remains an internal differential
oracle. A release build requires LLVM 21 at run time and a C compiler for
linking.

The release also closes the previously scheduled TLS, unsafe, freestanding and
device-capability work: client and server TLS (including typed fallible errors,
private trust anchors, ALPN and HTTPS serving); user FFI and layout control;
raw pointers and `unsafe`; allocator hooks, `defer`, user `Drop`, per-CPU
storage and kernel examples; and capability-gated MMIO, IRQ and frame handles.
The language now includes the trait/iterator/const-generic work recorded in the
MK8 and A-12 entries, and the backend has opt-in separate compilation,
content-addressed object caching and parallel unit compilation.

**A-11's planned checker work is complete.** It covers the outstanding
reborrow check, nested partial moves, direct text-view bindings whose temporary
owner is promoted, and `str`/`View` fields backed by an earlier String/Bytes
field in the same `datac`. Branch-result and reassignment lifetime extension,
raw reference fields, borrowed containers and escaping temporary borrows remain
deliberate non-goals until a separate owner-join design exists. The kernel
scheduler and the major Polyp v4 stages are already present in this release;
they are not the next milestone.

Entries below that say a completed feature is “not started”, “ready to
schedule”, or awaits a release are historical context and are superseded by
the current state above. Update those entries when their detailed design record is edited;
do not treat them as current scheduling advice.

MK5-S2-M1: `io` and `process`, with the `main(argc, argv)` codegen change argv needed. MK5-S3: `net`, whose first task was a compiler fix because the plan's own `net` grant vocabulary could not be written open item 32, now resolved). **MK5-S4 shipped as the HTTP client**: keep-alive, response framing (Content-Length, chunked, bodyless, read-to-end-of-file), a configuration-sized connection pool whose leases are tickets rather than owners, redirects, and the `http_pool` key in `coral.toml` spliced into the shipped stdlib source. It was expected to cost no compiler work at all and cost **three** pieces: the config plumbing the pool ceiling required, and two defects that had to be fixed before any request could be framed at all the lexer decoded `"\r"` as the letter `r`, and `codegen_c` did not escape a carriage return when emitting a C string literal. **MK8-S1-M1 part 2 (A-2) and MK5-S6-M1 (the `Option`/`Result` decision) are both done, and A-4 followed them: the critical path's row 3 is complete.** A-5's `for` loop then shipped as **MK8-S1-M3** (open items 27/36a/46 resolved), so what is left of MK8-S1 is A-11's checker expressiveness and nothing else. The shortest path to a program a shell script cannot write was **MK5-S1 → MK5-S2-M1 → MK5-S3 → MK5-S4**: text you can build and numbers you can format; `io` + `process` (stdin, argv, spawn, capture the first end-to-end payoff, "run a command and read its output"); `net` for real; and then the HTTP client ("fetch a URL and print the body", the headline payoff). MK5-S5 is done (maps + filesystem breadth + real `env` bodies), MK5-S6-M1 is done (row 2), MK5-S7-M1 is done (its answer is `plan/mk9-memory-model.md`, and `poll` shipped as MK5-S3-M2), and **MK6-S1-M1 → MK6-S2-M1** is the owner's chosen order for threads and then concurrent downloads with MK5-S4c (poll multiplexing, no language work) recorded as the cheaper route if MK6-S1-M1 slips.
- **Shipped by MK5-S2-M1, and the shape it took**: `io` is **ungated** (open item 38 answered: writing your own stdout and reading your own stdin is authority over nothing shared, so no `io` domain exists yet) and is one `File` over a file descriptor a file, a pipe, a socket and a terminal are the same thing at the POSIX level, so there is no reader/writer hierarchy and no traits to build one from. The surface is `read`/`read_into`/`read_all`/`write`/`write_text`/`write_str`/`close`/`flush`/`set_nonblocking`/`wait_readable`/`wait_writable`, the three standard descriptors, `Line` with `io.read_line`/`read_lines`/`io.read_all`, the builtin `print`/`print!` under explicit names plus `eprint`/`eprint_bare`, and an owned `BufReader` datac with `read_line_into`/`read_line`/`read_all` (open item 49 answered: yes, a `datac`, with the one process-wide reader over stdin held in a module-scoped `pd var`). `process` is gated on `process` and ships `run`/`spawn`/`Child.wait`/`kill`/`is_running`, `args`/`arg_count`, `exit`/`getpid`. The grant names the **program** as its own argument never `argv[0]`-by-convention so `process = ["/bin/sh"]` is one absolute path checked before the fork; like `fs` (and unlike `net`'s planned vocabulary) the check resolves symlinks first, which on a NixOS machine means the grant names the resolved `/nix/store` tree rather than the `/bin/sh` link the caller wrote. argv needed the one compiler change MK5-S2-M1 predicted (open item 50): the emitted `main` is now `int main(int argc, char** argv)`, saving both into two runtime globals that only `std/process` reads. **MK5-S2-M2** then added the per-call working directory (`spawn_in`/`run_in` with a `chdir` in the child, code 126 when the child cannot enter it) and the fallible `try_run`/`try_run_in` returning `Result<RunResult, ProcErr>`.
- **Shipped by MK5-S3, and the shape it took**: the `net` vocabulary is `host`, `host:port`, `*.host`, `*:port`, `*` validated in one place (`resolve.rs::validate_net_pattern`), matched by a matcher of its own (`codegen_c`'s `kelp_host_glob`/`kelp_host_match`), with `*` matching within one label and a lone `*` the whole-resource wildcard the entry module holds. The split is at the *last* `:`, which is also why an IPv6 literal is unexpressible as a pattern rather than ambiguous. `checked_args` became a `Vec<CapCheck>` instead of a `Vec<usize>`, because for `net` *which* arguments are resources is a property of the call rather than of the argument types: `net.send_text(s, text)` has a `str` argument that is not a resource, and `net.recv(s, max)` a `usize` that is not a port. `connect` checks host and port together; `listen` checks the port alone, because a listener binds the machine and v1 has no `net.listen(host, port)` so for a listener the port *is* the resource, and a pattern with no port constrains none; `resolve` checks the host alone, ignoring the pattern's port, because resolution is not port-specific. The module is `connect`/`listen`/`accept`/`send`/`send_all`/`send_text`/`recv`/`recv_into`/`close`/`Listener.close`/`shutdown_write` plus `Listener.port`/`Socket.peer_addr`/`Socket.wait_readable`/`Socket.wait_writable`/`Socket.set_timeout`/`net.resolve`, on top of thirteen `extern` bodies with `MSG_NOSIGNAL` on every `send`, so a peer that closed cannot kill the process with `SIGPIPE`, and `EAGAIN` reported as "timed out" rather than "receive failed". `net.resolve` returns `List<String>` (addresses formatted with `inet_ntop`, deduplicated in resolver order), not a `getaddrinfo` blob.

- **Three latent bugs MK5-S2-M1 flushed out, all earlier than MK5-S2-M1, all now pinned by the suite**: an empty `Bytes`/`String` used to hold a NULL `data`, so `Bytes.empty().as_str()` and any `print` of an empty owned buffer handed NULL to `strlen`/`printf`. AddressSanitizer caught it on the first `io.read_all()` of an empty stream, because the ASAN pass gives the child no stdin; the two empty constructors now allocate the single NUL byte the invariant always claimed (`data[len] == 0`, including `len == 0`). A `File` write goes straight to the descriptor with `write(2)` while the builtin `print` and templates go through stdio's buffer, so the write primitives now flush the matching stdio stream first (`kelp_io_flush_stdio`) without that, `print("a")` followed by `File.write_str("direct")` came out `directa` whenever stdout was a pipe, which is exactly what the io fixture showed before the fix. And a module holding a domain with an **empty** pattern list (`caps(process = [])`) emitted no allowlist at all, so any call that names a resource referred to a symbol that was never defined and `cc` rejected the program; the empty list is now emitted as `{ NULL }` and denies, which is what makes an empty grant a usable thing to hand out. One borrow-checker consequence worth knowing: the owning form of a read is `BufReader.read_line_into(out)`, and a `RunResult` moves as a whole rather than field by field.
- **Partly unblocked, still missing**: appending to a *file* shipped in MK4-S1-M1, owned buffers grow in memory (`String.push`/`push_str`/`reserve`/`clear`/`with_capacity`, `Bytes.push`/`append`/`reserve`/`clear`), and the `List` ordering surface shipped in MK5-S1-M4 `index_of` is the only piece of it still unwritten, deliberately deferred to MK5-S6-M1 (open item 42) rather than shipping a `-1` sentinel. `env`'s real bodies, `Map`, and the filesystem breadth (`fs.mkdir_all`, `fs.remove_all`, `fs.walk`, `fs.copy`, `fs.open`, `fs.metadata`, `fs.temp_path`) shipped in **MK5-S5**; the HTTP client shipped in **MK5-S4** (keep-alive, framing, the pool, redirects) with `https` still out, because TLS is MK5-S4b-M1 and a dependency decision; an **HTTP/1.1 server** (`st2`, `plan/http-server.md`) followed in `std/http`: `http.listen`/`serve`/`serve_n`/`serve_threaded`, the `Limits` table with its 400/408/411/413/414/431/501/505 refusals, keep-alive, pipelining, chunked and `Expect: 100-continue` request bodies, and a hostile-client test matrix on both backends, with `net.mono_ms`/`net.try_accept`/`net.try_shutdown_write` added to `std/net` for it (listening is gated on the port only, open item 55 still stands); `Option`/`Result` is MK5-S6-M1. Two limits MK5-S2-M1 records as deliberate rather than accidental: `process.run` **buffers both output streams whole** (there is no streaming capture form, so a child with unbounded output wants `spawn` instead), and there is **no process-wide `chdir`** a global working directory would make every grant pattern's meaning depend on mutable global state. MK5-S2-M2 answered the second without weakening it: `spawn_in`/`run_in` `chdir` in the *child* only, and added `fs.symlink` to the filesystem breadth (both paths checked), the fallible `try_run`/`try_run_in`, and `process.executable`.
- **Backlog, not scheduled: Coral (open item 72)**, the project-layer build tool and package manager. `kelpc build` compiles one file or one directory; this repo already carries shell scripts and test-harness code that a build tool should own (`bench/speed/run.sh`, the flag logic in `kelpc/tests/compile_and_run.rs`, the build command in `examples/download.kp`'s header comment). Coral owns the manifest, the task graph, dependencies, caching and artifacts, and leaves compilation to `kelpc`. An earlier revision made this MK13 with six stages; it is an open item now, and the design sketch is in the Backlog part below. Coral is not next: nothing in MK5-MK11 depends on it, and `cargo test` plus `bench/speed/run.sh` own the build today. Writing the parts of Coral that shell out against this stdlib turned up **three stdlib-sized gaps** (`process.spawn_in`, a fallible `process.run`, `fs.symlink`), all three shipped as **MK5-S2-M2** plus MK5-S5's continuation, and one that closed itself when captures shipped — all four are in that section's "What the port hit". None of them was a language feature, and none is left: what a port still needs is the compiler's CLI contract (open item 72), not the stdlib.
- **Far future, and wanted**: MK7, the language's **next backend**, is now **LLVM IR** rather than a hand-written one. The hand-written track is retired: the optimizer was the multi-year part, LLVM supplies it along with DWARF, sanitizers and multiple targets, and the `-O0` to `-O2` gap it closes is measured at 1.15x to 5.5x per workload (the MK7 record in `done.md`). **The replacement is weeks of emission-layer work, not years**: the front half (lexer to typed IR) is reused unchanged, only the emission layer is new, and the phases, phases' estimates and the stage mapping are in the MK7 record in `done.md`. The compile-time argument that motivated the hand-written track is given up with it, because LLVM *is* the C toolchain's backend. Kelp stops being "C with a mask" by having a real backend rather than an own one, and **rewriting `kelpc` in Kelp is out of scope permanently** (see **Far future additions** below and the MK8 section). The substrate for deep systems work (kernels, drivers, firmware, allocators) is still recorded in the Backlog part below. Nothing there is scheduled, and none of it is v1 or v1.1 work.
- **Deferred despite being in `syntax.md`'s deltas**: `caps(...)` is the last one. Those deltas were aspirational scheduling and lost to implementation order; the milestone list below records where each one is now targeted (`impl` imports shipped as MK2-S1-M1, `pd` and templates as MK2-S1-M2, `alias` substitution as MK2-S1-M3, `caps(...)` at MK4-S1-M1).
- **The heap exists, and ownership is checkable at runtime.** `Bytes` and `String` are non-`Copy`, so assigning or returning one moves it; it is freed at the end of the block that owns it, and a `datac` with an owned field drops its fields recursively. A passdown of an owned type is freed by an `atexit` handler, which is v1's only drop point at process exit. The suite proves all of that rather than asserting it: every heap fixture is rebuilt with `-fsanitize=address` and run, so a double free, a use-after-free, or a leak fails `cargo test`. That caught two real bugs during MK3-S1-M1 (a branch merge that dropped the drop candidates, and a reassignment that leaked) which is the point of the milestone.
- **A growable sequence type exists, and it is a compiler builtin, not a user generic.** `List<T>` holds scalars, `String`, `Bytes` or a `datac`; a borrow or a `str` view cannot be an element (an element outlives the list, and v1 has no lifetime syntax to say otherwise), and neither can another `List`. It is non-`Copy`, so MK1-S3-M1's move checking and MK3's drop plan apply unchanged: `push` moves an element in, `pop` moves one out, and the list frees its elements and then its buffer at the end of the owning scope in a `datac` field and an owned `pd` too, through the same `needs_drop` hook `Bytes`/`String` use. `get` returns a copy for a `Copy` element and a borrow for an owned one. Codegen is monomorphized: one C struct and one function set per element type the program mentions, emitted (for a `datac` element) together with that struct. Element types are part of the type, so `List<i32>` and `List<String>` are different C types with different functions the price is that a `List` cannot be passed to a function that does not name its element type, which is what a real generic would fix.
- **A type can now refer to itself.** `Box<T>` (MK3-S2-M2) is the second builtin container: one heap cell holding a value or nothing (`Box.empty()`), with `of`/`get`/`set`/`take`/`is_empty`. Its empty state is what makes a recursive `datac` expressible without `Option`, and both containers are pointer-indirect so `datac Node(val next: Box<Node>)` (a linked list) and `datac Tree(val kids: List<Tree>)` (a tree) both work, as does a mutually recursive pair. A `datac` naming itself or a later `datac` **by value** is still refused, with the fix in the message.
- **One emission order, and it is what makes recursion work.** Container typedefs are emitted *before* every `datac`, holding their contents through a pointer and naming a `datac` element by a forward-declared struct tag; struct typedefs are tagged for exactly that; container *functions* are emitted after the structs, innermost instantiation first, with drop prototypes ahead of them so a `datac` that owns a container can call one. That ordering is also why the recursive drop (`Box<Node>` whose pointee owns a `Box<Node>`) is correct rather than a double free ASAN proves it on a 200-node list.
- **The stdlib is no longer hypothetical.** `kelpc/std/` ships fifteen modules inside the compiler binary (`stdlib.rs`, `include_str!`), all written in Kelp and reachable as `impl "std/fs"` etc.: `mem`, `str`, `path`, `math`, `fmt`, `io` (ungated), `fs`, `time`, `rand`, `env`, `process`, `net`, `option` and `result` (all four ungated — `http` is ungated and holds `net`, delegated by its importer). The only non-Kelp pieces are `extern fun` bodies supplied by `externs.rs` allocation, `strlen`, the `&str` primitives, the float-format and `strtoll`/`strtoull`/`strtod` conversions, the libm calls, and the syscalls behind `fs`/`io`/`process`/`net`/`time`/`rand` plus `env`'s three stub panics. That is stdlib decision 3 in practice: the policy is Kelp source, the unportable primitive is C.
- **Capabilities are real, and the gate is compile-time.** A module's capability set is received from its importer (the entry module holds everything), a delegation must be covered by what the delegator holds, and referencing an ungranted namespace is a *resolution* error `fs.read` does not resolve, rather than resolving and being rejected at runtime. The runtime check that does exist is the fine-grained one: each call site's path or name argument is matched against the *calling module's* compiled-in allowlist, after lexical normalization and symlink resolution, in that order. `caps_denied` (a path outside the grant) and `caps_symlink` (a link inside the grant pointing outside it) both panic with the `.kp` call site, the attempted path, and the granted patterns.
- **Alias substitution is textual, and that shows.** `%*name*%` is spliced in as raw text before parsing, so `%*doubled*% = %*answer*% * 2` with `%*answer*% = 40 + 2` prints 44, not 84 precedence is whatever the expansion produces. That is the accepted cost of the plan's "pretty simple" choice over a hygienic macro system; `kelpc/tests/fixtures/aliases.kp` pins it so the behavior is documented rather than discovered.
- **`pd var` semantics, resolved and shipped** (was `syntax.md` §9's open question): a `pd var` is **read-only inside functions**. It may only be assigned at its own top-level declaration, since v1 has no top-level statement form beyond `pd` itself. Functions that reference a passdown receive it as a **shared borrow** (for non-`Copy` values) or by value (for `Copy` ones), so no function can write through it and no cross-function exclusivity rule is needed. `syntax.md` §9's list of options is answered by that sentence; the syntax authority is unchanged (semantics are the plan's call, not the syntax file's). Implemented in MK2-S1-M2.
- **Passdown visibility is module-scoped.** This was not specified anywhere; MK2-S1-M2 answers it the way MK2-S1-M1 answered imports only functions in the module that declares a passdown can name it, and there is no `alias.name` spelling for another module's passdown. Recorded as an open item below, since it is a v1 restriction rather than a considered design.
- **Not shipped, and known**: every function whose result is a *view* of something that would have to be truncated (`path.parent` and `path.stem` return an owned `String` instead). `env`'s bodies and the fs breadth (`fs.mkdir_all`, `fs.remove_all`, `fs.walk`, `fs.copy`, `fs.touch`, `fs.open`, `fs.read_lines`, `fs.temp_path`, `fs.metadata`) shipped in **MK5-S5**, and `Map` with them. *N* items are no longer on that list: `fs.list` and `str.split` return `List<String>` as of MK3-S2-M1. Buffer growth is no longer on it either: MK5-S1 shipped `String.push`/`push_str`/`reserve`/`with_capacity`/`clear`, `Bytes.push`/`append`/`reserve`/`clear`, `str.concat`, `panic`/`assert`, integer conversions, the number/parse/`fmt` surface, and the `List` ordering methods.

## Milestone naming

Every tracked unit in this plan carries an MK/S/M identifier.

### Hierarchy

| Level | Prefix | Scope | Meaning |
| --- | --- | --- | --- |
| **Mark** | `MK` | Project-wide | A major era of the project. The largest tracked unit. |
| **Stage** | `S` | Within a Mark | A significant sub-project within a Mark. |
| **Milestone** | `M` | Within a Stage | The smallest tracked unit. |

Read as MK > S > M.

### Identifier format

- **Mark**: `MK1`, `MK2`, `MK3`, … numbered continuously across the project.
- **Stage**: `S1`, `S2`, `S3`, … numbered continuously within its Mark.
- **Milestone**: `M1`, `M2`, `M3`, … numbered continuously within its Stage.

A fully-qualified identifier is written `MK1-S2-M3`. In context the short form (`M3`) is sufficient.

### Rules

- **(a)** A Mark is closed when all its Stages are closed.
- **(b)** A Stage is closed when all its Milestones are closed.
- **(c)** A Mark is not renumbered once any of its Stages has shipped.
- **(d)** A Stage is not renumbered once any of its Milestones has shipped.
- **(e)** New Milestones append within their Stage; they are not inserted between shipped Milestones.
- **(f)** Backlog items keep their `A-n`/`B-n`/`C-n`/`D-n`/`E-n` labels until an item is promoted to a Stage. The items themselves live in the Backlog part below.

### MK5-S5 maps, fs/OS breadth, and the real `env` (DONE)

*Deliverable*: a keyed container, the filesystem functions that are cheap now that `List` exists, and `env` bodies that are not stubs. *Gate*: none for `Map`; `fs`; `env`.

*Shipped, and what it cost*: three commits. **`Map<V>`** (part 1) is the second builtin generic, and the sketch's shape held: `String` keys, a monomorphized value type, FNV-1a over the key's bytes, open addressing with tombstones. The one design choice worth recording is that entries live in a **dense insertion-ordered array** and the hash table is a separate index of `entry index + 1` (`0` empty, `SIZE_MAX` tombstone), because `keys()` must return insertion order; a removal marks the entry dead and tombstones its index slot instead of shifting, so the order is stable. The value is held through a pointer, which is what lets the map typedef still be emitted before every `datac`. **Its key type became generic in A-2** (`Map<K, V>`, with `Map<V>` kept as the `String`-key shorthand), which turned the two `String`-specific hash/equality helpers into per-instantiation ones generated from the key type. `get` borrows an owned value and copies a `Copy` one; `get_or` and `values` are offered only for a clonable value type, exactly as `List.slice` is. **fs breadth and path polish** (part 2) are ordinary Kelp over six new externs; the two interesting ones are `mkdir_all`, which is one recursive C extern precisely so the grant is checked once on the whole path rather than once per prefix *above* the granted root, and `copy` (one `sendfile` loop). **`fs.symlink`** arrived afterwards, as the continuation MK5-S2-M2's `done.md` entry records: both of its paths are checked, which keeps an `fs` grant closed under link creation. **`env`** (part 3) replaced the three stub externs with four real ones (`getenv`/`setenv`/`unsetenv`), added the `unset` the sketch had but the stub module never declared, and proved the check is on the *name*, before the call: a grant on `PATH` does not let the holder ask whether `HOME` exists.

*Two capability-matcher gaps this milestone flushed out, both earlier code, both now pinned*: `fs.open`'s second argument is a **mode string** (`"r"`/`"w"`/`"a"`/`"rw"`), and the `fs` domain matched *every* `str` argument as a path so the mode would have been normalized and denied. `fs` now names its resource arguments per call, the shape `net` already used. And a trailing `/**` did not admit the **directory itself**, only paths below it, so a grant on a tree could not create or remove the tree's own root which is exactly what `mkdir_all` and `remove_all` do. `kelp_glob_match` now treats a trailing `/**` as zero or more segments, so `/var/lib/app/**` covers `/var/lib/app`. Both were invisible while the entry module holds the whole-resource wildcard, and both only show up in a delegated module or a fresh `mkdir_all`.

*What is not shipped, deliberately*: `Map.of` (a map starts empty) and `Set` (`Map<bool>` covers it open item 41); `env.names()` (listing is reading all of it); `fs.copy` on a directory; and `path.stem` is owned rather than `&str` as the sketch wrote it, because a prefix cannot be a view without a length-carrying view type (open item 44).

*Cost and notes*: `Map` is the second builtin generic and deliberately the cheap one `String` keys, monomorphized value type, FNV-1a over the key's bytes in the runtime, open addressing with tombstones: a `Ty::Map`, a `map_sig` next to `list_sig`, a `write_map` next to `write_list`, a `Map#` arm in the call-naming switch, and a drop that frees each key, then each value if it needs it, then the table. `Map<Map<i32>>`/`Map<List<i32>>` stay impossible: the value set is narrower than the `List` element set, which A-10 slice 1 widened to take a `List` or a `Box`. `env.names()` is deliberately absent: listing the environment is reading *all* of it, which a grant of `["PATH"]` should not permit (if it ever ships, it is the one function whose check is "must hold `*`"). `fs.copy` is the only place `sendfile` is genuinely better than a read/write loop a 20 GiB copy would double the memory, and the repo already benchmarks a 20 GiB write. `fs.walk` needs `path.join` per entry (20 lines of Kelp, inheriting `fs.list`'s sorted order, which is what keeps the test deterministic). `fs.remove_all` is already proven in the repo: `caps_list`'s recursive `clear` does it in ~15 Kelp lines, and after MK5-S1 it is 8.

### MK5-S7-M1 concurrency: what is possible now, and what is not (DONE)

*Settled: the answer it owed is `plan/mk9-memory-model.md`, which is the plan of record for concurrency, and `poll` (readiness on `File`/`Socket`) shipped as MK5-S3-M2. The text below is the analysis that produced the answer.*

Deliverable: an answer, plus `poll`. What works without new language features **multi-process** (`process.spawn` is real parallelism and real isolation, and it is the honest v1 answer), **single-threaded event loops** (`poll` readiness on `File`/`Socket` + `time.sleep_ms` is enough for a server at this scale), and the existing cleanup points (`atexit` + scope drops; there is no `defer`, no cancellation, and a panic takes the process since `kelp_panic` calls `exit(1)`). What a thread would need, and why each piece is missing: a *function value* to run (no first-class functions anywhere in the parser), owned data to hand to it (open item 1: there is no move-taking parameter spelling, so a spawned thread could only borrow something whose lifetime the checker cannot relate to it), a rule about `&mut` crossing the boundary (lexical, function-local lifetimes), and a per-thread frame/cleanup story (drops are keyed to lexical blocks in one function). Conclusion: **no threads until function values *and* move-taking parameters exist** a language milestone, not a stdlib one and `async`/`await` needs those plus a state-machine transform in codegen. MK5-S7-M1 is therefore written down as "processes + `poll`" and revisited when a real program demands more.

### MK7 backend: from C to LLVM IR (the hand-written track is superseded)

> **Superseded 2026-09-20.** The hand-written backend this section describes is retired. The plan of

>

*Retired execution plan. The Mark below says why and what it costs; the retired plan owned the stage
order, the two-agent split, the gates and the risk register, and its own summary was the answer to
"what is done and what is left". A branch `mk7/own-backend` carries it: stage 0 (the backend seam, so a second backend can
be validated at all) is done, and stage 1 emits x86-64 assembly itself through `as` and `ld` with no C compiler
in the chain, and has landed scalars, `f32`/`f64`, a linear-scan register allocator for integer locals, and a
first slice of aggregates (small `datac`s by value). Measured at that point: **108 of 241 integration tests
pass on the new backend and 241 of 241 on the C one**, so the differential gate is live and the coverage number
is a measurement rather than a claim. Three numbers in the text below are stale and corrected in that file (and
below, where they recur in the staged-path sketch): the integration suite is 241 tests, not 118; the stdlib
declares 90 `extern fun`s, not ~20; and the "Cranelift, then decide" staged path in point 2 below was decided
against before stage 1 started, the retired plan's own "not on this branch" list records "no LLVM, no Cranelift" as the reading this
branch takes, so stage 1 is a hand-written x86-64 backend from its first commit, not a Cranelift prototype.*

Stated as a goal in its own right: *Kelp should stop being C with a mask*. Nothing about the language's identity lives in the backend the differentiators are the capability system and the move/borrow model so this is not about making Kelp faster. It is about Kelp not depending on a C compiler to exist, and about fixing the one thing that is actually bad today: **compile time is ~95% somebody else's fixed overhead.**

#### Why (measured 2026-09-18 on this machine, best-of-5, using the C that `kelpc build` already keeps next to the binary):

| program | `kelpc build` | clang + link | Kelp's own pipeline |
| --- | --- | --- | --- |
| `examples/hello.kp` (230 lines of C) | 80 ms | 76 ms | **~3 ms** |
| `bench/speed/speed.kp` (532 lines of C) | 108 ms | 102 ms | **~4 ms** |

And inside clang's share: cc1 startup plus system-header preprocessing ~38 ms (that is the *entire* cost of `-O0 -c` on the trivial file), optimizer ~25 ms on the bigger one, link ~46 ms even for a prebuilt `.o`. So ~76–102 ms of every `kelpc build` is fixed toolchain cost, and our whole lexer → preprocess → parser → infer → borrowck → codegen pipeline is 3–4 ms. A backend that emits an object and calls `ld` directly could plausibly reach ~10 ms compiles a 10x compile-time win and no `cc` dependency.

**What it costs, measured rather than guessed:** the *same* generated C compiled `-O0` vs `-O2`, on the four `bench/speed` workloads:

| workload | `-O0` | `-O2` | penalty |
| --- | --- | --- | --- |
| `collatz` (branchy int) | 446 ms | 83 ms | 5.4x |
| `float` (div + add loop) | 265 ms | 101 ms | 2.6x |
| `mix` (div-bound loop) | 204 ms | 168 ms | 1.2x |
| `fib` (real calls) | 28.4 ms | 24.0 ms | 1.2x |

`-O0` is the worst realistic case (everything spilled, nothing inlined). A hand-written backend with a decent register allocator lands between `-O0` and `-O2`: call-heavy code barely notices, branchy and FP-heavy code notices a lot. Closing the rest of the gap means writing an optimizer inlining, CSE, LICM, strength reduction which is the multi-year part (LLVM is millions of lines; Cranelift is six figures and lands around `-O1`). **That is the trade: ~10x faster compiles and no toolchain, for ~1.5–3x runtime on numeric code until an optimizer exists.**

**Staged path** (each stage is testable with what already exists):

1. **Backend boundary.** `codegen_c.rs` becomes one implementation of a backend, `driver.rs` (43 lines, and the only place that shells out) picks one, and `kelpc build --backend=…` selects it with an env-var override so the 118 end-to-end tests, which are backend-agnostic by construction (compile, run, compare stdout), can validate both backends in one `cargo test`.
2. **Cranelift** (`cranelift-codegen` + `cranelift-frontend` + `object`) for the scalar subset first: no `Bytes`/`String`/`datac`. This is where the compile-time win lands and where the runtime gap is smallest. The `tir` surface is small enough for this to be a real option: 177 lines, ~16 node kinds, four scalar widths.
3. **`datac` layout**, calling convention, and `extern "C"` calls so the ~20 one-line externs (`sqrt`, `clock_gettime`, `stat`, …) keep working as direct calls.
4. **Move the non-trivial runtime out of C**: `externs.rs` (251 lines of C bodies) plus `PATH_RUNTIME`/`CAP_RUNTIME` (the glob matcher, the `..`-rejecting path normalizer, `realpath`-with-a-missing-tail). Two fiddly pieces to plan for: `print` currently goes through C's `printf`, and on x86-64 SysV calling a variadic function requires setting `AL` to the number of vector registers used; and the capability checker's matcher/normalizer are Kelp-visible behaviour that is currently C text.
5. **Then decide.** Keep Cranelift, hand-write x86-64 (own register allocator, no optimizer), or go all the way to a static ELF with raw syscalls and our own runtime allocator, formatter, and `fs` which is the only path to a genuinely self-contained binary.

Things that get *better* rather than worse on the way: GNU statement expressions and compound literals leave the strategy (a real backend handles value-position blocks natively), `-fwrapv` becomes explicit wrap semantics we control, and the `#line` markers the C backend already emits (item 20) are replaced by DWARF rather than added to.

Gate it on `bench/speed/` (runtime parity, four workloads with cross-language checksums) plus a compile-time column that pair is the whole argument, and it is already in the repo.

Rejected numbering: an earlier revision of this file put moves and borrow checking at MK1-S2-M1 and retired MK1-S3-M1/MK1-S4-M1, on the theory that `syntax.md`'s deltas won. The implementation did not do that MK1-S3-M1 (moves) shipped as MK1-S3-M1 so the record above is the numbering that counts.

## Open items

1. ~~**Move-taking parameters have no spelling.**~~ Resolved twice, in opposite directions, which is worth reading in order. **MK1-S4-M1** settled it as "no move-taking parameters in v1, by design": a `datac`-typed parameter is always a borrow (shared, or exclusive via `mut T`), and a value moves only by local rebinding. **MK8-S1-M2 phase A reverses that**: `name: move T` takes ownership, the call site moves the argument in exactly as `val b = a` does, and the callee frees it when its scope ends. `mut` and `move` are mutually exclusive; `move` on a `str`/`&T` is refused (a borrow has no owner to transfer) and so is `move` on a receiver (a method that consumed its receiver would destroy the caller's value at a call that reads like one). The type-level change is one line — the parameter resolves to the bare `T` instead of `Ty::Ref` — which is why the borrow checker and codegen needed no new rule.
2. ~~**`pd var` semantics and the `pd` wiring pass.**~~ Resolved twice: MK2-S1-M2 made a passdown read-only inside functions, and MK2-S2-M2 replaced that with a hidden *borrow* typed by the declaration (`pd var` exclusive, `pd val` shared), so a `pd var` is writable from any function that references it while every access stays borrow-checked.
3. ~~**`pd` and `Bytes`/`String`.**~~ Resolved in MK3-S1-M2. An owned passdown is allowed and its drop point at process exit is an `atexit` handler registered alongside the generated global's initializer, so `pd val banner = String.from_str("...")` works and is freed. Reading an owned passdown inside *another* passdown's initializer is still rejected ("its value is not Copy") unchanged from MK2-S1-M2, now enforced by `is_copy` rather than by naming `datac` specifically.
4. ~~**`when` is boolean-only in v1.**~~ *Resolved in MK8-S1-M1 (part 1)*: `when` now has both forms — no scrutinee means the boolean chain (unchanged), a scrutinee means patterns over an `enum`, with exhaustiveness checked and a missing variant named in the message. The remaining Kotlin-isms (nested/literal patterns, guards) are deliberately absent; a pattern is a variant name plus one binding per payload field, and `_` ignores one.
5. ~~**`process.run_shell`**~~ Resolved in MK5-S2-M1: no shell-shaped entry point ships. `process.run(program, args)` takes the executable and the argument list separately, which is what makes the capability check a single absolute path; a caller that wants a shell writes the shell's path itself, and the grant then says so (`process = ["/bin/sh"]`).
6. ~~**Is `io` (stdin/stdout/stderr) really ungated?**~~ Answered in MK5-S2-M1: **ungated**, which is the same answer as item 38 (that item is this question asked from the purity side). `std/io` has no `domain_of` row and `io` is not in `stdlib::DOMAINS`, so there is nothing to gate it with even if a caller writes `caps(io = [...])` the error says `io` is not a capability domain.
7. ~~**`math` on `f32`.**~~ **Resolved in 26.10.3:** `f32` overloads of every `std/math` function, and `f32.to_f64()`/`f64.to_f32()` to convert. Original text: Either add `f32` overloads or accept implicit `f32 -> f64` promotion, which interacts badly with inference. With overloading locked in (stdlib decision 4), the clean answer is `f32` overloads.
8. **`String` API surface.** The standard library section in `architecture.md` sketches `String` largely in parallel with `Bytes`, and decides that text-returning `str.*` functions return `String` rather than `Bytes`. That decision is this document's, not `syntax.md`'s confirm it, especially whether `path.join`/`path.normalize` should return `String`.
9. ~~**Canonical top-of-file order**~~ is `impl`, then `pd`, then `datac`/`fun`, and `%*alias*%` may appear in any of those. Enforced for `impl` (MK2-S1-M1) and `pd` (MK2-S1-M2) each is a parse error after any `datac`/`fun`. MK2-S1-M3 answered the `%*alias*%` half by taking it out of the parser's hands entirely: `alias` declarations are stripped by `preprocess.rs` before the parser runs, so a declaration is legal anywhere a statement could start and the canonical order does not apply to them. References keep their slot.
10. **Passdowns are module-scoped, with no cross-module spelling.** MK2-S1-M2's answer to a question `syntax.md` §9 leaves open. MK8-S2 item A-13 slice 1 keeps it: `pub` is refused on a `pd`, because a passdown that could be exported through a module alias would contradict the module scope this item settled. 17. ~~**`pd var` cost, and how to remove it.**~~ Resolved. Every reference to a `pd var` used to be an exclusive borrow (MK2-S2-M2), so one call could not take it both exclusively and shared. The hidden parameter's type is now decided by what the *function* does with the passdown, over the call graph: a probe pass runs with every passdown shared and records each use that needs an exclusive borrow plus every call edge, `close_pd_modes` walks the edges to a fixpoint (a caller of a writer holds the passdown exclusively too), and the pass that emits the program runs again with the result. A `pd var` no function writes is a shared borrow everywhere, so `show(cfg)` — a function that takes the passdown as an argument *and* reads it — compiles, while `combine(tally, tally)` is still refused. The edge is followed even when the callee never names the passdown, because a function that only forwards takes the global's own address: that is what keeps a shared borrow from being held across a write.

29. **`List.get` is the one signature that depends on the element type** *and stays as it is after MK8-S2-M1*: a `View` did not make `&T` and `T` interchangeable at a use site (a `View` is a text view, not a general borrow), so the `.as_str()` chain on `List<String>.get(i)` is still there — and still removaable only by the owner-side coercion item 21 keeps open., and that leaks into ordinary code. `List<String>.get(i)` gives a `&String`, so passing it to a `str.*` function needs `.as_str()` (open item 21 compounding), while `List<i32>.get(i)` gives an `i32` and can be used in arithmetic directly. 30. ~~**Borrow lifetimes got shorter for temporaries, and are still lexical otherwise.**~~ **Resolved: a bound borrow now ends at its last use, not at the end of its block.** A borrow held in a local binding is live from its creation to the last use of that binding, or of a value derived from it (a reborrow bound to another local, a `View` made from it, a closure that captured it, a returned borrow), along every path that can still reach a use; once no use remains the owner may be mutated, moved or reassigned. `val first = names.get(0); names.push(...)` in one block is accepted with no extra `{ }`, which was the workaround this item named (the `{ }` `list_owned.kp` wrapped its read in is now optional). `plan/nll.md` is the rule and the algorithm (no CFG: a backwards last-use scan over the structured HIR, one release point per scope-durable borrow, released by the block walk). Still refused, each pinned by a fixture: mutation while a borrow is used later in the same block, a use in a later iteration of the enclosing loop, a borrow a scoped block captured when the same call borrows the owner exclusively, a borrow of a local returned from the function, a `defer` that uses the borrow after a mutation, and a `View` used after its owner is reassigned. The two earlier refinements stand: a borrow produced by a *statement's* temporary still ends with the statement (`print(l.get(0)); l.push(x)` stays legal), and a call that **hands the borrow back** (`String.from_str("x").as_str()`, or `fun f(p: Pair).return: &i32 = ...`) still requires a place, because the result outlives the statement. `View` is no longer exempt: it follows the same last-use rule. Owner *drops* are untouched: still lexical, at scope end.

32. ~~**`net`'s capability vocabulary cannot be written, and would deny every host if it could.**~~ **Resolved in MK5-S3 (part 1), as the milestone's first task and its first commit.** As found: `stdlib::patterns_are_paths` counted `net` as a path domain, so `validate_cap_pattern` rejected the `api.example.com:443` patterns the plan's own examples use, and `codegen_c` emitted `kelp_cap_check_path` for `net` which lexical-normalizes a hostname, fails, and denies everything; `checked_args("net", …)` also only ever handed over the first `str` argument, so the port was never matched at all. 33. ~~**A borrow does not remember what it was borrowed from, so a pointer local cannot be used as a cursor.**~~ **Resolved (borrow checker 2 of 2, A-11 slice 3; `plan/provenance.md`).** As found: `var cur = list` binds the borrow, and `cur = cur.next.get()` was refused ("cannot assign to 'cur' while it is borrowed") because the borrow of `cur.next` was registered against **`cur`** the pointer rather than against `list`, its owner. A reference-typed binding now carries a **root set** (the owners its value may borrow from): a `val`/`var` sets it from the initializer, `cur = expr` replaces it and releases the old roots at the assignment, and an `if`/`when`/loop join unions the arms' roots. A borrow made through the cursor is a borrow of the owner, so mutating the owner under a live cursor stays refused while rebinding the cursor is accepted. The iterative `Box`-list walk, an indexed `List` cursor, and a cursor re-pointed from owner A to owner B (then A mutated) are accepted fixtures; two `mut` cursors into one root, a mutation under a live cursor, a cursor returned from a local and a moved root stay refused. Explicit lifetime syntax stays out.

38. ~~**Does `io` stay ungated?**~~ *Answered in MK5-S2-M1: ungated.* WASI gates stdin as an input capability; the plan's classification says writing your own stdout and sleeping are not authority over anything shared. Gating stdin would make a filter need `impl "std/io" caps(io = ["stdin"])`; not gating keeps the common case free. `std/io` therefore has no row in `stdlib::domain_of`, and `io` is not a name in `stdlib::DOMAINS` either, so `caps(io = [...])` is rejected as "not a capability domain" rather than silently accepted. 39. ~~**Is argv `process.args()` (ungated) or `env.args()` (gated)?**~~ *Resolved in MK5-S2-M1 as `process.args()`/`process.arg_count()` in `std/process`, and the gate needed one clarification.* This file's sketch put argv under `env`; argv is your own invocation, not authority over the shared environment, and `env.args` is dropped. 40. ~~**Is string concatenation an operator (`+`/`+=`) or a function (`str.concat`)?**~~ Answered by shipping the function: `str.concat(a, b)` lives in `std/str` and `String.push_str` beside it (MK5-S1). `+` reads better and hides an allocation; a function makes the allocation visible and needs no syntax change. `syntax.md` §10 has no such operator, so an operator means editing `syntax.md`. **Recommendation**: `str.concat(a, b)` plus `String.push_str` in MK5-S1; revisit `+` as a deliberate syntax decision later, and never make `+=` on a `String` implicit it would be the only operator that allocates.

43. ~~**Multiple `caps(...)` clauses on one `impl` line.**~~ Documented: `wiki/reference/capability-patterns.md` and `wiki/language/capabilities.md` both carry `impl "logger" caps(fs = ["/var/log/myapp/**"], env = ["LOG_*"])`, and `caps(*)` is stated beside it. 44. ~~**A length-carrying borrowed view (`&[u8]`-shaped): v1.1 or later?**~~ *Resolved in MK8-S2-M1*, and shipped as the recommendation's own spelling: a builtin **`View`** beside `Bytes`, with no `&` in the grammar. `s.view()` (one `strlen`) or `string.view()` (none), then `len`/`is_empty`/`get`/`slice`/`eq`/`to_string`, plus a `View` -> `String` copy where one is expected. `syntax.md` §11.5 is the reference. **One half of the item is deliberately not shipped**: a view *cannot be a field*, because v1 has no lifetime syntax to tie a field to its source (A-11), so the recommendation's "a borrow rule that lets it appear as a field" waits for that. 45. ~~**`time.sleep_ms` needs a `time` grant in a library module.**~~ **Resolved by `thread.sleep_ms` (MK9-S3-M1 stage C2, found while closing this in 26.10.2):** the ungated `std/thread` module already carries a `sleep_ms`, which `std/http` uses with only a `net` grant, so a library module sleeps without `time`. `time.sleep_ms` stays gated with the rest of `std/time`. 46. ~~**Is a `for` loop worth its own milestone?**~~ **Yes, and it shipped as MK8-S1-M3**: one single-purpose commit, desugared in the parser, with the desugar pinned by a fixture, exactly as recommended. The `iter`/`next` protocol stays unscheduled; it is the expensive version and nothing has asked for it. `syntax.md` §6.2 was the prerequisite and was edited first.

47. ~~**Do panics carry errno and `strerror`?**~~ Adding `errno` to `fs`/`net`/`process` panic messages makes every syscall failure diagnosable, at the cost of making panic text less stable for golden assertions. **Recommendation**: yes, as a two-line addition (`kelp_panic_errno(const char* msg)` used by the syscall externs), keeping the message prefix stable and the errno detail on a second line. This is also the cheap preparatory half of MK5-S6-M1. **Resolved that way in MK5-S6-M1's cheap half**: `kelp_panic_at`/`kelp_panic_errno` print `errno N: <strerror>` on a second line under the unchanged prefix, `kelp_panic_gai` covers `getaddrinfo` (whose failure is a return code, not `errno`), and a call site that cleans up before panicking captures the code first. `fs_errno` pins it; `a_failed_syscall_reports_errno_and_strerror` asserts both lines.

48. ~~**Unicode scope.**~~ Settled and shipped as recommended: codepoint-level operations (validated UTF-8, `str.char_at`, `str.byte_index`, `str.decode_at`), ASCII-only case operations with the reason in the doc comment (`std/str.kp`: "uppercasing arbitrary Unicode needs a character table, which v1 has no place to put"), and `String.char_count` documented as non-continuation bytes. No grapheme awareness and no case folding. Real case mapping and grapheme clusters need megabyte tables and a segmentation algorithm; codepoint-level handling is a table-free decode of the UTF-8 rules `kelp_utf8_valid` already implements. **Recommendation**: codepoint-level (`str.char_at`, `str.byte_index`, validated `String`), ASCII-only case operations, documented as such, no grapheme awareness and no case folding. `String.char_count` stays "non-UTF-8-continuation bytes" and the doc comment says so.

49. ~~**Buffered IO: a `BufReader` datac, or unbuffered reads only?**~~ *Answered in MK5-S2-M1: the `datac`, as recommended.* Unbuffered `read_line` over a pipe is one syscall per byte (unusable); buffering needs a buffer, which is an owned `Bytes` field in a `datac`. `std/io` ships `BufReader(file, buf, start, end)` with `read_line_into` as the primitive, `read_line()` as the `Line` wrapper, and `read_all()` draining the buffer first; the process-wide reader over stdin is a module-scoped `pd var`, which is what `io.read_line()`/`io.read_lines()` use, so the convenience hides the state without making it global to the user. Two limits worth knowing: `buf` must be non-empty (`read_into` reports 0 for a full buffer, which the reader reads as end of file), and an empty `Line` cannot be unwrapped by value `read_line_into` is the owning form.

50. ~~**`main(argc, argv)` versus a `pd` global for the arguments.**~~ *Done in MK5-S2-M1, as recommended.* A generated `pd val argv: List<String>` would avoid changing `main`'s signature, but `.kp` `main` cannot take hidden passdown parameters (MK2-S1-M2's restriction), so the runtime has to stash `argc`/`argv` either way. The emitted signature is now `int main(int argc, char** argv)`, both values are stored in runtime globals that only `std/process`'s externs read (`process.arg_count`/`arg_at`, with `process.args` built in Kelp), and no `.kp` source names them one codegen change, no new surface. A second, unplanned codegen fix came with it: function prototypes are now emitted *before* `kelp_init_pds`, because `io`'s `pd var` reader calls `buf_reader(...)` in its initializer and the init function had no prototype in scope.

51. ~~**Should the streaming reads be primary, with the allocating form as sugar?**~~ Answered the recommended way: `net.recv(s, max)` and `net.recv_into(s, buf, at)` both ship, with the difference in `std/net.kp`'s doc comment, and `read_to_end` exists where the length is known (`Cursor.read_to_end` in `std/http`). `net.recv(s, max)` is what people write first and cannot express "read exactly `Content-Length`" without growth; `recv_into(buf, at)` is the correct choice for a known-length body but needs a buffer the caller sized. **Recommendation**: both, with the difference spelled out in `std/net.kp`'s doc comment, and **no** `read_to_end()` until MK5-S1's growable `Bytes` exists that is precisely its use case.

52. ~~**`process.run`'s capture model.**~~ Answered as recommended and shipped: `process.run` captures with `poll`, so a child that fills its stderr pipe while the parent reads stdout cannot deadlock, and `std/process.kp` documents that both streams are buffered whole; `spawn` is the streaming form. Whole-output capture is what people want and can deadlock on a chatty child if implemented naively (the err pipe fills while the parent blocks reading out); `poll`-based capture fixes it at the cost of a more complex extern; `spawn`-only pushes the model onto the caller. **Recommendation**: `process.run` with `poll`-based capture plus a documented "buffers both streams" memory cost, and `spawn` for the streaming case.

53. ~~**`char` is a type with no values.**~~ *Resolved in MK8-S2-M1*, taking the first of the two recommendations: a character literal is real. `'x'`, with `\n` `\t` `\r` `\0` `\'` `\"` `\\` and `\u{...}`; it holds one Unicode scalar value and **takes the integer type its context asks for** (so `c == '"'` works when `c` is a `u8`), which is what makes it usable in byte-level code, and it is `char` when nothing constrains it. A code point that does not fit the requested type is refused rather than truncated. `char` is a code point and not a byte, so its C type is `uint32_t`. The old text, kept for the record: `syntax.md` §5 sketches `fun push(s: mut String, ch: char)`, the primitive list names `char` (line 387), and the stdlib sketch has `str.char_at(...).return: char` in one place and `.return: u32` in another but the lexer has no char literal, no function returns a `char`, and the integer conversions of part 2a are between integer types only, so no program can produce one. MK5-S1-M1 resolved the immediate need by typing `String.push` as `u8` (the same type `str.byte` returns, and the same type `Bytes.push` takes), which is honest but leaves the padding fill in `fmt.pad_left`/`pad_right` facing the same choice. **Recommendation**: either add a char literal (`'x'`, escapes, ASCII-only) as a deliberate syntax decision with `syntax.md`'s agreement the smallest addition that makes the existing `char` type real or delete `char` from the primitive list and use `u8`/`u32` everywhere. Do not ship a third stdlib function whose parameter type no program can spell.

54. ~~**Should integer conversions be implicit?**~~ Answered the recommended way and shipped: MK5-S1-M2's explicit `to_<T>` conversions stay, with no implicit widening in arithmetic or argument matching. MK5-S1-M2 added explicit `to_<T>` conversions; the rejected alternative was implicit *widening* in arithmetic and argument matching, which would have made the conversion functions unnecessary. It was rejected because it changes arithmetic for every future program which of `i32`/`u64` wins in `i32 + u64`, whether a narrowing can ever be implicit (it must not be), and what `list.get(0) + 1` does when `get` is `usize` and because it would not have given `from_i64` its narrowing digit anyway. The conversions are 64 generated entries rather than a hand-written matrix, so the surface cost is a table. **Recommendation**: keep conversions explicit; if the ergonomics bite, the narrow fix is to let a *literal* adapt to a widening target the way it already adapts to the exact one (`f(255)` where `f(n: u64)`), not to widen operator rules.

55. ~~**A `net` grant does not say which interface a listener binds.**~~ **Resolved in 26.10.2:** option (a) shipped as `net.listen_on(host, port)` and `http.listen_on(host, port)`, checked on `host:port` like `connect`; `listen(port)` stays as it was. As found: `net.listen(port)` binds `0.0.0.0`; the check matches the *port* alone (MK5-S3, and see the MK5-S3 section for why the sketch's "host *and* port" was not implementable), so a module granted `127.0.0.1:8080` may listen on `0.0.0.0:8080`, which is reachable from outside the machine. That is a widening, not a bypass the module still cannot name a host or port outside its grant but it is the one place where a `net` grant means less than its text suggests. **Recommendation**: two options, in order of preference. (a) `net.listen(host, port)` with the host checked like `connect`'s, and `0.0.0.0`/`*` as the explicit "every interface" spelling honest, but it is new stdlib surface, not a fix. (b) Bind the *granted* host: the allowlist is already compiled in as constant data and `kelp_cap_check_port` already walks it, so a "give me the host to bind" accessor is possible but a pattern is a glob, so it can match several hosts and the compiler would have to pick one, which is why (a) is preferred. Not fixed in MK5-S3 because nothing needs a listener that a `*:port` grant does not already express.

56. ~~**The pool has no idle timeout, and its ceiling is per host.**~~ **Resolved in 26.10.2:** `Pool.set_idle_timeout(ms)` makes `checkout` close a connection idle that long instead of reusing it, and `Pool.close_idle(after_ms)` closes every such connection and returns the count; the clock is `net.mono_ms`, so `std/http` still holds no `time` grant. As found: *Shipped that way in MK5-S4; item 63 records the exact semantics and the reasoning, so this item is now just the observation.* Two consequences a program can meet: it keeps `size` connections per host for its whole life (so talking to many hosts can walk into the fd limit), and a connection the peer has closed sits idle until it is used, where it fails **once**. A reaper needs a clock, which would make `std/http` hold `time` as a second capability (legal open item 43 but a policy decision). **Recommendation**: add `Pool.close_idle(after_ms)` when a real program hits either limit; do not build it speculatively.

57. ~~**`coral.toml` gains its first numeric value, and still has no sections.**~~ Settled, and further than the recommendation: `kelpc` now stops reading at the first `[section]` header and hands the rest of the file to Coral (`resolve.rs`), so `[tasks]`, `[dependencies]` and `[toolchain]` are legal beside the compiler's own keys, and the second numeric key arrived as `naming_case` beside `http_pool`. The flat keys above the first section stay the compiler's.

58. **`Transfer-Encoding: chunked` shipped in MK5-S4, not deferred.** The earlier plan deferred it and made it an explicit panic, on the grounds that a to-EOF read works for a one-shot request. Keep-alive removes that escape hatch: with a persistent connection, a chunked body has no other end marker, and reading to EOF would block until the server closed which it will not do. So the decoder ships with keep-alive. It also needs hex parsing, which `str` does not have (its `parse_u64` is decimal), so the size line is decoded byte by byte.

59. **A loopback server in the harness is now required.** MK5-S3's fixtures could be both ends in one process because `net` calls do not block on one another; an HTTP client blocks inside `send` until the response arrives, so a `Pool` cannot be exercised single-process. The helper binds `127.0.0.1:0`, passes the port through argv, and serves canned bytes and it can assert *how many connections were accepted*, which is what makes "the pool reused the socket" a direct assertion rather than a timing inference. This reverses the earlier claim that MK5-S4 needed no server helper.

60. ~~**Threads (MK6-S1-M1): every prerequisite in one place, and the narrow shape recommended.**~~ *(a) and (b) are shipped, as MK8-S1-M2 phases A-F: `name: move T` takes ownership, a declared function, a `fun` literal or a capturing closure is a value, and a call through one is positional with the callee's own parameter list — so a thread entry point can be a closure carrying what it runs on, which is the shape this item had ruled out as too expensive when it was written. (c)-(e) are all three settled by `plan/mk9-memory-model.md` and implemented in MK9-S3-M1 stages A1/A2/B1/C1: the panic policy (a panic ends the thread; the joiner sees `Err`; the process survives), the per-thread frame story (an abandoned panicking frame leaks, recorded rather than hidden), and the atomics with the `Send`-shaped crossing rules the checker enforces. Stage C2 (`thread.sleep_ms`, `thread.current_id`) shipped 2026-09-25, both ordinary functions over `extern fun` bodies rather than checker builtins, and stage D1 shipped the same day: the memory model published as the language's own at `wiki/language/concurrency.md`, closing MK9-S3-M1. The recommendation's own narrow shape lost to the better one: closures are in, not closed out.)* As written while it was open, threads are a language milestone, not stdlib work, and they need: (a) **function values** the parser has no first-class functions at all, so there is nothing to name as an entry point; (b) a **move-taking parameter spelling** (open item 1: a `datac`-typed parameter is always a borrow, so a thread could not own what it runs on); (c) a **per-thread failure policy** `kelp_panic` calls `exit(1)`, which would let one worker's panic kill every other download; (d) a **per-thread frame and cleanup story** drops are keyed to lexical blocks inside one function's frame; (e) **atomics and a `Mutex`** in the stdlib, plus a **`Send`-shaped rule** in the borrow checker, because the model's core promise (a `&mut` is exclusive) is what a second thread would otherwise break silently. **Recommended narrow shape**, to keep the milestone as small as it can honestly be: function *references* (`thread.spawn(worker, job)` naming a declared `fun`), restricted to a single move-taking parameter enough for a worker pool, and *not* closures, which would drag in capture analysis and lifetimes. Async/`await` stays out of scope until function values exist for other reasons.

61. ~~**`http.get` does not use a pool, deliberately.**~~ *(Picked, 2026-09-25, as MK6-S2-M1 shipped: the per-thread shape, not the `Mutex`-shared one. `examples/download_pool.kp`'s four workers each build their own `http.Pool` with `http.pool(host, port)` and never share it, which needs no new capability and no lock — a `Pool`'s `var idle` field is exactly the shared mutable state `thread.spawn`'s rule 3 refuses to send, so per-thread was the shape that needed nothing further from the language.)* The one-liner is `Client.send` over a fresh connection; pooling is opt-in through an explicit `Pool`. The transparent alternative would need a process-wide pool in `std/http` (`pd var`), and that is exactly what MK6-S1-M1 makes expensive: a global pool shared by threads needs a lock, and a lock around every request serializes the very thing MK6-S2-M1 is for. Per-thread pools (each thread its own `Pool`) or an explicitly shared one behind a `Mutex` are the two shapes that survive MK6-S1-M1, and neither is expressible yet. **Recommendation**: revisit transparent pooling when MK6-S1-M1 lands, and pick then do not bake a global in now and pay for it at MK6-S2-M1.

62. **`Response.header` returns an owned `String`, not `&str`.** Forced, not chosen: `&str` return elision roots at a parameter or a local, so a borrow reached through `List.get` cannot be handed back (`return headers.get(i).value.as_str()` fails the place rule, and binding the element first makes *that binding* the root instead of `self`). One allocation per lookup until a length-carrying view (open item 44) or real lifetimes make the borrow expressible. `has_header` exists so the common "is it there" question allocates nothing.

63. **The pool as shipped: `size` is a ceiling on what is *kept*, and there is no handle and no reaper.** Three deviations from the sketch, each deliberate. (a) `Lease` carries `fd`/`reused` and the pool owns the descriptors a `Lease` that owned a `Socket` could never be taken apart, since a parameter is a borrow, so `release` could not move the socket back (see item 62's rule for the general shape). The ownership story that matters is unchanged: `release` consumes the lease. (b) `size` is *max idle*, Go's reading: a request that arrives while every kept connection is busy gets a fresh one, so `checkout` has no failure path and a program never fails because its pool was small. (c) No idle reaping, so a program talking to many hosts keeps `size` connections per host until it exits reaching for a reaper means a clock, which means `std/http` holds `time` as a second capability (legal, open item 43, but a policy decision). **Recommendation**: leave all three; add `Pool.close_idle(after_ms)` when a real program hits the fd limit, and note that a stale connection is discovered on use and fails *once* (the body-framing verdict is what decides reuse, so a peer's silent close is a parse error, not a corruption).

64. **The escape set is now closed: `\n`, `\t`, `\r`, `\"`, `\\` and nothing else.** Anything else is a diagnostic rather than the bare character, which is the behavior change worth knowing about, because the old fallback made `"\q"` mean `"q"`. `\0` stays rejected for a second reason (a `str` is NUL-terminated and could not hold one). **Shipped since**: `\xNN`, exactly two hex digits, in a string, character and byte literal, so `"\x1b[0m"` is spellable and `"\x41a"` cannot run on. **Still absent**: `\u{...}` in a string literal (the decision about whether a string can name a code point directly is still open; write the character itself, and a byte above the ASCII range is `Bytes`).

65. **A capability pattern is source text, so the harness and the program must agree on a literal path.** `caps_scratch` in `kelpc/tests/compile_and_run.rs` now builds `/tmp/kelp_caps_<name>` literally instead of asking `std::env::temp_dir()`: the fixtures grant `/tmp/kelp_caps_<name>/**`, and a `TMPDIR` pointing at a sandbox left the harness creating one directory while the program read another. The general rule (also worth applying to any future scratch fixture): when a test's grant is written in the fixture, the harness's scratch root is not configurable.

66. ~~**The manifest format change Coral needs.**~~ Shipped as option (a): one manifest, and `kelpc` reads the keys it knows and stops at the first `[section]` header rather than rejecting it (`resolve.rs`). Coral's `[tasks]`, `[dependencies]` and `[toolchain]` sections sit under that line, and a new compiler key no longer breaks an old manifest. Today `coral.toml` is flat, holds four keys (`name`, `version`, `entry`, `http_pool`), rejects any line starting with `[`, and rejects an unknown key by name. Coral needs sections (`[package]`, `[tasks]`, later `[deps]`). Options: (a) one manifest, with `kelpc` reading the keys it knows and ignoring other sections; (b) two files, `coral.toml` for the build tool and `kelp.toml` for the project. (The rename folded the old contrast — the compiler's `x.toml` versus Coral's proposed `coral.toml` — onto a single name, so option (b) now needs a second name, and `kelp.toml` is the free one.) **Recommendation**: (a), because a project has one identity and splitting it lets the two files disagree; it also fixes the current behavior where a new compiler key breaks an old manifest. 67. **What Coral is written in, and when it is ported.** Coral is a Rust program while the compiler is, which means the build tool cannot build itself and its own tasks need a compiler that exists. Writing Coral in Kelp needs MK8-S1/S2 (generics, `Option`/`Result`, function values, containers) and the stdlib breadth MK5 delivers. **Recommendation**: Rust through MK13-S4, then port as the first large non-compiler program written in Kelp, since Coral is a big real program with no unsafe requirements. (The `MK13-...` names in items 67-70 are the identifiers the Coral design carries in the Backlog part below now that it is not a Mark; open item 72 is the scheduling question.) All the language prerequisites are shipped: generics (A-2), `Option`/`Result` (MK5-S6-M1), containers (MK3), and function values with captures (MK8-S1-M2 phases A-F). 68. ~~**Is a package registry acceptable?**~~ The plan lists a package registry and third-party dependencies as deliberate non-goals, and Coral is a package manager. 69. ~~**What a version constraint means for Kelp.**~~ A semver range needs a compatibility theory (what counts as a breaking change in a language with no traits and, until MK8-S2 item A-13 slice 1, no visibility rules), and a lockfile needs a format with a checksum story. Related: a task's output becoming another task's input without the second task holding a write grant on the first's tree. **Recommendation**: a fixed, documented grant set for the tool itself, orthogonal to per-task grants, with the C-1 runtime-authority work (MK10-S2-M1) as the thing that makes it checkable rather than documented.

71. **Should Kelp target regulated and financial domains?** An earlier revision made this MK12, with six stages (decimal arithmetic, transactional primitives, audit and traceability, formal tooling built on MK11, legacy interop, certification), and then said in the same breath that it "is a **decision to make**, not a task to schedule". 72. **Coral: the project-layer build tool and package manager - a Mark, or a question?** An earlier revision made this MK13, with six stages. The design survived the review: tasks are Kelp programs with their own `impl` grants, `coral.toml` grows sections, the task graph is Gradle-shaped, and the build cache is the point. The *scheduling* did not. Nothing in MK5-MK11 depends on Coral; `kelpc build`, `cargo test` and `bench/speed/run.sh` work today; the first thing Coral needs from the compiler is a stable CLI contract that is only starting to exist (`kelpc version` is its first piece, and it ships now); and Coral cannot itself be a Kelp program until MK8-S1/S2 ship. **Recommendation**: open item. **What exists so far** (`coral` repo, at `26.9.2`): `init`/`build`/`run`/`check`/`clean`, `test`/`fmt`/`lint`, `docs get`/`docs list`/`docs search`, `sync`, `task`, `[tasks]`, `[dependencies]` as git dependencies (one repo, or one folder inside one; no versions, no lockfile), a fingerprint build cache, and toolchain management — global (`coral toolchain kelp use <ver>`, the `~/.coral/bin/kelpc` link) and per project (`[toolchain] kelp` in `coral.toml`, written by `coral toolchain kelp pin <ver>`), the latter being MK13-S6-M1's per-project selection, and the store under `~/.coral/toolchains/` holding one version per component since `coral` v0.5.0 — installing or using a version removes the others, so a pin that is not the stored version displaces it. The design sketch is in the Backlog part below, as is "What the port hit" — the four findings a first port produced: three stdlib-sized gaps (`process.spawn_in` for a per-call working directory, a fallible `process.run` so a missing tool is a reportable error, `fs.symlink` for the toolchain link — **all three shipped as MK5-S2-M2**) and one language gap (capture-less closures) that MK8-S1-M2 phases E-F closed. Promote Coral to a Mark when a second project outside this repository needs it, or when the compiler's CLI contract is frozen. One question has no home since `rebrand.md` was deleted (the X → Kelp rename executed; see the `rebrand/x-to-kelp` branch): what `coral`’s name replaces, given that the compiler is `kelpc` and the manifest is already `coral.toml`.
73. **A grant denial cannot be a value, so a fallible call cannot report one.** Found while shipping MK5-S2-M2's `try_run`. The capability check is compiled in per *calling* module and emitted at the call site, where it panics — so a program outside the grant, and a relative one (which normalizes to nothing), is refused before any Kelp function runs. `ProcErr` can therefore hold `NotFound`, `NotExecutable` and `DirNotFound`, all decided by a `stat`/`access` pre-check before the fork, but not the `Denied` variant the Backlog part below's row sketched. **The shape a fix needs**, in the order worth considering: (a) a non-panicking check mode in codegen, selected by the callee the way `checked_args` selects the resource arguments, where the guard does *not* call on deny and the verdict reaches the callee as a value — a hidden argument, since the callee's own return type is the only place the `Err` can be built; (b) the same, carrying the verdict in a runtime global the callee must consume, which is smaller but fails *open* if a callee ever forgets to consume it — which is why (a) is preferred. What is not in question is the panic's usefulness for the case it covers now: a manifest that grants the wrong program is a configuration error, and the message names the call site, the path and the granted patterns. Worth doing when a real program resolves a program path at *runtime* (the C-1 runtime-authority work, open item 18's neighbourhood) and has to recover from a denial rather than crash.

74. ~~**A spelling that is on its way out keeps working, and says so.**~~ Deleting or replacing a spelling used to be a breaking change with one possible shape: land it, and every program that used the old text stops compiling the same day. The decision (2026-09-20) is that it does not have to be. A retired spelling goes into a **register** (`kelpc/src/deprecated.rs`: an id, what is outdated, what to write instead), the compiler keeps accepting it, and `kelpc build`/`kelpc run` print an `outdated:` finding that names the fix and says the entry is removed on the next development cycle. The deadline sentence is shared by every entry, so no entry can promise a different one. `--deny-outdated` turns those findings into errors, which is the migration gate for a project or a CI run that wants to hear about its own code; the flag is off by default, because the compiler's job is to build a program written for the version it has. `kelpc fmt` never rewrites the old spelling into the new one (it copies tokens), and `kelpc lint` does not report deprecations (that is a build's finding, not a style pass's). The compiler's own sources carry none: the shipped stdlib is migrated before an entry is written, because a deprecation there would warn every program that imports the module about a file its reader cannot edit, and a unit test keeps that true. **First entry, and the reason the mechanism exists**: `impl "path" as name`, deprecated in favour of the path's own name. A module's namespace is now the module's own name, and a dependency's entry module is named after the directory Coral fetched it into: `impl "deps/argparse/lib"` is `argparse` (the `[dependencies]` key) and `impl "deps/fpl/json/lib"` is `json` (the library's folder inside a whole-repository dependency), so the clause names what the path already says (`syntax.md` 13.1). The removal is the item this entry schedules: delete `as` from the parser, migrate the fixtures that were deliberately left on it, and wipe the entry. Recorded rather than deleted, because the *removal* is the next development cycle's work even though the warning ships now. **The removal has shipped** (2026-09-20): `as` is gone from the parser, the six `.kp` files that spelled the clause are migrated, `ImplDecl::alias`/`alias_span` and the resolver's override path are deleted, and the entry is wiped from the register, which then held `caps-with` alone. A program that still writes the clause gets a parse error naming the fix, and `as` stays a keyword rather than becoming an identifier. The tests that migrated with it: `kelpc/tests/outdated.rs` (the refusal replaces the warning) and the two corpus drivers that reached `std/rt` through the clause. **The register is empty, since 2026-09-21**: `impl "path" with caps(...)` went in the same cycle rather than getting one of its own, because the one shared deadline sentence already said "the next development cycle" and a second cycle would have left that finding naming a deadline that had passed, which is the drift the shared sentence exists to prevent. The parser refuses the keyword by name, `ImplDecl::caps_with_span` and the resolver's deprecation push are deleted, the entry is wiped, and the grant is unchanged: `impl "std/fs" caps(fs = ["/var/log/**"])`. `kelpc/tests/outdated.rs` and `kelpc/tests/check.rs` carry the refusal, `--deny-outdated` is a no-op while the register is empty, and the wording an entry buys is still unit-tested in `deprecated.rs`, on an entry built in the test rather than registered.

75. **Should a call take a trailing closure?** A builder-shaped API wants one, and Polyp (`plan/polyp-ui.md`) is the concrete case: `polyp.column { ... }` rather than `polyp.column(f = fun() { ... })`. Kelp has closures today and no sugar for them, so this is the question of whether it should. The cost is not in the parser. A call site names the callback argument (`f = fun(...)`), so a trailing block leaves that parameter unnamed and the compiler has to choose it by function type, which is a selection rule the language does not have and has avoided so far; the `.return:` return clause would have to come from the expected type instead of being written; and `fmt.rs`, a token-level formatter that copies tokens and rewrites the whitespace between them, would need a rule for rewrapping a block. **Landed**, as two pieces and with Polyp as the builder API that paid for it. `plan/trailing-closure.md` makes a same-line `{ ... }` the call's last argument; `plan/scoped-blocks.md` adds a block header `{ k -> ... }`, a value-returning block, and a `scoped fun(...)` parameter that accepts only a literal or trailing block written at the call site and may capture the enclosing frame by shared borrow. `examples/polyp/lib.kp`'s `polyp.column { k -> k.text(s.title) }` compiles and runs, so the callback parameter is selected by function type and the `.return:` clause comes from the expected type. **Exclusive captures landed too** (`plan/exclusive-captures.md`): `state.count += 1` inside a block is accepted when the owner is a `var` or `mut` parameter and nothing else in the call touches it. `fmt.rs` still has no block-rewrapping rule.

### 3. The minimal useful Kelp

If only five things could be added to make Kelp useful and functional without bending it:

1. **A length-carrying view.** The biggest single lever for text, parsers, network and paths; it closes three open items at once.
2. **`Option`/`Result` plus tagged unions.** Makes error handling first-class instead of a datac convention, and needs generics.
3. **`unsafe` plus FFI plus `repr(C)`.** Makes systems work, libc and C interop possible: the one reason Kelp today is "C with a mask".
4. **Threads plus `Mutex` plus atomics.** Servers, workers, real parallelism; the precondition for anything network-serious.
5. **`for`.** Makes ordinary code tolerable without touching the semantics.

Everything else, JSON, regex, encodings, LSP, GUI, ML, Decimal, certification, WASM, a registry, is either a library (writable once views and generics exist), a target (it comes with the backend), or a deliberate non-decision.

### 4. The honest consequence

Kelp will never do "everything", and that is the point. The languages that tried, C++, Scala and Swift among them, pay with compile time, specification size and a steep learning curve. Kelp's strength is not that it can do everything, but that it does **one thing right**: ownership plus capabilities in a small, explicit language. The useful version of Kelp is therefore not the largest one but the **most focused** one: a systems and application language for programs that take files, network, processes and security seriously, and that stays small enough to read in one evening.

## Far future additions

*The itemized lists (`A-1`-`A-17`, `B-1`-`B-10`, `C-1`-`C-4`, `D-1`-`D-5`, the suggested order, the unscheduled ergonomics wants in `G-1`-`G-5`, and the pitfalls work-off in `H-1`-`H-18`) are in the Backlog part below. They are a backlog, not a schedule: no numbers, no order, no commitment. What stays here is the part that is a decision rather than an item.*

**Three structural blockers.** Each one is a whole class of program the language cannot express today, and each one is why a block of backlog exists at all.

- **No `unsafe`** (B-3). No kernel, driver, allocator or runtime, and no escape valve for a deliberately conservative borrow checker.
- ~~**No user-declarable generics** (A-2, open item 34).~~ *Shipped as MK8-S1-M1 part 2.* Type parameters on `datac`/`enum`/`fun`, monomorphization at every use site, receiver methods on a generic type, explicit type arguments, and a `Map` with a real key type — so `Option`/`Result`, `datac Pair<A, B>` and a non-`String` map key are all expressible, and open item 34 is resolved. The list below is therefore **two** structural blockers, not three.
- **No runtime authority** (C-1, open item 18). Capabilities are compile-time constants and the entry module is unrestricted, so a *sandboxed* `kelpc` is not even expressible: a compiler's authority is runtime data (paths from `argv`, `PATH`/`CC`, temp files), not an allowlist.

**Three reversals of deliberate decisions.** These are not extensions. Each one undoes something v1 chose on purpose, and each needs an explicit decision before it becomes a task.

- **Allocators** (A-7, B-7): v1 has no custom allocator and no arena, and allocation failure panics. Reversed when a real program needs an arena or a fallible allocation.
- **Freestanding** (B-6): v1 assumes an ambient libc runtime (`stdio`, `malloc`, `atexit`, `main`). Reversed for a kernel, a firmware image, a bootloader or an embedded target.
- **Concurrency model** (B-4): v1 avoids a memory model by not having threads. Reversed *before* threads (MK6-S1-M1; see **Dependency notes**), not after.

**One permanent non-goal.** Rewriting `kelpc` in Kelp is out of scope, permanently. There is no bootstrap
stage, no stage 1, no stage 2 and no fixpoint, and none will be added: the compiler is and stays a Rust
program. The MK8 mark's rewrite stages are cancelled for this reason, and changing the backend target to
LLVM (the MK7 record in `done.md`) does not reopen the question.

**One far-future proposal, with a document of its own and now a prototype.** **Polyp** is a native UI framework for Kelp: declarative views over the platform's own widgets, GTK first on Linux, with the language's borrowing and its exhaustive `when` doing work a UI framework usually does at run time. It is still a proposal, not a commitment and not a Mark, and nothing is scheduled; what changed is that the substrate exists. `examples/polyp/` (v1, the builder syntax) and the frozen `examples/polyp-v0/` are a GTK4 library and a counter, built and run on both backends under Xvfb, on user FFI (B-1) and the scoped trailing blocks open item 75 asked for. `plan/polyp-ui.md` owns the case, the three things it would do that Tkinter and Compose Multiplatform do not, and its own prerequisites.

**KelpScript, a garbage-collected sibling language**, is a far-future proposal with no Mark, no open item and nothing scheduled. Its design direction and the first steps are in [`plan/kelpscript.md`](kelpscript.md).

**Two more far-future language ideas, recorded and not scoped.** **Panic provenance** (`plan/panic-provenance.md`) would print the chain a value took to a panic rather than only the line it happened on; the borrow checker's provenance work it was waiting on (open item 33) has shipped, so it is unblocked but still not scheduled. **Differential testing as a language feature** (`plan/differential-testing.md`) would let a writer declare two functions equivalent and have the compiler generate cases and compare them, which is the mechanism the suite already gates the default backend on, turned outward; it needs a design pass before anyone writes code, and how a compiler-generated call site composes with `caps(...)` is the hard part. Neither is a Mark, nothing is scheduled, and no work has started.

Everything else in the backlog is an extension rather than a reversal, and lives in the Backlog part below.

#### A. Language surface for compiler-grade programs

*A-1 to A-13 are promoted to MK8-S1 and MK8-S2; A-14 to A-16 and C-2 to MK8-S3. C-1 is MK10-S2. The items are kept here as the detail. The retired bootstrap item (formerly A-17) is gone: rewriting `kelpc` in Kelp is out of scope permanently.*

- **A-1. Tagged unions and exhaustive pattern matching.** **Part 1 shipped as MK8-S1-M1 (part 1)**, recorded in `done.md`: the spelling is `enum` with payload-carrying variants, chosen over a `sum` keyword and over variants on `datac` because Rust's meaning of `enum` is exactly the meaning wanted here, while `datac` stays a record with one layout and one set of rules. What landed: `enum Name { Variant(val f: T) ... }` (variants newline-separated, the payload list shared with `datac`), construction as `Shape.Circle(r = 1.0)` / `Shape.Empty`, the `when <place> { Variant(bind) -> value else -> value }` pattern form (the boolean `when` has no scrutinee, so the two forms never collide), exhaustiveness checking that names a missing variant, payload binding by copy for `Copy` and by shared borrow otherwise, a C `tag` + `union` layout with a per-variant drop switch, enums as container elements, and one merged `datac`/`enum` declaration order. `syntax.md` §2.3/§3/§6.3/§9.2/§17 carry the syntax. What is left of A-1: nested/literal patterns and guards, which nothing needs yet. `Option<T>`/`Result<T, E>` still wait on A-2 (generics for the payload).
- **A-2. User-declarable generics.** **Shipped as MK8-S1-M1 part 2**, and open item 34 is resolved. Type parameters on `datac`/`enum` declarations, every use site monomorphizing into an ordinary named type; generic *functions* (`fun first<T>(xs: &List<T>).return: T`) and receiver methods on a generic type (`fun Pair<A, B>.first().return: A`); type arguments inferred from the arguments and from the expected type, with an explicit spelling at the expression when inference has nothing to go on (`Pair<i32, String>(...)`); inference through a nested generic constructor; and the builtin `Map` taking a key type (`Map<K, V>`, with `Map<V>` kept as the `String`-key shorthand). The key set is closed to `String`, the integers and `bool`, because the compiler generates the key's hash and its equality — a key of the user's own type would need a trait (A-12) or a comparator function (A-4), neither of which exists, and that is the one piece of "a `Map` with a real key type" that generics alone could not reach. (**Superseded in MK8-S2 item A-6**: the compiler derives a keyable `datac`/`enum`'s hash and equality from the same fixpoint that derives its order and deep copy, so neither a trait nor a comparator was needed after all; see A-6 for the pivot.) `Box<T>`/`List<T>`/`Map<K, V>` remain compiler builtins. **Extended in language-completeness 6**: a parameter may now be a compile-time *value* (`datac Buf<const N: usize>`, `fun sum<const N: usize>(a: &[i32; N])`), with `impl Trait` in argument position as the other sugar the same machinery carries; `plan/const-generics.md` (A-20) is the design and `syntax.md` 9.3 is the reference.
- **A-3. `Option<T>`/`Result<T, E>` with propagation.** No `?`, no `if let`, no combinators, no null. The error-`datac` convention (stdlib decision 2) carries the stdlib and does not scale to a compiler: nested fallible calls become nested `if`s and every failure shape wants its own datac. This is MK5-S6-M1's decision point, and it is compiler ergonomics as much as stdlib surface. `?`/`if let` are syntax, so `syntax.md` gains them first. **Shipped**: MK5-S6-M1 gave `if let`, `?` on any `Ok`/`Err` or `Some`/`None` shape and the two modules, and **A-12 slice 6** (`plan/traits.md` 11) closed the last piece, the error conversion `?` was left without: a declared `impl From<Source> for Target` is now called when the operand's failure payload differs from the function's, and `std/convert` ships `From<T>`/`Into<T>`. There is no blanket impl, no `Into` in the operator and no boxing.
- **A-4. Function values, closures, and move-taking parameters.** **Shipped as MK8-S1-M2 phases A-F, which close A-4.** `name: move T` takes ownership of its argument (open item 1's spelling), a declared `fun` is a value of type `fun(T).return: U`, a `fun` literal is written where an expression is expected, a literal that names a binding from the enclosing scope is a **closure** typed `closure(T).return: U` (a function value plus the heap environment its captures were moved into, dropped where the closure dies), a plain function value is widened into a closure where one is expected (through a generated shim when it names a function, so nothing is allocated), and `std/option`/`std/result`/`std/list` take callbacks that may capture. Every callback's payload is a borrow, so a call never moves an element or a payload out. **Nothing in A-4 is left**: the two pieces an earlier record listed as remaining — a `sort_by`-shaped comparator over an owned element type, and the helpers that hand an owned payload out by value (`option.unwrap` on an `Option<String>`, `result.map` over a `Result<T, MyErr>`, `list.filter` over a `List<String>`) — need **A-11's partial moves**, not closures, and are recorded there and in the modules' headers. A compiler is pass-structured `walk(node, |n| ...)`, comparators, diagnostic sinks, per-node callbacks — all of that is expressible now. MK5-S7-M1's two prerequisites (function values and a move-taking parameter) are met, and open item 60's (a)/(b) now cover closures as well, so MK6-S1-M1's language surface is no longer the blocker. **Exclusive captures (language-completeness 7 of 8, `plan/exclusive-captures.md`, verdict "implement now", implemented):** a scoped block may now *write* what it captures (`s.count += n`, `xs.push(n)`, a `Copy` `var` counter, a `mut` parameter), by an exclusive borrow of the owner for the call the block is written in, inferred from the body with no new syntax; every interaction with the call's other arguments, a second capture, the receiver and a live borrow is decided by the existing borrow table. A stored callback stays impossible, and a block nested in a block cannot use a name the outer block captures exclusively (v1).
- **A-5. Iteration: a `for` loop, then possibly a protocol.** Open items 27, 36a and 46. **The cheap half shipped as MK8-S1-M3**: `for x in list { }` desugars to an index and a `while`, so a list walk no longer reads like C (the element binding is `List.get`'s — a copy for a `Copy` element, a shared borrow for an owned one). **The protocol shipped as language-completeness task 2 (`plan/iterators.md`)**: `std/iter` declares `pub trait Iterator { type Item  fun mut Self.next().return: option.Option<Self::Item> }`, `for x in <expr>` keeps the index walk when the type is a `List<T>`/`[T; N]` and becomes a `next()` loop when it implements `Iterator` (the choice is made in `infer.rs`, the first pass with a type), any other type is refused naming the trait, and `Range` plus `count`/`sum_i64`/`collect_list` ship in the module. The loop control the `None` arm needs (`break`, and `continue` with it) is now an ordinary statement, refused outside every loop and free of the iterated place's mutation rule. Still open and recorded in `plan/iterators.md` 5: generic adapters (`take`/`skip`/`enumerate`/`zip`/`chain`), the closure adapters, and `List.into_iter()` all wait on generic trait impls (`impl<I: Iterator> Iterator for Take<I>`), which the parser does not accept.
- **A-6. A keyed container with non-`String` keys, and `Set`** (open item 41). A compiler's tables are keyed by interned symbol id, type id, node id, and `(module, name)` stringifying keys to reuse `Map<V>` is the wrong shape at the wrong cost, and `Map<bool>`-as-`Set` is a recorded stopgap rather than a substitute at compiler scale. **The key set widened in MK8-S2 item A-6 slice 1, by derived structural hash and equality rather than by a trait or a comparator.** A `datac`/`enum` whose every field (or variant payload) is keyable is now a key: the compiler derives `kelp_hash_<T>` and `kelp_eq_<T>` for it from the same declaration-graph fixpoint that already derives its order and its deep copy, so the two new operations are the same shape as two that exist, and neither A-12 (a trait carrying hash/equality) nor A-4 (a comparator function) is needed. This entry, and the A-2 entry above, asserted the opposite: they said the key set was closed because the compiler supplied hash and equality only for `String` and the scalars. That was true of what MK8-S1-M2 shipped, and the pivot is a correction to that claim rather than a rejection of it: the fixpoint was already there for order and copy. The comparator route was rejected for a concrete reason: it would put a function value in every `Map` entry and change `Map`'s own type. The slice is `String`, the integers, `bool`, `char`, and a `datac`/`enum` of those; a float stays refused (`nan != nan`), and so do a `List`/`Map`/`Box`, a view, a borrow, and a `datac`/`enum` with a field outside the set. (**Widened in MK8-S2 item A-12 slice 1**: a `datac` or `enum` that declares its own `hash`/`eq` pair is a key however the derived fixpoint judges its fields, which is the escape hatch for a float field or a comparison the derived rules do not express; the key is still cloned into the entry, so the type has to be deep-copyable and a `List`, `Map` or `Box` field still stands in the way; see A-12.) `Set<T>` is **not** in this slice and remains open; `Map<bool>` is still the recorded stopgap.
- **A-7. Shared ownership of immutable data, and allocator control.** No `Rc`-shape, no arena/region, and no custom allocator (all explicit non-goals today), while a `datac` field must be owned so interned strings, type tables and symbol tables can only be shared as *indices* into a `List`. Indexing is the standard compiler design and will work; the language gives no help, and with no allocator hook the allocation-heavy phase of compilation stays slow. An arena for AST nodes and a shared-immutable table type are the two things a compiler actually reaches for **decided 2026-09-26: not to be reached for**. That "a compiler" was the whole case for this item, and rewriting `kelpc` in Kelp is now permanently out of scope (see **Far future additions** and the MK8 section), so the item's own motivating example no longer exists. Not reversing the no-custom-allocator, no-arena stance until something other than a self-hosted compiler asks for it.
- **A-8. A length-carrying borrowed view, and borrows in fields** (open items 22, 29, 44). **The half that is a language feature shipped as MK8-S2-M1**: a builtin `View` — a pointer and a length, `s.view()`/`string.view()` to make one, `len`/`is_empty`/`get`/`slice`/`eq`/`to_string` on it, `print` emitting `%.*s` from the pair, and a `View` -> `String` copy where an owned value is expected. A slice is a pointer and a subtraction, a scan has its bound with it, and a function may return a view of its first reference parameter. **What did not ship, and why**: a `View` cannot be a *field*, an enum payload, a list element or a map key, because tying a stored borrow to its source needs lifetime syntax (A-11) — so "borrows in fields" stays open, and the parser that wanted to keep its input in a `datac` passes the view instead. **What also did not ship, and is stdlib work rather than a gap**: `path.parent`/`str.trim`/`str.prefix` still return owned values, and `List<String>.get(i)` still needs `.as_str()` — neither is a property of the type, both are signatures that would have to change. `syntax.md` §11.5 is the reference.
- **A-9. The bit surface.** v1 has *no bitwise operators at all* (the plan's own note: `str.char_at` does UTF-8 masks by subtraction), no char literal (open item 53), and no sized/hex/binary literal story. A lexer, a codegen and any byte-format work need shifts, masks and testable bits and `&` is already taken by borrows, so the spelling is itself a decision. **Shipped as MK8-S2-M1**: `&` `|` `^` infix, `~` prefix, `<<`/`>>` as two adjacent `<`/`>` characters, with the spellings resolved as predicted — `&` is bitwise-and in infix position and the borrow prefix in prefix position (C++'s reading), and the shifts are not lexed as one token so `List<List<i32>>` still closes. Precedence is C's *except* that the bitwise operators bind tighter than the comparisons, which is the one deliberate divergence: `flags & MASK == 0` means `(flags & MASK) == 0`. A char literal exists now too (open item 53). **Shipped since**: `0x` and `0b` integer literals (the decimal-only rule left `val mask: i32 = 0xff` a parse error naming an identifier `xff`). **Still open**: the sized form, a literal suffix such as `5u8`, which the language deliberately does not have because a literal takes its width from its context, and `fmt.hex` is the printing side.
- **A-10. Loosened container element rules** (open item 28). **Slice 1 shipped in MK8-S2 item A-10**: a `List<T>` and a `Box<T>` are now legal `List` elements, so `List<List<T>>` and `List<Box<T>>` compile and run on both backends. An element lives in the list's own buffer, so the element type only has to be a complete, droppable C type, which both are, and `container_depth` in `codegen_c.rs` (and its LLVM mirror) already emitted a nested container before the one that contains it. The `List` refusal now names what is actually refused (a `Map`, an array, a borrow or a view, an atomic, a function value, `unit`), and the `Map` value set is given its own, narrower body so a `Map` value stays a scalar/`String`/`Bytes`/`datac` (a container there is still refused). **Still open**: a borrow or a view element needs A-11's or H-9's lifetime story; `Map` values stay closed for now; and the array rule stays as it is, so a `List`/`Box`/`Map` element inside a fixed-size array is still refused (`[[u8; 4]; 8]` is an inline page table, and a container element would make it variable-size).
- **A-11. Borrow-checker expressiveness.** Deliberately conservative, which is over-strict rather than unsound and a compiler is where the strictness lands hardest: ~~no provenance, so a pointer local cannot be reused as a cursor (item 33)~~ **a reference binding now carries a root set, so a pointer local is a usable cursor (A-11 slice 3, item 33 resolved; `plan/provenance.md`) — `cur = cur.next.get()` is accepted, the owner stays borrowed while any cursor into it is live, a reassignment releases the root it left, and an `if`/`when`/loop join unions the roots**, ~~lexical lifetimes, so a bound borrow lives to the end of its block (item 30, workaround is an extra `{ }`)~~ **a bound borrow now ends at its last use, not at the end of its block (A-11 slice 2, item 30 resolved; `plan/nll.md`), so the extra `{ }` workaround is gone**, and explicit lifetime syntax (`'a`) stays out; partial moves, shipped as A-11 slice 1 and now covering both halves, the `datac` field and the owned `enum` payload, so a field read directly off an owned local moves out, a `move` parameter included because it is an owned local in the callee, and a `when`/`if let` over an owned place binds an owned payload by value the same way, while a field or payload out of a borrow or a nested place stays refused (the `Line` text case on the datac side, and the payload bound as a `&T` on the enum side). The three deliberate leaks (item 15) turned out **not** to need field-granular drop tracking or a flow-sensitive branch merge after all a narrower fix (`DropPlan::at_assign` keyed to a place, not only a binding) closed all three, and item 15 is resolved. **Decided, 2026-09-26: do not pursue explicit lifetime syntax (`'a`), NLL or pointer provenance now.** **Two of those three have since been lifted on request: item 30's lexical over-strictness (slice 2) and item 33's missing provenance (slice 3).** Explicit lifetime syntax (`'a`) stays out, as does a lifetime-carrying element rule (A-10's borrow/view element, H-9): with no written lifetime there is nowhere to say how long a stored view would have to stay valid. **Slice 4, exclusive captures (`plan/exclusive-captures.md`):** a scoped block's capture of a `var` or a `mut` parameter is an exclusive borrow for its call when the body writes through it, registered in `take_call_arguments` beside the call's other borrows. That work found two things: a write through any capture was an internal compiler error rather than a refusal (fixed), and **two reborrows of one `mut` parameter in one call (`fun h(s: mut State) { g(s, s) }`) are not checked at all**, because a `&mut`-typed name passed on is not a `Ref` node (still open, a candidate for its own task; the exclusive-capture case is closed by an explicit same-call check).
- **A-12. Traits/interfaces and dynamic dispatch.** Substitutable by enums for dispatch *if* A-1 exists, but not for destructors (a user `Drop`) and not for a pass abstraction ("a stage is a thing with a `run`"). **Slice 1 shipped in MK8-S2 item A-12**: a `datac` or `enum` becomes a `Map` key by declaring `fun T.hash().return: u64` and `fun T.eq(other: &T).return: bool`, which the map calls instead of the derived pair, so a type the derived key fixpoint refuses (a float field, or a comparison the derived rules do not express) can be a key with no trait keyword and no new syntax. The two names are the declaration, both halves are required, and a half or a signature the map cannot call is refused where it is declared; the escape hatch is from the key set only, so the key is still cloned into the map and the type has to be deep-copyable, which leaves a `List`, `Map` or `Box` field out. Deferred to slice 2 and beyond: a `trait` keyword and named traits, user `Drop`, dynamic dispatch, and a key pair on a generic type's instantiation. **Slice 2 progress (H-5)**: `==`/`!=` over a declared `eq` shipped. The front end lowers `a == b` to `a.eq(&b)` and `a != b` to `!a.eq(&b)` (and `View` against `View`/`str` to the builtin `View.eq`), before borrowck and codegen, so both backends run the declared body and no operator is added anywhere. `eq` alone is now a complete declaration: it gives the operator without making the type a key, and a lone `hash` is still refused (a key needs the pair). No equality is *derived*: a `datac`/`enum` with no declared `eq` keeps the old refusal, and `<`/`>` on such a type is still refused. `plan/syntax.md` §5 is the decision and `plan/kernel-ub-notes.md` carries the stage note. What is still open in H-5: whether `String`/`Bytes` should compare byte-wise through the operator (a bare `String`/`Bytes` and a `str` still refuse). **Corrected after slice 1**: a *call* of a method on an `enum` value was listed here as refused, and the slice's own verification showed the two receiver spellings disagreed. A value of enum type now resolves a declared method (`val e = E.A`, then `e.tag()`, H-15), which is the call the `Map` probe was already making, and the receiver refused in its place is the variant-construction path (`E.A.tag()`, since it names a type rather than a value). **Slice 2 shipped (2026-10-03): traits with static dispatch, and nothing more.** A `trait Name { fun [mut] Self.method(...).return: T ... }` is a named set of method signatures, `impl Name for Type { fun [mut] Self.method(...) { ... } }` gives them to a `datac`/`enum` in the trait's module or the type's (at most one impl of a trait for a type, every signature matched exactly, and an inherent method of the same name is refused at the impl), and `fun f<T: A + B>(...)` bounds a type parameter: the bound is checked at every call/instantiation and the body is then monomorphized per concrete type exactly as generics already are, so dispatch is static and both backends and the freestanding mode needed no new lowering. What the slice deliberately leaves open is `dyn`/trait objects and dynamic dispatch, default methods, associated types, `impl Trait` in argument position, a trait on a builtin or on a generic instantiation, `where` clauses, supertraits and operator overloading through a trait, each refused by name with the follow-up in the message; `plan/traits.md` is the design, `plan/syntax.md` 9.5 the surface, and the note in `plan/kernel-ub-notes.md` records that no new undefined behaviour was added. `Drop` stays the one compiler-known trait and keeps its own spelling (`fun mut T.drop()`): `trait Drop` is refused where it is written. **Slice 3 shipped (2026-10-03): default methods, supertraits and impls for builtin types.** A trait method may carry a body, which an impl may omit (getting the default, monomorphized per implementing type) or override with exactly the declared signature, and a trait whose methods are all defaulted can be implemented by an empty block; `trait B: A + C` names supertraits, so `impl B for X` requires an `impl A for X` and a `<T: B>` may call `A`'s methods (a `T: B` satisfies a `T: A` bound transitively, and a cycle is an error); and a trait may be implemented for a builtin type that already carries methods (the integer scalars, `String`, `str`, `Bytes`, `View`, an `Atomic<T>` alias), with the orphan rule keeping the trait in the same module as the impl. Both backends and the freestanding mode still need no new lowering: a default body becomes an ordinary concrete method per impl. What remains open in A-12 is `dyn`/trait objects with dynamic dispatch, associated types and consts, a generic trait, `impl Trait` in argument position, a `where` clause, an impl for a generic instantiation, and operator overloading through a trait, each still refused by name; `plan/traits.md` is the design and `plan/syntax.md` 9.5 the surface. **Slice 4 shipped (2026-10-03): borrowed trait objects with dynamic dispatch.** `&dyn Name` and `&mut dyn Name` are legal as a parameter type and as a local binding type; a `&T` where `T` implements `Name` coerces to `&dyn Name` at a call argument or a typed `val`/`var` binding, written as the ordinary borrow (`describe(&c)`), and a `&mut T` coerces to both spellings. A `&dyn` is a fat pair (the borrowed value's address and a static vtable pointer), `Copy`, owning nothing and dropping nothing; a method call goes through the vtable, one slot per trait and supertrait method with the supertraits first, each a thunk over the erased data pointer, so the call is bounds-free and allocation-free and a freestanding image can use it. Object safety is checked where the `dyn` type is written: a method returning `Self`, a parameter other than the receiver that mentions `Self`, or two methods of one name is refused by name. The coercion is the borrow it was written from, so borrowck tracks it unchanged; a `&dyn` can never be stored or returned. What remains open is `Box<dyn Name>` and a bare `dyn Name`, upcasting between trait objects, associated types and consts, a generic trait, `impl Trait` in argument position, a `where` clause, an impl for a generic instantiation, and operator overloading through a trait; `plan/traits.md` 9 is the design and `plan/syntax.md` 9.5.1 is the surface. **Slice 5 shipped (2026-10-03): associated types.** A trait may declare `type Item` (optionally bounded, `type Item: Named`), an impl binds it with `type Item = i32` and must bind every declared one and no other, and `Self::Item` in a trait signature (a default body included) or `I::Item` for a bounded type parameter names the type each impl supplies. The projection is resolved at each instantiation, so dispatch stays static and neither backend learns a new lowering; the declared bound is checked at every impl and generic code then uses the bound's methods through the projection. A trait that declares an associated type is not object safe, so `&dyn` of it is refused by name. Default associated types, associated consts, generic associated types and equality constraints (`I: Iterator<Item = i32>`) are refused by name. `plan/traits.md` 10 is the design and `plan/syntax.md` 9.5 the surface. **Slice 6 shipped (2026-10-03): generic traits, `From`, and error conversion for `?`.** A trait may take type parameters (`pub trait From<T>`), a trait method written with no receiver is a static method (`fun from(value: T).return: Self`, called `AppErr.from(x)` or `X.from(x)` through a bound), an impl names the trait instance (`impl From<IoErr> for AppErr`) and one type may implement `From<A>` and `From<B>` at once, and a bound may carry arguments (`<X: From<i32>>`). Dispatch stays static, so neither backend learns a new lowering and a freestanding image may use it. `std/convert` ships `From<T>`/`Into<T>` with no blanket impls, and `?` converts a differing failure payload through `E2.from(e1)` when the impl exists, naming both types and `From` when it does not. What remains open in A-12: `Box<dyn Name>` and a bare `dyn Name`, upcasting between trait objects, associated types and consts, an associated type or `&dyn` of a generic trait, a blanket impl, `impl Trait` in argument position, a `where` clause, an impl for a generic instantiation, a generic method, and operator overloading through a trait; `plan/traits.md` 11 is the design and `plan/syntax.md` 9.5 the surface. **Slice 7 shipped (2026-10-03): owned trait objects, `Box<dyn Name>`.** A `Box<T>` whose `T` implements a trait coerces to `Box<dyn Name>` at a call argument, a typed binding, a `return`, a `datac` field initializer and a `List.push` argument, and the coercion is a *move*: the box's allocation becomes the trait object's, so nothing is copied and no second allocation happens. The value is the same fat pair a `&dyn` is (the erased data pointer plus the same static, read-only vtable), but it is not `Copy` and it owns what it points at. The vtable gains a drop entry, and the box frees through it, so dropping a `Box<dyn Name>` runs the concrete type's own drop glue (user `drop` first, then the fields) before the allocation is freed; a `List<Box<dyn Name>>` and a `datac` field free their elements and their value the same way. The vtable also carries the concrete type's size and align, which the freestanding allocator hook needs to free a value whose size is erased. A method call goes through the vtable as it does on a `&dyn`, `get` borrows a `&dyn` back out of the box, `Box.empty()` is the null owned trait object, and `&Box<dyn>`/`mut Box<dyn>` reach the box's own vtable through the borrow. Object safety is unchanged and is checked where the `dyn` is written (`Box<dyn A + B>`, a generic trait and a trait with an associated type are refused by name), the borrow checker treats the value as any owned `Box` (a move is a move, a partial move of a field is refused), and an owned trait object crosses a thread boundary while a borrowed one does not. Both backends emit the same vtable and the same drop, and a freestanding image with its own allocator builds with no undefined symbol and boots. What remains open in A-12: a bare `dyn Name`, upcasting between trait objects, associated types and consts, an associated type or `&dyn` of a generic trait, a blanket impl, `impl Trait` in argument position, a `where` clause, an impl for a generic instantiation, and a generic method; `plan/traits.md` 12 is the design and `plan/syntax.md` 9.5 the surface. **Operator overloading closed for the arithmetic, order and unary-minus operators in language-completeness task 5** (`plan/traits.md` 13): `std/ops` ships `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg` and `Ord`, `std/fmt` ships `Display`, and a `datac`/`enum` that implements one gets the operator as a front-end desugar into the trait method, on both backends with no new lowering. A bitwise/shift/logical operator through a trait and a user-declared operator trait stay out; an operator on a bounded generic type parameter works, because the body is checked per instantiation. `plan/syntax.md` 9.5.4 is the surface.
- **A-13. Visibility/privacy.** Every top-level item of a module was reachable as `alias.Item` (MK2-S1-M1) with no way to keep one in. A ~100k-line compiler with a fully public surface is a structural problem, not a style one. **Slice 1 shipped in MK8-S2 item A-13**: private by default, with `pub` accepted as an optional leading token on a top-level `fun`, `extern fun`, `datac`, `enum` and `const`. The gate is a resolution error in `infer.rs`, not a loader rule: an item of another module named through an alias is refused while it is not exported, and its own module still reaches it bare. A method carries no `pub` (its reachability follows its declaring type, and `pub` there is a parse error that says so), a `pd` carries none (module-scoped by design, item 10), and the refusal names an existing item as private, which is distinct from `module 'X' has no item 'Y'`. A compiler-shipped `std/...` module exports everything, transitionally, because the shipped modules import each other (`syntax.md` 13.4). **Left for a later slice**: nothing else is scoped yet. There is no `pub` on a field, a variant, a method or a passdown; no per-item export list (`pub(items)`); no crate, package or `pub(crate)` shape; and the shipped-module exemption itself is removed by the slice that marks the shipped declarations `pub`. **The shape of an exported signature is checked in the same slice** (`syntax.md` 13.4): a `pub` item may not name, anywhere in its signature, a type its module does not export, and the rule recurses through containers, arrays, generic arguments, function types and borrows. A type parameter is not a declared type, the shipped-module exemption applies, and a private declaration may name anything. `impl` lines, `pd`s and `main` are unchanged.
- **A-14. Compilation at scale.** Separate compilation, incremental/query-based compilation, a cross-build cache, and a reserved internal-library location (today `impl` is local-files-only and `std/...` is the *compiler's* namespace). The measured baseline makes this a requirement rather than a nicety: ~95% of `kelpc build` is the C toolchain's fixed cost and Kelp's own pipeline is 3 to 4 ms (recorded in the MK7 record in `done.md`), and a compiler-grade program is an order of magnitude more source than the current front end. The LLVM backend (the MK7 record in `done.md`) does not shrink that cost: it is the same backend `cc` uses. **Slice 1 shipped (2026-10-04): separate compilation.** `kelpc build --incremental` (and `kelpc run --incremental`, and `[build] incremental = true` in `coral.toml`) keeps the front end whole-program and splits the *backend*: one LLVM module per source module id, holding that module's own items and the instances of its generic functions, plus one `_support` unit holding every compiler-generated helper (the per-type drop/clone/eq/hash/order functions, the container sets, the closure thunks, the vtables, the panic helpers and the `pd` globals). Each unit is optimized at the selected `-O` level and compiled to its own object under `<out>.units/`, and `driver.rs` links every unit object with the runtime and the per-program `extern fun` object. A symbol another unit references is external in its owner and a declaration in the user; one only its own unit uses is `internal`, and the reference set comes from the typed IR (plus the per-program C object's own text, which can call across the object boundary in C). Emission order is a function of declaration order and sorted type lists, never of a hash map's iteration order, so identical sources produce byte-identical unit IR (`KELPC_DUMP_UNITS=<dir>` writes it, and two real nondeterminism bugs were fixed for it: the capability grants and the generic instantiations were both emitted in map order). The mode is off by default and changes nothing when off; the C oracle ignores the flag and keeps its one translation unit; debug info is emitted per unit, each unit's compile unit naming its own `.kp` files; a freestanding project is refused by name. What the slice deliberately does not do is the documented cost: there is no cross-unit inlining, and no caching or parallelism yet. `plan/incremental-compilation.md` is the design, the flag, the unit and linkage rules and the limits, and `plan/kernel-ub-notes.md` carries the stage note. **Slice 2 shipped (2026-10-04): the content-addressed object cache.** A unit's object is a pure function of (its LLVM IR text, target triple, CPU and feature string, optimization level, relocation and code model, debug-info setting, compiler version string); the key is the hex SHA-256 of a labelled canonical byte string built from exactly those plus the IR (an in-tree SHA-256 in `kelpc/src/sha256.rs`, since `kelpc` has no dependencies), and the entry is `<key>.o`. There is no dependency tracking and no interface file: identical IR means identical object, so correctness cannot rest on a dependency graph. The cache lives in `$KELPC_CACHE_DIR` or `<out dir>/.kelpc-cache`; a store writes a temporary file and renames it into place so concurrent builds never see a partial entry; a missing, unreadable, empty or visibly truncated entry is a miss, and an entry that fails to link is reported with the units that used it and deleted so the next build recovers. `KELPC_CACHE=off` disables a build, `KELPC_CACHE_STATS=1` prints `kelpc cache: H hits, M misses, S stored`, `--timings` adds per-phase wall times and a per-unit `hit`/`miss` list, `KELPC_CACHE_MAX_MB` (default 1024) evicts oldest-modified entries at the end of a build, and `kelpc cache stats`/`kelpc cache clear` inspect and empty the directory. The tests build the same project twice (second is all hits and the binary is identical), change one string literal or one callee signature and assert exactly the affected units miss (checked against the dumped per-unit IR), vary `-O` (no sharing), truncate an entry (a miss, rewritten), build twice at once (both succeed, no partial files), hit the size cap (oldest first), and disable the cache (nothing written). **Slice 3 shipped (2026-10-05): parallel unit compilation.** A cache miss is lowered, optimized and emitted on a worker thread inside `std::thread::scope`; each unit creates its own LLVM context and each worker owns one `TargetMachine`, and LLVM's targets are registered once before the first worker starts. The worker count is `KELPC_JOBS` when it names a positive integer and **2** otherwise, deliberately not the CPU count on this small host. Results are collected by unit index and the objects are linked in unit order, so thread timing cannot change an object or a binary; a unit that fails or panics is recorded and the other workers finish, the build then fails naming the first failing unit by index (not by race), and the units that did compile keep their cache entries so the next build resumes. The memory guard is unchanged: `_exit(75)` from its watchdog is process-wide and runs no destructors, so it ends a build with workers the same way it ends a whole-program one. Tests: the serial/parallel equivalence corpus, byte-identical unit IR and objects at jobs 1 and jobs 4, the failing-unit resume, and the memory-floor test with workers. **A-14 is therefore only partly done, and only on the backend side.** What is done is separate compilation of the *backend* into units, a content-addressed object cache over those units, and parallel compilation of them. What is **not** done: the front end is still whole-program (parse, resolve, infer and borrowck run once over every module); there are no interface files and no dependency tracking (the cache key names a unit's exact IR instead); there is no cross-unit inlining; there is no reserved internal library location (`impl` is still local-files-only and `std/...` is the compiler's namespace); and the cache is not shared across machines or compiler versions by construction. What slice 3 measured is in `plan/incremental-compilation.md`: it does not pay for a 3-line program, and it starts to pay once a program reaches the heavy `std` modules (a ~100-line `std/http` project is 1.4 to 1.6 times faster cold and about 2.5 times faster warm).
- **A-15. Tooling.** A test framework (an explicit non-goal today) — the library half of that want is recorded as **`testkit`, the self-test harness** in the Backlog part below, `kelpc fmt` (shipped — item 13, with its three recorded limits), a lint pass with the configurable naming option (item 23), and a documentation generator with doc-comment extraction.
- **A-16. Diagnostics and debuggability.** **The source-location primitive shipped:**
  `std/source` is ungated, and `source.file()`/`source.line()` resolve at the Kelp
  call site on both backends, so a library can name the location that invoked it.
  The C backend maps its generated code back
to the `.kp` one directive per statement (item 20, closed), so a `cc` diagnostic on
it names a source line. The rest of this item moves to the LLVM backend
(the MK7 record in `done.md`): LLVM emits DWARF from the debug locations we attach,
so the format is no longer our work. **The tracing and profiling hook set is now
`std/trace`**: `trace.event(source.file(), source.line(), name)` writes an event,
and `trace.begin`/`trace.end` write a duration span to stderr. It is explicitly
opt-in through `impl "std/trace" caps(time = [])`, timestamps use the monotonic
clock, and the tab-separated records escape tabs and newlines in text fields. A
library cannot discover the location of its caller, so callers pass the two
`std/source` values deliberately. `plan/tracing.md` is the design record.
- **A-17. Retired, and the number stays unused.** The bootstrap milestone this item asked for (build `kelpc` in Kelp, then check the fixpoint) is cancelled permanently: rewriting `kelpc` in Kelp is out of scope. See **Far future additions** below and the MK7 record in `done.md`.
- **A-18. A fixed-size, stack-allocated array type.** ***DONE*** (`[T; N]`, held inline, with `len`/`is_empty`/`get`/`set` and a bounds check; `syntax.md` 3 and 12.4 are the reference). *New, named 2026-09-20.* `syntax.md` §3's type table has no `[T; N]`-shaped entry: `List<T>` is the only sequence type, and it is heap-backed and growable, so every fixed-size buffer today either goes through the allocator or does not exist. This is not only a systems want: a page table, an IDT/GDT, a register-save frame, or any interrupt/ISR-path buffer must exist with zero heap and before an allocator can be trusted (B-3, B-7). Arguably more fundamental than B-3 itself an `unsafe` pointer still needs something fixed-size to point at that is not behind `malloc`. Needs a type spelling, `Copy`-when-element-is-`Copy` semantics, bounds checking (with an `unsafe` escape once B-3 exists), and a decision on how it interacts with `repr(C)` (B-2, since a C struct's array field is exactly this). **Extended in language-completeness 6**: a length may be a `const` type parameter (`datac Buf<const N: usize>(var data: [i32; N])`, `fun sum<const N: usize>(a: &[i32; N])`), inferred from an array argument, folded from the existing constant evaluation as a const argument, and monomorphized one copy per value; arithmetic on the parameter inside a type (`[T; N + 1]`) stays refused by name. `plan/const-generics.md` and `syntax.md` 9.3 are the reference.
- **A-19. Compile-time constant evaluation.** ***DONE*** (a `const` initializer and an array's length are both a general compile-time expression, and either may call a plain `fun` that stays inside the same subset; `syntax.md` 14.1 is the reference). *New, named 2026-09-20.* `syntax.md` §14.1's `const` folds a scalar initializer expression at compile time (`const PI2: f64 = math.PI * 2.0`) but that is the whole of it: there is no general const-evaluated expression, no compile-time function execution, and nothing that could compute a fixed array's length (A-18) or a `repr(C)` struct's array-field size from an expression rather than a literal. Without this, A-18 can only take a bare integer literal as its length, which is usable but shuts out the common pattern of a length computed from another constant (`const PAGE_SIZE: usize = 4096`, `val table: [Entry; PAGE_SIZE / ENTRY_SIZE]`).

#### B. Substrate required for deep systems

*Promoted to MK9 (see `roadmap.md`'s MK9 tables). The items are kept here as the detail.*

What separates a systems-*dialect* application language from a language that can host a kernel, a driver, a firmware image, an allocator or a runtime.

- **B-1. User FFI.** `extern fun` is no longer compiler-only. MK9-S1-M1's first slices landed: a project's `coral.toml` `[extern."<module id>"]` section assigns a user module one of the capability domains, a native library, a `header`, `include_dirs`/`library_dirs`, an optional `pkg_config` package and the exact `symbols` its declarations may bind to (a `"kelp=c_symbol"` entry renames that binding). The language side landed with it: a user `extern fun`, `...` variadics, `fun(...)` function pointers as parameters and returns, `extern type` opaque handles with a parent chain, `null()`/`is_null()` and the unchecked `cast()`, and `move closure(...)` callback parameters expanding to the `(thunk, env, destroy)` triple, on both backends, plus the `ui` domain a display binding needs. What is left is `extern "C"` block syntax, symbol import/export and linkage attributes, and a `repr(C)` struct by value (B-2, needed as soon as one crosses); `plan/user-ffi-gap-analysis.md` is the record. With them, Kelp reaches libc and a real C library: `examples/polyp/` binds GTK4 through this and nothing else.

  **The capability-interaction design pass happened, decided 2026-09-26: extend the existing domain mechanism to a manifest-declared user module, do not build a second gating system.** Today a module's domain is a fixed compiler table (`stdlib.rs::domain_of`, keyed by module path, e.g. `"std/fs" => "fs"`) — the *importer's* `impl "std/fs" caps(fs = [...])` line is what is checked, and `std/fs.kp` itself writes no `caps(...)` on itself at all. The fix is to let `coral.toml` add an entry to that table for a project's own module: a new manifest section (`[extern]` or similar) assigns a user module one of the **six existing domains** (`fs`, `net`, `process`, `env`, `time`, `rand`no new domain names or new pattern vocabularies in this pass, so the existing per-domain pattern matcher (`fs_checked_args` and its siblings) needs no new code) and names the native library and the exact symbol set that module's `extern fun` declarations may bind to. Once assigned, everything downstream is unchanged: an importer writes `impl "src/sqlite_ffi" caps(fs = [pattern])` exactly as it would for `std/fs`, checked by the same gate. This is real new manifest vocabulary (the roadmap text's "new grant vocabulary" concern was correct), but it is additive to one existing mechanism rather than a second one, and the symbol allowlist is what makes the native surface auditable rather than an open link-time escape hatch. A domain that doesn't fit one of the six (a device, an IRQ line) is explicitly out of scope here it is C-3's territory (MK10-S1), not this pass. The "admitted hole" option (no check at all) is rejected outright: it would let any FFI-using module bypass `caps(...)` entirely, which guts the language's headline feature. **Implemented as MK9-S1-M1's first slices**, with `ui` added as the seventh domain for a display binding; `plan/user-ffi-gap-analysis.md` lists what landed and what remains.
- **B-2. ABI and layout control.** No `repr(C)`, no alignment, no packing, no unions, no bitfields, no explicit size/offset, no enum discriminants, no layout intrinsics (`size_of`/`align_of`/`offset_of`). So no MMIO register block, no wire or on-disk format, no packet header, no kernel struct, no C-interop struct the artefacts deep systems work is made of. MK7 stage 3 lists `datac` layout, calling convention, and `extern "C"` calls as *backend* work for the compiler's own ~20 externs; this item is the user-facing version of the same thing.
- **B-3. `unsafe`, raw pointers, and the memory surface.** No raw pointers, no pointer arithmetic, no casts/`transmute`, no `volatile`, no address-space or provenance control, no uninitialised allocation. Needed for MMIO, DMA, intrusive lists, allocators, page tables, kernel objects and lock-free structures. The plan's own evidence that Kelp cannot express this today is that `Bytes`/`String`'s runtime is a fixed C preamble in `codegen_c.rs` and the stdlib's primitives are 251 lines of C in `externs.rs`. With A-11's checker still conservative and no `unsafe`, there is also no escape valve the single structural reason a kernel is out of reach.
- **B-4. Atomics, ordering, and a published memory model.** **Done, MK9-S3-M1 (A1, A2, B1, D1):** the atomic cell, `Ordering`, the standalone fence, the `Send`/`Sync`-shaped crossing rules, and the published definition at `wiki/language/concurrency.md`. What a `&mut` guarantees, what concurrent access to one location does and what the compiler may assume are all stated there; what a capability-protected region may be shared across is still open, scoped to MK10-S1.
- **B-5. Threads, and then a concurrency story.** **Done, as MK6-S1-M1, MK9-S3-M1 and the `Mutex<T>` remainder:** `thread.spawn`/`thread.join`, the rule for `&mut` never crossing a thread boundary and a shared borrow crossing in exactly one shape, owned data moved to a thread, the per-thread panic policy (a panic ends the thread; the process survives; the frame is admittedly leaked, since there is no per-thread TLS or `Drop` on the panic path), and `std/sync`'s `Mutex<T>`: a `lock` scoped block with a `mut T` borrow that cannot escape, release on every exit, poisoning on a panic inside the block, and `into_inner` (`plan/mutex.md`). `async`/`await` stays a further step, needing a state-machine transform in codegen nothing here builds. The intermediate MK5-S7-M1 shipped first, multi-process plus `poll`, is still the answer for a program that wants isolation rather than sharing.
- **B-6. Freestanding / no-runtime mode.** Kelp assumes an ambient runtime: libc stdio, `malloc`/`realloc`/`free` from the preamble, `atexit` for owned `pd` drops, `main(argc, argv)`, and `kelp_panic` → `exit(1)`. Needs a `no_std`-shaped mode with no libc, no stdio and no implicit heap, a user-supplied panic handler and entry point, raw syscall access, target selection, linker-script/section control, static and shared library output, cross-compilation, and C-free static-ELF output. This is the requirement for kernel, bootloader, firmware, hypervisor, RTOS and embedded targets and MK7 stage 5's "static ELF with raw syscalls and our own runtime" is the same item approached from the toolchain side. **Decided, 2026-09-26: defer, do not reverse the ambient-runtime assumption yet.** Nothing concrete (an actual kernel, firmware image or embedded target) is asking for this today; reversing "assume libc" speculatively, with no program to build against it, is exactly the kind of decision this section warns against making without a driver. Revisit the moment a real freestanding target exists.
- **B-7. Allocator control.** A custom global allocator, per-arena/per-subsystem allocators, alignment and huge-page requests, DMA-safe allocation, and *fallible* allocation (`try_alloc`) today allocation failure panics and `mem.alloc(n)` is a fixed zero-filled `Bytes`. Arena/bump allocation and custom allocators are explicit non-goals in the current plan, so this item reverses that non-goal for the same reason A-7 wants an arena for the compiler.
- **B-8. Destructors and deterministic cleanup.** No user `Drop` (needs A-12), no `defer`, drops only at lexical scope exit and `atexit`, and a panic path that calls `exit(1)`. Systems code needs release points it can point at, a `Drop`-equivalent for resource handles, and a cleanup story for the panic/abort path which also means rethinking "a panic takes the process".
- **B-9. Hardware and ISA surface.** SIMD vectors, intrinsics, CPU-feature detection and dispatch, inline assembly, naked/interrupt-handler functions, calling-convention control (syscall, interrupt, fastcall), stack alignment and prologue control, atomics-as-instructions (with B-4), and cache/prefetch hints. Without these there is no lock-free primitive, no context switch, no device ISR and no vectorised kernel.
- **B-10. Data-format primitives.** Endianness conversion intrinsics, unaligned load/store, and byte-order-aware reads and writes, so a wire or on-disk format is expressible without hand-rolled shifting (which A-9 is also needed for).
- **B-11. Thread-local and per-CPU storage.** *New, named 2026-09-20.* B-4 and B-5 cover atomics and what crosses a thread boundary, but neither names *per-CPU* data the single most common kernel pattern: a per-CPU run queue, a per-CPU interrupt stack, per-CPU scheduler state. This is a distinct storage class from a thread-local in an application (there is no OS thread underneath a CPU core in a kernel), and it needs its own storage-duration rule rather than falling out of B-5's threading model.
- **B-12. Virtual memory and address-space management.** *New, named 2026-09-20.* B-3's own text names "page tables" once, as an example of what raw pointers would let a program *build*, but nothing in the plan addresses the far larger question of how a kernel represents and manages an address space it owns: mapping and unmapping regions, page-table walks, and how a capability grant (MK10) would name a physical or virtual memory region the kernel itself is managing, as distinct from MK10-S1's device/MMIO vocabulary for a *userspace* grant.
- **B-13. A kernel-side syscall ABI.** *New, named 2026-09-20.* MK9-S4-M2 ("raw syscall access") is Kelp code *calling* a syscall as a client of some other kernel. A kernel written in Kelp needs the opposite side: defining and dispatching its own syscall ABI for userland register conventions on entry/exit, trap/exception vectoring into the dispatcher, and validating a pointer argument that came from untrusted userspace before it is dereferenced. Structurally a different problem from B-1's FFI-as-caller story, and unaddressed anywhere in the plan.
- **B-14. Stack-overflow guards and stack probing.** *New, named 2026-09-20.* Nothing in B-9's ISA-surface item (which already covers stack alignment and prologue control) mentions guard pages, a stack-limit check, or a probing sequence for a large stack frame. Relevant the moment deeply recursive code runs on a fixed, unguarded kernel stack, which is the normal case before an OS-level guard-page mechanism exists to catch it.
- **B-15. Panic and cleanup semantics with no OS underneath.** *New, named 2026-09-20.* B-8 records today's rule as "a panic takes the process" via `exit(1)`; in a `no_std`/freestanding target (B-6) there is no process and no `exit(1)` to call. What a panic *does* with nothing underneath halt, triple-fault, call a user-supplied hook, spin is not stated even as an open question, and B-6's "user-supplied panic handler" bullet does not say what the default is or what contract the handler is given.
- **B-16. Inline-assembly operand and constraint syntax.** *New, named 2026-09-20.* B-9 names "inline assembly" as one bullet among several; it does not specify how Kelp code would name a register, a clobber, or an input/output operand's constraint, which is the entire mechanical difficulty of a usable inline-asm feature (see Rust's multi-year `asm!` stabilization for the shape of this problem). Without this detail, "inline asm" is a wish, not a feature with a spelling.
- **B-17. A testing story for freestanding targets.** *New, named 2026-09-20.* MK11-S3 (conformance/fuzzing) and MK11-S4 (DWARF/sanitizers) both assume a hosted environment with an OS underneath the binary under test. Nothing addresses how a `no_std` kernel or firmware image gets tested at all a QEMU-driven harness, a hardware-in-the-loop rig, or even a documented decision that this is out of scope.

#### C. Capability-model gaps (this language's headline, extended)

*C-1 is promoted to MK10-S2, C-2 to MK8-S3, and C-3/C-4 to MK10-S1 and MK10-S3. The items are kept here as the detail.*

The capability system is the differentiator, and it is currently a compile-time constant allowlist plus an unrestricted entry module. Two consequences matter for anything beyond one sandboxed program.

- **C-1. Runtime-derived authority.** A real `kelpc` takes its authority from runtime data: source paths on `argv`, the project root, `PATH`/`CC`, a temp directory, an arbitrary `cc` binary. Kelp cannot express "this authority came from my input": grants are compiled-in patterns, no module ever holds a capability *value* it could pass or attenuate, and there is no runtime delegation. Needs capability values/handles as a first-class (or explicitly restricted) thing plus a rule for deriving a pattern from runtime input safely. `coral.toml [caps]` can now restrict `main` (C-2), but it can only name static patterns, so the headline feature is still off for a compiler whose authority begins in runtime input.
- **C-2. Restricting the entry module.** **Shipped:** `coral.toml [caps]` sets
  `main`'s own capability ceiling. With no section, the compatibility default
  remains every domain's whole resource; once `[caps]` exists, an omitted domain
  grants `main` nothing. The same grant controls both direct calls from `main`
  and what it may delegate, and the tests pin an ungranted domain, an allowed
  call and a runtime denial outside a narrow pattern. `syntax.md` 1.4.1 is the
  authority.
- **C-3. Device and kernel vocabulary.** Grants for device nodes, MMIO regions, IRQ lines, kernel object handles, memory regions/pages, and file descriptors *as capabilities* rather than as names the object-capability reading the model is already shaped for (seL4/Fuchsia-like), and the direction that would make capabilities a systems feature rather than a sandbox one.
- **C-4. Attenuation and per-request grants.** Handing a narrower grant to a plugin or worker at runtime (the multi-process story MK5-S7-M1 ships), revoking one, and bounding a grant's lifetime and holder count.

#### D. Verification and semantics duty

*Promoted to MK11. The items are kept here as the detail.*

Cross-cutting, and the reason the current claims cannot simply be extended to unsafe or concurrent code: every memory-safety and capability claim in the verification section is verified *through clang* (ASAN, `-fwrapv`). Once there is `unsafe`, raw pointers or atomics, the obligation transfers to Kelp, and the argument has to be about Kelp's semantics rather than C's.

**Superseded as a backend-flip gate (2026-09-20).** D-1, D-2, D-4 and D-5 were also the conditions a hand-written backend had to meet before it could become the default: it had to emit code whose semantics were pinned, emit its own DWARF, and carry a sanitizer story. Those obligations moved to LLVM (the MK7 record in `done.md` and its stage record): its IR has a defined semantics for the operations we emit, it emits DWARF from the debug locations we attach, and AddressSanitizer is one of its passes. What remains of D-1 to D-5 is the part about `unsafe`, atomics and threads, which is why MK11 still carries them all. D-3 (the Miri-equivalent checker) was never a backend gate and is unchanged.

- **D-1. A formal operational semantics, and an aliasing model for `&mut`** a Stacked-Borrows/Tree-Borrows equivalent, or a documented decision not to have one. The borrow checker's rules are implemented across `infer.rs`/`borrowck.rs`; the model they implement is not written down anywhere.
- **D-2. A UB catalogue.** Defined behaviour for overflow (currently `-fwrapv` from the C toolchain), uninitialised memory, out-of-bounds, provenance, the FFI boundary, and data races (once B-4 exists). "No UB" cannot be claimed against an undefined model.
- **D-3. A Miri-equivalent dynamic checker** (or a proving argument) for the move/borrow/aliasing rules, so soundness is a test result rather than a reading of the checker's source.
- **D-4. Conformance, differential testing and fuzzing.** A grammar/conformance corpus, differential runs of two backends over the same fixtures (the backend seam's `--backend=` flag is the seed of it, and the retired track's own refusal ranking is the method this reuses), and fuzzing of the lexer, parser and checker against the semantics.
- **D-5. Own sanitizers and debug info.** DWARF emission, source mapping (A-16), and a sanitizer story that does not depend on clang. **Superseded as a backend prerequisite**: LLVM emits the DWARF and ASAN is an LLVM pass, so a flip no longer depends on either being written by hand. What stays ours is a Sanitizer story for `unsafe` code and, from A-16, a location primitive a Kelp source can write.

#### E. Suggested order, and cost

*Block E calls A-7/B-7 (allocators), B-6 (freestanding) and B-4 (concurrency model) decisions to make rather than tasks to schedule. Those three are MK9-S5, MK9-S4 and MK9-S3 the decision is now made inside a tracked Mark.*

Nothing here is scheduled. If it ever is, the cheapest useful sequencing is:

1. A-1 to A-5 and A-11 unions/patterns, generics, `Option`/`Result`, function values, iteration, and checker expressiveness. Without them a compiler-grade front end is not writable at all, and A-1 is the largest single language change since borrow checking. (A-1 to A-5 have shipped; what is left of this step is A-11.)
2. A-6 to A-13 containers, shared data/arenas, views, bits, element rules, traits, privacy. The ergonomics that make a large body of Kelp code tractable.
3. A-14 to A-16 with C-2: scale, tooling and restricting the entry module. C-1's runtime-derived authority follows as MK10-S2. What a compiler-grade program needs beyond the language surface.
4. B-1 and B-2 FFI and layout. The first *systems* unlocks, and partly free from the C backend if only they were exposed.
5. B-3 to B-10 unsafe, atomics/model, threads, freestanding, allocators, destructors, ISA. Each one a subsystem; together, the difference between a systems-dialect language and a systems language.
6. Block D runs alongside from the first `unsafe`, and B-4 (the memory model) is a precondition for honest claims about B-3, B-5 and B-9.

For calibration: A-1, A-2, A-4, B-3, B-6 and B-9 are each larger than the entire MK5-S1 to MK5-S7 stdlib program, and A-14 is a project of its own. Three items are reversals of deliberate decisions rather than extensions A-7 and B-7 reverse "no custom allocators, no arena", B-6 reverses "assume an ambient libc runtime", and B-4 creates the concurrency model v1 avoids on purpose. Those should be treated as decisions to make, not tasks to schedule.

#### F. Dependency and precedence notes

- **The precedence rule still applies: `syntax.md` wins on syntax and style.** Any syntax these blocks need a sum type, `unsafe`, `repr`, `'a`, `View`, `defer`, `?`, `if let`, `trait` must be added to `syntax.md` first, because that file is the authority on syntax and this one is not. (`for` was on this list and is the one entry that has since shipped, as MK8-S1-M3, with `syntax.md` §6.2 edited first.)
- **Open items these blocks close or supersede**: 4 (`when` value patterns), 11 (line continuation, if syntax work starts), 12 (a datac naming only earlier datacs), 13 and 23 (`kelpc fmt`/lint), 15 (the three deliberate leaks, via field-granular drop plus a flow-sensitive merge), 18 (`main` unrestricted), 20 (`#line`/debug), 28 (element rules), 29, 30 and 33 (borrow lifetimes, provenance, bound-borrow scoping), 34 (generics), 36c (`Option`/`Result`), 37 (TLS, as the first FFI/link case), 41 (`Map` keys, `Set`), 44 (a length-carrying view), 53 (`char`). Three that were on this list — 27, 36a and 46 (`for`) — closed early, as **MK8-S1-M3**: the cheap loop shipped as a parser desugar, and only the `iter`/`next` protocol is still a question.
- **The structural blockers, restated**: see **Far future additions** above for the three, and why the first two are also the reason A-2 sits on the critical path.
- **What is not in this backlog, on purpose**: GC or exceptions (both permanent divergences, `syntax.md` §13), and a REPL/LSP/IDE story (unscoped in this plan entirely, and downstream of A-1 to A-16). A package registry and third-party dependencies were on that list; they are now the Coral design's decision (roadmap open item 72) rather than a settled non-goal, with path and git dependencies paying off whether or not an index ever exists.
- **What is not in this plan at all, permanently**: rewriting `kelpc` in Kelp. There is no bootstrap stage, no stage 1, no stage 2 and no fixpoint, and none will be added; the compiler is and stays a Rust program. The MK8 mark's rewrite stages were cancelled for this reason, and the LLVM backend change does not reopen the question (the MK7 record in `done.md`).

#### G. Small language and ergonomics wants

*Unscheduled, and not blockers. Every item below is a convenience rather than a class of
program the language cannot express, and none is a reversal of a v1 decision. They are written
down so the plan can say no to a concrete thing instead of re-arguing an idea.*

- **G-1. A native UI library.** A window, an event loop, text entry, drawing and input events, all written in Kelp. The substrate is in: B-1's first slices (user FFI and the `ui` domain) let a module bind GTK, and Polyp (`examples/polyp/`) is a working GTK4 library and counter built on them, with the event-loop authority gated as `ui = ["*"]` because a display call carries no name to match (C-1 is what would make a finer pattern enforceable). What is missing is depth rather than reach: drawing, layout control and any platform beyond Linux (B-2, and the toolkit-free alternative of B-2, B-3, B-6 and B-9). The earlier position was that GUI is "a library (writable once views and generics exist), a target, or a deliberate non-decision"; views, generics and now a prototype exist. Nothing is scheduled.
- **G-2. Multiple return values.** `fun min_max(xs: &List<i32>).return: (i32, i32)`, plus a destructuring binding (`val (lo, hi) = min_max(xs)`), so a function hands back two things without a one-shot `datac` per pair. **Shipped** (2026-09-24) as MISSING-z2bB9, with `syntax.md` 3.1 and 4 as the authority: `syntax.md` gained the type and the binding form first, exactly as this item asked, and the three decisions it listed are answered there. A tuple is a *record with positional fields*, so (a) it is not `Copy`, it moves as a whole, and a position read out of an owned binding is the partial move 10.1 already has, while reading one out of a borrow is refused; (b) `?` is about its operand and never about the tuple, so a `Result<(A, B), E>` propagates to the tuple and the binding takes it apart; and (c) an element is stored by value, so it obeys open item 12 (a tuple field may only name types declared before its declaration) and the field rules (`str`, `View` and a borrow are refused as elements). The surface the item did not ask for stayed out: no tuple pattern in `when`, no positional access on a value, no one-element tuple (`(T)` is `T`), and nothing variadic.
- **G-3. `elif`.** Spelling sugar for `else if`. **Decided and shipped** (2026-09-20): both spellings work and mean one link, `elif` is the preferred one, and `else if` gets a cosmetic warning from `kelpc lint`. This supersedes the argument this item carried when it was written (that `elif` is Python's and the plan's Kotlin-look preference argues for keeping `else if`): the spelling is a reading preference, so the compiler accepts both and the lint, not the compiler, speaks about it. `syntax.md` 6.1 carries both spellings and is the authority; the lexer has `elif` as a keyword, the `elif` link goes through the same parser function as `else if`, and `kelpc fmt` copies the token it was given, so neither spelling is rewritten.
- **G-4. The capability clause spelled `caps(...)`, without `with`.** **Shipped** (2026-09-20): the parser reads `impl "client" caps(net = ["127.0.0.1:*"])`. `with` carries no information: `impl` already means "this module declares what it imports", and `with` was never a keyword, only a contextual identifier the `impl` parser matched literally. The surface this item called the cost is what the register exists for: `syntax.md` §13.1 and §15.2, `architecture.md`, the shipped stdlib's prose, every fixture and example in `kelp/`, and the diagnostic that names the grant to write all moved in the same session, and the `wiki/` pages move on the unreleased branch. The old spelling was registered as `caps-with` and **removed 2026-09-21**, in the cycle that removed `impl "..." as name` rather than one of its own: the register's single deadline sentence said "the next development cycle" for both, so a second cycle would have made the finding name a deadline that had passed (open item 74). The parser now refuses `with caps(...)` by name, and the grant is unchanged.
- **G-5. A comment lint: a run of line comments that wants to be a block comment.** Two or more consecutive `//` lines with no blank line and no code between them warn that one `/* ... */` block comment says the same thing, which is exactly what block comments are for (`syntax.md` §2.1: a note that spans lines, or a commented-out region, and block comments nest). Warning only, never an error: consecutive line comments stay legal, the run length is a free parameter with a default of 2, and a `//` line immediately describing the statement below it stays a line comment. **Shipped** (2026-09-20) as the first rule of `kelpc lint` (`kelpc/src/lint.rs`), the pass item 23's naming-case option was waiting on.

#### H. The documentation's workaround list, worked off

*Sources: the wiki's [Known issues](/meta/known-issues) and [Pitfalls](/language/pitfalls)
pages, which are derived from `syntax.md` §17 (limits in v1), §18 (errors you will hit) and §22
(the rules that explain most errors). One item per row that carries a workaround. The invariant
this block exists for: when H is worked off, the Pitfalls page is rules rather than workarounds,
and Known issues is empty. Every H item names the existing item it overlaps, or says it is new.*

- **H-1. Partial moves, and the owned payloads they unblock.** **Shipped as A-11 slice 1**, both halves: `cannot read the owned field 'name' by value` is gone for an owned local, because reading an owned field by value now moves it out, and a `move` parameter counts because it is an owned local in the callee; an owned `enum` payload read out of an owned place moves out the same way, because `when`/`if let` over an owned place binds it by value. That is what the owned helpers waited on, and they ship with it: `option.unwrap`/`expect`/`unwrap_or` and `result.map`/`map_err` take their receiver with `move`, so `option.unwrap` on an `Option<String>` and `result.map` over a `Result<T, MyErr>` work. What is left of the item is the rest of A-11: a field or payload read out of a **borrow** is still refused (the accessors whose receiver stays a borrow are `Copy`-only, and `list.filter` over an owned element is the remaining one of those), a projection out of a **nested place** is refused, and open item 15's field-granular drop tracking is untouched. **Work: A-11** (the rest).
- **H-2. A temporary that a binding keeps alive.** Deletes `this call returns a borrow of its parameter 'self', so that argument has to be a variable or a field` and `.as_str()`/`.view()` on a temporary is refused. **Work: A-11** (lifetimes) plus a temporary lifetime extension rule — a temporary bound by `val u = set.union(a, b)` lives as long as `u` — which is the shape open item 30 draws the line against today.
- **H-3. One borrowed text type.** Deletes `argument 'b' has type 'String', expected 'str'` and `argument 'x' has type 'View', expected 'str'`. **Work: open item 21's other direction** (an owned `String` where a `&str` is expected) plus collapsing `str` and `View` into one length-carrying borrowed type, so `v.to_string()` is not the price of a slice at a `str` parameter. `syntax.md` §5.1/§11.5 are the authority.
- **H-4. Borrows in fields.** Deletes `field 'text' is a borrowed type ('View')` and `field 'text' is a borrowed type (str)`. **Work: A-8/A-11** — the lifetime syntax that lets a stored borrow name its source; A-8 is exactly the half that did not ship with `View`.
- **H-5. Equality that is not spelled `eq`.** Deletes `cannot compare 'View' values with '=='`. **Partly shipped in MK8-S2 item A-12 slice 2**: `==`/`!=` now lower in the front end to a declared `fun T.eq(other: &T).return: bool` (`a == b` is `a.eq(&b)`) for a `datac`/`enum`, so `eq` alone is a complete declaration that gives the operator without making the type a key, and to the builtin `View.eq` for `View` against `View` or a `str`. Item 25 records why `==` on an owned value, a `datac` or a `str` was a deliberate type error; a `datac` with no declared `eq`, a bare `String`/`Bytes` and a `str` keep that refusal (no equality is derived), and `<`/`>` stay refused on every one of them. **Extended in language-completeness task 5** (`plan/traits.md` 13): the shipped `std/ops` declares `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg` and `Ord`, and a `datac`/`enum` that implements one gets the matching arithmetic or order operator as a front-end desugar into the trait method (`a + b` is `a.add(&b)`, `a < b` is `a.cmp(&b) < 0`), with each operand evaluated once and only borrowed. `==`/`!=` still come only from a declared `eq`, so a type with `Ord` but no `eq` is refused equality by name and a type with `eq` but no `Ord` keeps the old `<`/`>` refusal. Builtin numeric types keep their builtin operators untouched. **Work left in this item:** whether `String`/`Bytes` compare byte-wise through the operator (the `PartialEq`-shaped trait), which is what the `Bytes` `check_eq_bytes` helper at line 934 is still waiting on.
- **H-6. Element type inferred for an empty container.** Deletes `List.empty()` / `Map.new()` has no element type. **Work: new** — infer the element from the first `push`/insert, or from the expected type where one exists, so the binding annotation is not the only source. `List<Circle>` (declared after the element type) is the ordering rule the work has to respect. **Shipped** (2026-09-20): a bare `var xs = List.empty()` is no longer refused at its declaration. Its element type stays open until the first operation that has to know it, and `push`/`insert`/`set` hand it in, from the next line, from inside a nested block, or from a loop binding, all the same, while a position that expects a container supplies it (`take(xs)` against `fun take(xs: List<i32>)`). A container nothing ever decides is refused exactly where it always was, at the binding, with the same message. `Map.new()` takes its key from the first `insert`'s key argument and its value from the value argument; `Box.empty()` takes its element from `set`. The order the compiler reads types in does not move, so the `List<Circle>` ordering rule is untouched: `Circle` declared after the list behaves the same written on the binding or inferred from a `push`.
- **H-7. Nested and view-valued containers.** Deletes the refusal of a nested container as a list element. **Half shipped in MK8-S2 item A-10 slice 1**: `List<List<T>>` and `List<Box<T>>` compile and run, so `'…' cannot be a 'List' element` no longer fires for a `List` or a `Box`. The view-valued half, a borrow or a `View` element, is still refused and needs H-9's or A-11's lifetime story; the array rule is not part of this and stays as it is.
- **H-8. `Map` keys beyond `String`, the integers and `bool`.** Deletes `Map` key type refused. **Shipped in MK8-S2 item A-6 slice 1**, by derived structural hash and equality: the compiler derives the key's hash and equality for a keyable `datac`/`enum` from the same fixpoint that derives its order and deep copy, so neither A-12 nor A-4's comparator was needed (see A-6 for the pivot and the reason a comparator was rejected). What this deletes is the refusal of a `datac`/`enum` key; a float, a container, a view, a borrow and a non-keyable `datac`/`enum` are still refused, and `Set<T>` is a later slice. **Widened again in MK8-S2 item A-12 slice 1**: a `datac` or `enum` that declares `hash` and `eq` is a key however the derived fixpoint judges its fields, so a float *field* no longer stands in the way (a bare float, container, view or borrow key still does, and the type has to be deep-copyable because the map clones its keys in).
- **H-9. Iteration that may mutate.** Deletes `for` cannot `push` to what it walks. **Work: A-5's open protocol**: a second spelling (a consuming `for x in move xs`, or an explicit iterator/cursor API) rather than a weaker borrow rule, since the loop borrowing its iterable is the design and the same rule every ownership language has. **Decided 2026-10-02: refuse every mutation of the iterated place** (`syntax.md` 6.2, `bugfix-pass.md`), so the rule is uniform for `Copy` and owned elements and `for x in xs { xs.push(x) }` is a compile error; the index `while` stays the way to change a list a loop walks. **A-5's protocol shipped (language-completeness task 2, `plan/iterators.md`)**: a user iterator is not covered by the place rule at all, only by the ordinary exclusive-borrow check, so a cursor that changes what it walks is expressible now; a `List` still needs the index `while`, because the element binding is `List.get`'s borrow and the walk is not a cursor. The rest of H-9 (a consuming `for x in move xs`) stays open.
- **H-10. Fallible narrowing conversions.** Deletes `i32.to_u64: value out of range` (runtime panic). **Shipped**: `n.try_to_u64()` is the twin of `n.to_u64()` and hands back `Option<T>`, for exactly the pairs whose plain conversion can lose a value, so a caller tests instead of panicking. A widening is already exact and so has no `try_to_<T>`, and the diagnostic says which method to write in that case.
- **H-11. A byte-literal spelling.** Deletes `argument 'c' has type 'char', expected 'u8'` and the `val c: u8 = '"'` workaround. **Shipped**: `b'x'` is one ASCII character or a `\xNN` escape and a `u8` by construction, so a byte never needs the type written on a binding first; it does not widen into a context that asks for a wider type (`'x'` is the spelling that takes its type from where it sits), and `syntax.md` 2.4 carries the spelling.
- ~~**H-12. A literal that adapts to a widening target.**~~ **Shipped in 26.10.3:** an integer literal where a float is expected is that float when exactly representable; values never convert. Original text: Deletes the `n * 1.0` type error. **Work: open item 54's narrow fix** — a *literal* adapts to the expected numeric type (`f(255)` where `f(n: u64)`), while conversions of *values* stay explicit; item 54 records why widening operator rules were rejected.
- **H-13. Error conversion for `?`.** Deletes `?` refuses to propagate a different error type. **Shipped in A-12 slice 6** (`plan/traits.md` 11): `?` calls a declared `impl From<Source> for Target` when the operand's failure payload differs from the enclosing function's, and the missing-impl error names both payload types and `From`; `std/convert` ships `From<T>`/`Into<T>` with no blanket impl. `result.map_err` remains a workaround for the cases a `From` impl does not cover. `syntax.md` §5.2 and §17 state the conversion rule.
- **H-14. User-code overloading.** Deletes two `fun pick(...)` overloads collide. **Work: new** — the restriction is policy, not a missing mechanism: the compiler already overloads `abs`/`min`/`max`/`clamp` for the stdlib (MK2-S2-M1), so the work is deciding the user-facing rule (arity only, or full overload resolution) and its diagnostics.
- **H-15. Methods on `enum`, and combinators on the option/result types.** Deletes `Option`/`Result` having no methods. **The `enum` half shipped**: a concrete `enum` declares receiver methods (`fun E.tag()`, the shape A-12 slice 1's `hash`/`eq` pair already has) and a call on a value of the enum type resolves one, so `val e = E.A` then `e.tag()` no longer needs a free function; the receiver that is refused is the variant-construction path (`E.A.tag()`), because it names a type rather than a value, and a generic `enum`'s template declares no method at all. **What is left is the combinator half, work: A-12 or receiver syntax** so `o.unwrap()` replaces `option.unwrap(o)`; it is Copy-only because of H-1, not because of this item.
- **H-16. Capture by borrow.** Deletes a borrowed binding cannot be captured. **Work: A-11** — a lifetime-carrying closure type so a literal that only reads captures a borrow, and `move` stays the opt-in for owning the environment.
- **H-17. `net` patterns that name an address.** Deletes `127.0.0.1` is not covered by `localhost`. **Work: new** — match a resolved address as well as the host string, or an explicitly address-valued pattern form; this is the same neighbourhood as open item 32's vocabulary and open item 55's listener gap, and it is capability semantics rather than stdlib surface.
- **H-18. Checked arithmetic.** Deletes the pitfalls page's one non-warning: integer `+`/`-`/`*` wrap silently, workaround `mathx`. **Work: MK12-S1 (numeric correctness)** — checked or trapping arithmetic under a build profile, with wrapping the opt-in; `-fwrapv` from the C toolchain is what makes today's behaviour the compiled-in one (D-2 also lists overflow in the UB catalogue).

**Rows that stay, because they are the design rather than a workaround.** `use of moved value 'a'` and `cannot move out of a borrow` are ownership working; `operator requires matching integer operands` is item 54's decision; `the character '中' (U+4E2D) does not fit in 'u8'` is a correct compile error (H-11 changes the spelling, not the rule); `cannot find module`, a relative or `..` capability pattern, a gated call refused, and an `impl` after a declaration are all deliberate; `*x` on a closure parameter is what `Copy` means. Those rows are rules for the Pitfalls page to keep, and the page's wording should say so rather than offering a workaround.

**Keeping Known issues empty.** The three reports on that page (BUG-1, BUG-2, BUG-3) are fixed, each with a fixture, and no H item is needed for them. What the page's own record leaves behind is three rules any future change must not break: a desugaring pass must key a block's drops by the block's identity and never by a span (BUG-1), a type spelling emitted before the `datac`s must walk through a borrow to the forward-declared tag (BUG-2), and codegen must not wrap a group a second time or emit a bound the source range rules out (BUG-3). The fixtures stay in the suite; a new desugar or a new early typedef is the change most likely to re-open one.

### Encodings and alphabets: a std library of tables and codecs (want)

*A library want, not a language want. Nothing in the plan blocks it, and it blocks
nothing else. It is recorded because the same handful of encoders has now been
hand-written three times and a fourth is about to be, and because the alphabet
tables themselves are the part worth writing down once.*

**Partly shipped.** `std/encoding` exists as of the current development cycle,
and it carries the `fpl/encoding` surface whole: base64 (RFC 4648 §4), base32
(§6), base58 (Bitcoin), hex, RFC 3986 percent and the `x-www-form-urlencoded`
pair, and the `hexdump`-shaped `dump`. Everything else this section describes is
still the want it was: the base64url/base32hex/85/58-variant rows, the derived
decode table, the `*_into` shapes, the split `DecodeErr` reasons, and the
replacement of the existing copies. Sub-question 2 is answered by that module:
a shipped module spells a string `const` the way `syntax.md` and the rest of
`std/` already do — `const B64_ALPHABET: str = "..."`, not `&str`.

**What the repository already proves.** `fpl/encoding` implements standard base64
and RFC 3986 percent-encoding in today's Kelp — 6-bit masking, `u8` pushes, a
`DecodeErr` enum, over `Bytes`/`String`/`Option`/`Result` — using no language
feature that MK8-S2-M1 did not already ship. `fpl/httpx` cannot reuse it (a folder
in `fpl` has to stand alone, so a consumer fetches only the folder it named) and
carries its own **private copies** of the base64 and percent encoders, which its own
documentation states outright. And `std/http`'s chunked-body decoder hand-decodes
hex byte by byte, because `str.parse_u64` is decimal-only (open item 58). Three
copies, one of them in the compiler's own stdlib.

**The shape wanted.** One ungated module, `std/encoding`, holding the alphabets as
named `const` tables plus a codec per alphabet, so a caller writes
`encoding.base64_encode(&data)` and never spells an alphabet inline:

```kelp
const B64_ALPHABET: str = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"
```

Ungated by the same argument `mem`/`str`/`math` are ungated: an alphabet table and a
6-bit shift are authority over nothing shared, so the module takes no
`stdlib::domain_of` row and `caps(encoding = [...])` stays rejected as "not a
capability domain".

**The alphabets, as many as are real.** Every row below is a published table with a
named source, which is the test for belonging here. "Similar types" is the point:
this is one family of tables, not one feature.

| Constant | Table | Source |
| --- | --- | --- |
| `B64_ALPHABET` | `A-Za-z0-9+/`, `=` padding | RFC 4648 §4 |
| `B64URL_ALPHABET` | `A-Za-z0-9-_` | RFC 4648 §5; URLs, JWT |
| `B64URL_UNPADDED` | the same, no `=` | RFC 4648 §5; JWT's actual spelling |
| `B32_ALPHABET` | `A-Z2-7`, `=` padding | RFC 4648 §6 |
| `B32HEX_ALPHABET` | `0-9A-V` | RFC 4648 §7; `base32hex`, DNS labels |
| `HEX_LOWER` | `0123456789abcdef` | convention; `fmt.hex`'s output |
| `HEX_UPPER` | `0123456789ABCDEF` | `percent_encode`'s escapes |
| `B58_ALPHABET` | Bitcoin's 58 | Base58Check addresses |
| `B58_FLICKR_ALPHABET` | Flickr's 58 | short-URL spelling |
| `B58_RIPPLE_ALPHABET` | Ripple's 58 | XRP addresses |
| `Z85_ALPHABET` | ZeroMQ's 85 | RFC 32 / Z85 |
| `B85_ALPHABET` | RFC 1924's 85 | `base85` |
| `ASCII85_ALPHABET` | `!` through `u`, Adobe form | PDF/PostScript `A85` |
| `CRYPT_B64_ALPHABET` | `./0-9A-Za-z` | `crypt(3)`; `bcrypt` |
| `PERCENT_UNRESERVED` | `A-Za-z0-9-._~` | RFC 3986 §2.3 |

**The other constants of the same shape.** An alphabet alone is not a codec; each one
needs the block arithmetic and the inverse table, and those are constants too:

- **Block arithmetic, per family**: bits per character, the mask, characters per
  block, and the padding character — `B64_BITS`/`B64_MASK`/`B64_BLOCK`/`B64_PAD`, and
  the base32 set (`5`/`31`/`8`/`=`). A codec is then a table plus these numbers, rather
  than the hand-written range tests `fpl/encoding`'s `b64_value` and `hex_value` use
  today.
- **The derived decode table**: byte -> value, with an out-of-alphabet sentinel. The
  entry records the decision that `std` derives it from the alphabet `const` instead of
  writing the encoder and the decoder as two independent pieces of arithmetic, which is
  where a typo hides.
- **The byte-level entry points share the codec**: `hex_value`/`hex_upper` are already
  written inside `fpl/encoding`'s percent codec, and they are the same two functions hex
  decoding and `std/http`'s chunk size line want.

**The codecs.** `base64_`/`base64url_encode|decode`, `base32_`/`base32hex_encode|decode`,
`hex_encode|decode` (lower and upper), `percent_encode|decode`, and the 58/85 family, each
with the in-place shape `recv_into`/`read_into`/`read_line_into` already use
(`*_encode_into(buf, out)`, `*_decode_into(text, out)`) so a large payload lands in a
buffer the caller sized, plus one shared `DecodeErr` in the error-`datac` convention
(stdlib decision 2) with the reason split out (`Invalid`, `Length`, `Trailing`,
`UnexpectedPad`) rather than one error type per codec.

**Sub-questions for whoever promotes it.**

1. **One module or two?** `hex_encode`/`hex_decode` are arguably `std/fmt`'s other half
   (`fmt.hex` prints a `u64`; a hex codec works on `Bytes`). Either the hex pair moves
   into `fmt` and `std/encoding` owns the rest, or `fmt.hex` stays the printing shortcut
   and `std/encoding` owns both. Two modules would also let `std/http` take the hex
   decoder without carrying the 85-family tables.
2. **The `const` type spelling.** `fpl/encoding` writes `const B64_ALPHABET: &str` and
   `std/http` writes `const DEFAULT_SCHEME: str`; both compile today, and `syntax.md` is
   the authority on which spelling a *shipped* module uses.
3. **`const` tables or a generated include?** A fourteen-row alphabet family is a table
   either way, and the compiler already generates its 64 integer conversions rather
   than hand-writing a matrix.
4. **Replacement, which is the reason to do it.** When it ships, `std/http`'s chunked
   hex loop (open item 58) and `fpl/httpx`'s private copies should go, and `fpl/encoding`
   becomes a thin re-export or is retired — that last part is an `fpl` decision, not a
   compiler one.

**What it does not need: anything in blocks A-H.** A-9 shipped (the bitwise operators
*are* the masking), `char` shipped, the `Bytes`/`String`/`Option`/`Result` surface
shipped, and `fpl/encoding` is the existence proof. This is the one entry in this Backlog
whose remaining work is scheduling and a module boundary rather than a language change.

### `testkit`, the self-test harness: what "more" would take (want)

*A library want. `fpl/testkit` is 88 lines: a `Report(passed, failed, failures)` tally, one
`check(mut Report, bool, name)`, six typed `check_eq_*` (i64, u64, usize, f64, bool, str), and
`failure_list`/`all_passed`/`summary`. It is honest about being a counter and a printer. This
entry records what the next version should be, split by what actually blocks each part —
because that split is the whole finding, not the wish list.*

**The three facts that shape any change.** They are in the library's own header and they are
not negotiable:

- **The tally must be passed, not held.** A passdown belongs to the module that declares it, so
a library can never keep the caller's state in a module-scope `pd var`. `mut Report` is what
crosses the module boundary, and `wiki/language/passdowns.md` uses this library as the worked
example. **Consequence: test discovery and auto-registration are impossible for a library**, not
merely unimplemented — a test writer must hand the counter in. That is why the discovery half
of "a test framework" is A-15/Coral territory, and only the predicate half is `testkit`'s.
- **No overloading in user code** (`syntax.md` §7.2 is stdlib-only), which is why the checks are
spelled per type. A single `check_eq<T>` needs either a comparator function value (A-4 shipped,
so `check_eq_by(r, a, b, eq, name)` is writable today) or H-14's user-overload rule.
- **Every check prints as it happens.** A run's output is a log, not a final count, and a failure
is one line: `FAIL <name>`. Nothing else is known at that point.

#### Writable now, with no language work

- **`Option`/`Result` predicates — the sharpest gap.** MK5-S6-M1 migrated every stdlib error
`datac` to one of the two, and `fpl`'s libraries return them, but `testkit` has no helper: a test
must write `check(result.is_ok(r), "name")` and loses both the error payload and the reason. A
`check_ok`/`check_err` pair that takes the enum, asserts the variant, and prints the payload on
failure is pure Kelp over what already shipped.
- **`check_ne_*` and the ordered comparisons** (`lt`/`le`/`gt`/`ge`) for the integer types, and
`check_eq_bytes(actual: &Bytes, expected: &Bytes)` — `Bytes` has no `==` (H-5), so the current
option is a length check plus a byte loop in every test that compares binary output.
- **`check_close(actual: f64, expected: f64, eps: f64, name: &str)`.** `check_eq_f64` is exact
equality on a `f64`; every float test today either picks an exact value on purpose or fails
sporadically, and the library offers nothing in between.
- **Expected and actual in the failure line.** The data is already in the caller's hand at the
`check_eq_*` call site, so `FAIL <name>: expected <e>, got <a>` is a formatting change. What is
*not* available is the call's location: a Kelp library has no source-location primitive, so
`at file:line` stays A-16's (item 20's `#line` maps *generated C*, which a Kelp
library never sees); worth writing down so nobody re-asks for it here.
- **A `Failure` record instead of a `List<String>`**: `Failure(kind, name, expected, actual)` so
`failure_list` renders it, a summary can group it, and a machine-readable line
(`FAIL\t<name>\t<expected>\t<actual>`) becomes possible without a `json` library that does not
exist. `Report(failures: List<Failure>)` is a `datac` change and stays source-compatible if
`failure_list` keeps its signature.
- **`skip(r, name)` and a skip count.** A check that is not run is not a pass, and today the only
way to say "not applicable" is to not call `check` — which silently makes the summary lie.
- **`exit_code(r) -> i32`**, so the caller writes `process.exit(testkit.exit_code(&report))`.
The library must not exit the process itself: `process.exit` needs the `process` domain, authority
is per module, and the empty-pattern grant (open item 39) is the caller's to declare. The helper
keeps the two-line idiom the docs already require down to one line without moving authority into
the library.
- **Suites and grouping**: `suite(r, "name")` pushing onto a `List<String>` path, with the path
prefixed in the log. Cheap, and it is what makes a 300-line test file's output navigable.
- **`benchkit`'s overlap**: `fpl/benchkit` already measures; a `timed(r, name, ...)` in `testkit`
would duplicate it. Decide which one owns the clock rather than adding a third.

#### Blocked, and on what

- **`check_fails`/`xfail` (a check that the code *fails*)** and any wrapper taking a closure that
mutates the report: the closure would capture a `mut Report` **by borrow**, which is refused
today (H-16, work A-11). It is expressible only by passing the report in as a second argument.
- **Setup/teardown around a group, and a `defer`-shaped cleanup**: no user `Drop` and no `defer`
(B-8). A test that opens a temp dir cleans up by hand, in every test.
- **Timing** (`time.now_ms`) lives in gated `std/time`, so a timed run makes `testkit` a gated
module (open item 45's neighbour). `testkit` is ungated today; that trade is a decision, not a
tweak.
- **Parallel runs** need threads (MK6-S1-M1), and a `Report` shared across threads needs a
`Mutex` and a `Send`-shaped rule (B-4/B-5). Do not design around it now.

#### The half that is not `testkit`'s

Golden/fixture testing — compile, run, diff stdout, assert the exit code, expect a
compile *failure* — is what this repository's own suite needs, and it is the farthest from what a
counter can do. It is already hand-written **twice**: `kelpc/tests/compile_and_run.rs`
reimplements discovery, per-fixture flags, expected output and an AddressSanitizer pass, and
`bench/speed/run.sh` is a 120-line shell program with its own flag assembly and table formatting.
The Coral design already cites both as the tasks it exists to absorb. A Kelp-side version is
writable today (`process.run` for the child, a temp dir under an `fs` grant, `testkit` for the
assertions) but it is a **task** with its own grants, not a library, and discovery stays
`kelpc test`-shaped — which is A-15's explicit non-goal.

**Do not forget the docs when any of this lands.** The claim "no filtering, no parallel runs, no
timing" is written in `wiki/getting-started/testing.md`, and the function table is duplicated in
`fpl/docs/testkit.md`, `fpl/README.md`, `wiki/libraries/testkit.md`, `wiki/libraries/catalogue.md`
and `fpl/index.toml`'s description. Five copies of the same API list is the reason the wish is
worth writing down before the code.

### Coral: the build tool and package manager (roadmap open item 72)

*The `MK13-Sn-Mn` identifiers below are the ones this design carried when it was a Mark. They are kept so the detail stays addressable. Nothing here is scheduled.*

*Scope: the project layer above the compiler. `kelpc` stays the compiler. Coral owns the manifest, the project layout, the task graph, dependency resolution, the build cache, artifacts, the test runner, formatting and publishing. Modeled on Gradle: a project model, tasks with declared inputs and dependencies, a build cache, and a development/release split. Named Coral.*

Why this exists, in this repository's own evidence: `kelpc build <path>` compiles one `.kp` file or one directory containing `coral.toml`, and stops there. Everything beyond that is currently someone's shell script or Rust test code. `bench/speed/run.sh` is a 120-line shell program that assembles flags, runs each workload five times, and formats a table. `kelpc/tests/compile_and_run.rs` reimplements discovery, per-fixture flags, expected output, and an AddressSanitizer pass. `examples/download.kp` documents its own build command in a comment. Each of those is a build-tool task that has been hand-written once and will be hand-written again by the next project.

**Division of labor.**

- **`kelpc` keeps the compiler jobs**: load the module graph, type check, move/borrow check, emit LLVM IR, invoke the linker. `kelpc build` and `kelpc run` stay documented low-level commands.
- **Coral owns the project**: manifest, layout, tasks, profiles, dependencies, cache, test runner, artifact naming, publishing, toolchain pinning.
- **Coral calls `kelpc`, never the reverse.** Everything Coral needs from the compiler is a command-line contract, not a link against compiler internals.

**Tasks are Kelp programs, and that is the design.** Gradle needed a scripting language, then a DSL, then a plugin API, because a task is arbitrary code. Kelp already has arbitrary code: a task is an `.kp` file with `fun main()`, run by Coral, and its authority is whatever its own `impl` lines grant. No scripting DSL, no dynamic plugin API, no build logic inside a string. A task that reads data and writes a report declares exactly that, and the capability checker enforces it:

```kelp
// tasks/report.kp
impl "std/fs" caps(fs = ["/project/out/**", "/project/data/**"])
impl "std/str"
impl "std/fmt"

fun main() {
    val size = fmt.uint(fs.size("/project/data/input.csv"))
    fs.write_text("/project/out/report.txt", str.concat("input bytes: ", size.as_str()))
}
```

The manifest names it, and Coral runs it:

```toml
# The shape Coral grows coral.toml into. Today's manifest is flat, has four keys
# (name, version, entry, http_pool), rejects every section, and rejects an
# unknown key, so this is a format change with a compatibility story to decide
# (open item 66).
[package]
name = "myproject"
version = "0.1.0"
entry = "src/main.kp"

[tasks]
report = { file = "tasks/report.kp" }
docs   = { file = "tasks/docs.kp" }
```

```sh
coral init myproject       # coral.toml, src/main.kp, tests/, .gitignore
coral build                # dev profile, artifacts in build/
coral build --release
coral run -- data.csv      # argv and exit code pass through
coral task report
coral test
coral fmt --check
coral clean
```

**Deliberately not in Coral**: a scripting language (tasks are Kelp), a dynamic plugin runtime (extensions are manifests and Kelp programs), and a general version-range solver (nothing carries a version by design — a dependency is a git remote, or one folder inside one — and ranges stay MK13-S3-M3's problem).

**What has shipped since the sketch** (`coral` repo, tagged `v0.3.0`): `coral init`/`build`/`run`/`check`/`clean`, `[tasks]`, `[dependencies]` fetched from the Gitea over SSH, the fingerprint build cache, and toolchain management. The last of those is **MK13-S6-M1**'s second half — per-project selection: `[toolchain] kelp = "v0.1.1"` in `coral.toml` names the compiler a project builds with, resolved as `$KELPC`, then the pin, then `~/.coral/bin/kelpc`, then `PATH`, with a pinned version that is not installed yet installed on the spot. `coral toolchain kelp pin <ver>` writes that one line in place (comments and section order survive it, and `kelpc` never sees it — the section is after the first `[`), `pin --clear` removes it, `installed` lists what is on disk, and `coral init --kelp <ver>` writes it at scaffold time. `coral v0.5.0` then made the store single-version: `install` and `use` drop every other version of a component once the new binary is in place, so a pin that is not the stored version displaces it (one reinstall per switch for two projects pinned differently) rather than accumulating toolchains. `coral toolchain kelp|coral install <ver>` prefers the tag's own release binary — the `kelpc-0.1.1-linux-x86_64` asset on kelp's `v0.1.1` release, downloaded with `curl` into `toolchains/<component>/<ver>/<binary>` — and falls back to `git clone --branch <ver> --depth 1` plus `cargo build --release`, which is what still makes `v0.1.0` (a tag with no release) installable.`coral v0.5.1` then dropped `coral add`, `coral update` and `coral.lock` outright — a Kelp library has no version, so a dependency is a manifest line and `coral sync` is what fetches and refreshes it — and `coral v0.5.4` made a dependency nameable as one **folder** inside a repo (`Juniper/fpl/sillyname`), fetched with `--filter=blob:none --sparse` and copied flat into `src/deps/<name>/`, so a sibling library in that repo never comes down. Workspaces, `coral test`/`fmt`/`lint`/`bench`, publishing and version ranges are still the sketch.

**What Coral needs from elsewhere.**

- **From the compiler**: machine-readable diagnostics, a module dependency list, separate compile and link steps, and a stable CLI contract (MK13-S1-M3). **The diagnostics half shipped** (2026-09-20): `kelpc check <file.kp|dir> [--json]` runs the front end with no code generation and prints one document, `{"schema":1,"ok":...,"diagnostics":[...]}`, each finding with its severity (`error`/`warning`/`outdated`), message, module and a 1-based range in the file it points at. That is what the `lighthouse` language server reads instead of prose from stderr. What is still open is the per-module dependency list and the CLI contract written down as a contract.
- **From MK5-S2-M1 (done)**: `process.spawn`, argv, captured output and exit codes, which Coral and every non-trivial task need.
- **From MK8-S1/S2, only if Coral is written in Kelp**: generics, `Option`/`Result`, function values and containers — **all four shipped** (A-2 as MK8-S1-M1 part 2, `Option`/`Result` as MK5-S6-M1, containers as MK3, function values and closures as MK8-S1-M2 phases A-F), so the language half of open item 67 is met. Until Coral is ported it is a Rust program that drives `kelpc`.
- **From MK9-S4-M2**: cross-compilation and library output, which MK13-S4-M2/M3 extend rather than invent.
- **From the capability model (MK4-S1-M1, done)**: task grants are checked the same way module grants are, which is what lets a build task hold less authority than the user running it.

#### What the port hit: three stdlib-sized gaps, all three now shipped

Writing the parts of Coral's Rust that shell out (`deps.rs`, `toolchain.rs`) against this stdlib ran into four things. Three were stdlib additions and **all three shipped as MK5-S2-M2** (the `fs.symlink` half continuing MK5-S5). None of them needed a language feature: the surface all of them would be written against — generics, `Option`/`Result`, containers, function values — was already shipped. The fourth was a language gap, and MK8-S1-M2 phases E-F closed it. The rows are kept as they were written, with what shipped recorded against each.

| Gap | Evidence | Workaround today | Fix | Size |
| --- | --- | --- | --- | --- |
| ~~**No `chdir`, and no per-call working directory.**~~ | *Done — **MK5-S2-M2**.* As written: `std/process.kp`'s `run` said it outright ("There is deliberately no `chdir` in v1: a process-wide working directory would make every grant pattern's meaning depend on mutable global state"), and Coral runs `git`/`cargo` inside specific target directories constantly, with `git -C`/`cargo --manifest-path` covering two tools and nothing else. | — | Shipped exactly as the sketch had it: `spawn_in(dir, program, args)` / `run_in(dir, program, args)`, `chdir` in the **child** between `fork` and `exec` (one branch in `spawn_raw`'s child path, plus the `dir` parameter), with `spawn`/`run` reduced to delegates passing `""`. Two things the estimate missed: `checked_args` for `process` had to stop being "the first `str` argument", because the directory is argument 0 in the `_in` forms, and a child that cannot enter `dir` exits **126**, which needed a reserved code and a doc line. | done |
| ~~**No `fs.symlink`** — and no `fs.read_link`~~ | *Done — **MK5-S2-M2** (the MK5-S5 continuation).* As written: `std/fs.kp` had no link primitive, symlinks appeared only where the *capability check* resolves them, and `toolchain.rs`'s `use_version` — the `~/.coral/bin/coral` link into the store — had nothing to call. | — | Shipped as `fs.symlink(target, link)` with **both** paths checked, which is the `fs` default and the safer reading: a grant stays closed under link creation. One consequence to know: the target must be absolute, since the check normalizes every path it matches. | done |
| ~~**`process.spawn`/`run` panic instead of returning a `Result`.**~~ | *Done — **MK5-S2-M2**, with one variant dropped.* As written: Coral treats a missing `git`/`cargo` as a reportable error, and ported as-is one missing tool ended the whole process. | — | Shipped as `try_run(...)`/`try_run_in(...)` returning `Result<RunResult, ProcErr>`, with `run` kept for callers that treat failure as fatal, and `process.executable` exposed as the pre-check in predicate form. Two precisions the sketch asked for and got: the failures are decided **before the fork** by `stat`/`access` (so `NotFound` means the path names nothing and `NotExecutable` means something is there that `exec` would refuse, and neither can be confused with a child exiting with a matching code), and `run("git", ...)` still has no `PATH` search — the check refuses a relative program, so resolving through `PATH` is the caller's job and stays out of the stdlib. **`NotAbsolute` and `Denied` did not ship**: both are refused by the compiler's call-site check, which panics, so neither is reachable from Kelp (open item 73 records the codegen change a value-returning denial would need). None of Coral's uses closed over meaningful state anyway, so this was never a blocker, only verbosity. | — | — | done |

The pattern in all three gaps was the same: the primitive was missing, the *shape* of it was already decided by the module that would gain it (`spawn_in` by `run`'s own doc comment, `try_run` by the `Option`/`Result` convention MK5-S6-M1 established for every other fallible stdlib call), and each was one extern plus one wrapper. To that the implementation added one place the estimate was wrong: the *capability* table, not the C, is what the `_in` forms moved — `checked_args` is keyed on the call's name now, so a working directory is never matched against a program allowlist. The one thing the compiler had to refuse outright is a value-returning grant denial (open item 73).
