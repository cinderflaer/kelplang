# The "Kelp" language milestone record (shipped)

The record of what actually happened, milestone by milestone. It overrides any plan elsewhere that said a feature would land earlier. Shipped: **MK1** (the core language), **MK2** (modules and compile-time), **MK3** (heap and containers), **MK4-S1-M1** (capabilities), and the standard library program **MK5-S1 through MK5-S4**.

Milestone identifiers follow the MK/S/M scheme in `roadmap.md`; the mapping from the older `M0`–`M9`/`C1`/`S1`–`S8`/`T1` identifiers is in that file's "Milestone naming" section.

## Milestone record

### MK1-S1-M1 Scaffold + lexer/parser for the full syntax surface (DONE, `1b616c5`)
- Shipped: workspace + `kelpc build <file.kp>` CLI; span-carrying lexer; newline-terminated statements (paren-depth aware, one `Newline` per blank-line run at depth 0 so a continued expression *must* be wrapped in parens; no trailing-operator continuation was attempted); `val`/`var`; `fun` + `.R: T` + expression bodies; `datac Name(val/var field: T, ...)` with per-field mutability; construction via call syntax `Point(x = 1, y = 2)` (no separate literal grammar, so no struct-literal-vs-block ambiguity exists); named + positional arguments in one call; `print`/`print!` where `print` adds the newline; compound assignment desugared at parse time; `when` desugared to an `if`/`else if`/`else` chain so no later pass ever sees it; `&str` accepted and lowered to plain `str`; AST pretty-printer plus unit tests.
- Not in MK1-S1-M1, deferred: receiver methods, `pd`, `impl` imports, string templates, `caps(...)`.

### MK1-S2-M1 Types + C codegen + first running binary (DONE, `ca4af6a`)
- Shipped: `types.rs` primitives + signatures; `infer.rs` signature checking, `val`/`var` inference, span-carrying type errors; `codegen_c.rs` mapping `.kp` types to C; `driver.rs` writing C to a temp file and invoking `cc -O2`.
- Shipped alongside it: `tir.rs`, the typed IR every later pass walks, and `#line`-annotated C as planned.
- Deliverable met: `kelpc build examples/hello.kp && ./hello` prints correctly, `fib.kp` computes fibonacci, and `kelpc/tests/compile_and_run.rs` compiles each fixture with the real binary and checks stdout or the expected rejection (14 end-to-end tests today).

### MK1-S2-M2 `datac`, mutability, loops (DONE, `4c9f914`)
- Shipped: `datac` → C `struct`, field access, `while` loops, `var` assignment, and **real per-field mutability**: a `val` field is never reassignable, and a `var` field is reassignable only when the root binding is also `var`.

### MK1-S3-M1 Ownership: moves (DONE, `f9d479c`)
- Shipped: `borrowck.rs`, run between `infer.rs` and `codegen_c.rs`, operating purely on `tir` Copy-ness is read off each node's resolved `Ty`, so it needs no struct/function tables.
- Copy rule: everything except `Ty::Struct(_)` is Copy. State is a per-scope `HashMap<String, VarState>` holding `is_copy` and `moved_at: Option<Span>`, mirroring `infer.rs`'s scope stack.
- Move points: a bare `Ident` read as a whole value. A `.field` read walks the place chain without moving anything, since v1 has no way to move a single field out. Assigning *to* a binding reinitializes it and clears moved state.
- `if`/`else`: each branch is checked from an independent snapshot; a variable counts as moved afterwards if either branch moved it.
- `while`: the body is checked twice in sequence, so a value double-moved across iterations is caught; the loop's post-state is then merged with the pre-loop snapshot because the body may run zero times.
- Diagnostics are single-span for now (`BorrowError { message, span }`); the two-span "moved here / used here" pair is polish, not a blocker.
- Fixtures: `use_after_move.kp` and `double_move_in_loop.kp` (rejected), `move_then_reinit.kp` and `field_read_does_not_move.kp` (accepted).
- Not implemented, and worth remembering: partial/per-field moves. The per-field `val`/`var` bookkeeping from MK1-S2-M2 is the natural hook for it.

### MK1-S4-M1 Borrowing (DONE)
- **Resolved the open prerequisite** ("no spelling for a move-taking parameter") by taking the option `syntax.md`/the plan's own "Gap, unresolved" note listed: *no move-taking parameters in v1*. A `datac`-typed parameter is now always a borrow implicit shared, or exclusive when written `mut T` (the *only* spelling; `&mut T` in parameter position is a parse error, since `parse_type`'s leading-`&` handling expects an identifier next, not the `mut` keyword token). The only way to move a `datac` value is still local rebinding (`val q = p`), which MK1-S3-M1 already checked. This is a real behavior change from MK1-S3-M1: calling a function with a `datac` argument no longer moves it.
- `types.rs`: new `Ty::Ref { mutable, inner: Box<Ty> }`, always Copy (copying a pointer doesn't move what it points at). `.R: T` never produces one `resolve_type` for return types is untouched by the new `resolve_param_type` path so **a borrow can never be returned to a caller in MK1-S4-M1**. That's deliberate: it's what makes call-scoped borrow release (see below) sound without real lifetime inference, at the cost of `&str` return elision staying out of scope (moot for now anyway, since `&str` isn't routed through `Ty::Ref` at all it's still its own flat Copy `Ty::Str`).
- `parser.rs`: `&expr`/`&mut expr`/`*expr` as prefix unary operators (same slot as `-`/`!`); `mut` recognized only in parameter position, right after `:`.
- `infer.rs`: call sites never write `&` passing a plain place to a `Ty::Ref`-typed parameter auto-borrows it (`check_call_arg` synthesizes the `tir::ExprKind::Ref` node; this is the *checker* desugaring, not codegen inspecting signatures codegen only ever sees the already-resolved tir). Forwarding an already-borrowed value type-matches directly; a shared parameter accepts an exclusive argument. `.field` access/assignment auto-derefs through a `Ref` base each node decides independently, purely from its own base's type so a `mut`-borrowed param's fields are writable and a `.field.field` chain through it "just works" with no extra plumbing. `check_target_writable` replaced the old "root must be `var`" assignment rule: writability now comes from either a plain owned `var` root, or a statically-exclusive `Ref` root.
- `borrowck.rs`: adds `BorrowKind::{None, Shared(n), Exclusive}` per owner. Two lifetimes: **call-scoped** (an auto-borrow or explicit `&expr` passed straight into a call every borrow in one call's argument list is *started before any of them release*, so the existing conflict check catches same-call aliasing like `f(&mut c, &c)` for free, no separate pass needed) and **scope-durable** (`val p = &c` released when `p`'s enclosing block pops, reusing the move-checker's scope stack). Moving or reassigning a variable while it's actively borrowed is rejected; reading `*p` as a whole value (not just through it) is rejected when the pointee is non-Copy, mirroring "cannot move out of a shared reference."
- `codegen_c.rs`: `FieldAccess`/assignment-target rendering picks `.` vs `->` per-node from the base's `Ty`; `&expr`/`*expr` map to C `&`/`*`.
- **Cut from this milestone, deliberately** (receivers landed right after, as MK1-S4-M2 below see that entry): receiver-form methods a separable parsing/method-resolution feature once the borrow mechanics alone turned out to be the bulk of the work. `&str` return elision (see above moot until `&str` routes through `Ty::Ref`). A known, narrow soundness gap, exercised by no fixture: `p = &c` *reassigning* an existing binding to a fresh borrow is checked against currently-active borrows at the moment of assignment but doesn't persist scope-durable tracking the way a `val`/`var` *declaration* does (`val p = &c`, which is fully tracked).
- Fixtures: `borrow_basic.kp` (shared + exclusive via a `mut` free-function parameter, plus a local `&`/`*` shared borrow), `borrow_conflict.kp` (simultaneous shared + exclusive, rejected), `same_call_aliasing.kp` (`f(&mut c, &c)` in one call, rejected the fixture that specifically exercises the call-scoped conflict check), `write_through_shared_borrow.kp` (mutating through an unmarked/shared param, rejected), `move_while_borrowed.kp` (rejected). `use_after_move.kp`/`double_move_in_loop.kp` were rewritten to move via rebinding instead of a function call, since a call no longer moves its argument.

### MK1-S4-M2 Receiver-form methods (DONE)
- `ast.rs`: `FunctionDecl.receiver: Option<Receiver>` (`Receiver { type_name, mutable, span }`), kept separate from `params` since the receiver sits outside the parens in the surface syntax. New `Expr::MethodCall { receiver, method, args, span }`.
- `parser.rs`: `fun [mut] Type.name(...)` is disambiguated from a plain `fun name(...)` by one token of lookahead (a `.` right after the first identifier commits to receiver form; `mut` right after `fun` always commits to it, since a free function never writes `fun mut name(...)`). `recv.method(args)` is disambiguated from `recv.field` in `parse_postfix` by whether a `(` immediately follows the name both share a new `parse_call_args` helper factored out of the plain-call-parsing path.
- `infer.rs` (the substantial part):
  - `sig_key(f)` is the lookup key in `sigs`/`tir::Function.name`: `Type#name` for a method, bare `name` for a free function. `#` can't appear in a real `.kp` identifier, so a method can share a bare name with an unrelated free function, or with a same-named method on a *different* receiver type, with no collision only two methods on the *same* type with the same name collide, which is exactly the duplicate-definition case that should error.
  - The receiver is resolved exactly like a parameter (`resolve_receiver_type`, sharing the `implicit_borrow_wrap` logic `resolve_param_type` was refactored to use) and prepended as a real `("self", Ty)` entry at `params[0]` both in the `FnSig` and in the `tir::Function` the body actually gets checked against. This means a receiver method is, underneath, indistinguishable from a free function whose first parameter happens to be named `self`; codegen needed zero changes for receivers specifically.
  - **No `self` keyword needed at call sites, and none needed to *read* a field either**: per `syntax.md` §5 ("no `self` keyword"), `fun Circle.area().R: f64 = 3.14159 * r * r` uses the bare field name `r`, not `self.r`. `check_expr`'s `Ident` arm now falls back, when a name isn't a local/parameter, to checking whether the current function has a receiver whose `datac` has a field of that name if so it synthesizes a `FieldAccess` on an internal `self` binding. (`self` itself remains available as an ordinary identifier for the rare case a method needs the whole receiver value, even though nothing requires writing it.)
  - `check_method_call` resolves `method` against the receiver expression's type-checked (but not yet borrow-producing) probe to find the `Type#method` key, then calls `check_call_arg("self", ...)` on the *actual* receiver expression for the real borrow reusing MK1-S4-M1's auto-borrow/aliasing machinery with zero special-casing, then lowers to a plain `tir::ExprKind::Call`. A `fun mut T.m()` call therefore participates in the same call-scoped conflict checking as any other exclusive borrow (e.g. `combine(c, c)`-style same-call aliasing would be caught here too, though no fixture exercises that specific combination for methods).
- `codegen_c.rs`: `c_name` maps a method key's `#` to `__` (e.g. `Circle#area` → `kelp_Circle__area`) not fully collision-proof against a hand-named `Circle__area` free function, but low-risk and simple; noted as a known limitation rather than engineered around.
- Fixtures: `receiver_methods.kp` (the spec's own `Circle.area`/`Circle.grow` example, adjusted for the doc bug noted in "Current state" above), `receiver_mut_on_val.kp` (calling a `mut` receiver method on a `val`-bound local, rejected exactly the free-function `write_through_shared_borrow.kp` check, now exercised through method-call syntax).

### MK2-S1-M1 Multi-file imports (DONE)

Split out of the original MK2 on the same reasoning that split MK1-S4-M1/MK1-S4-M2: the file/import layer is independently testable, and the remaining MK2 items (`pd`, templates, aliases) do not depend on it landing together. Shipped:

- **`diag.rs` (new).** A `Span` is only meaningful inside the file it was lexed from, so every diagnostic now carries the canonical id of the module it came from, and `SourceMap` maps that id back to path+text to print `--> file:line:col`. `ast::DatacDecl`/`ast::FunctionDecl` and `tir::Function` carry a `module` field for exactly this; `infer.rs` and `borrowck.rs` tag their errors with it at the function/decl boundary, so their internals are otherwise unchanged. Verified: a borrow error inside an imported module points at the imported file, not the entry file.
- **`resolve.rs` (new).** Loads the entry file, follows `impl` transitively, and returns one *merged* `ast::Program` plus a `Project` naming table. `impl "shapes/circle"` resolves to `src/shapes/circle.kp` relative to the project's `src/`; the last path segment is the default alias, `as` overrides it (line-segment validation rejects absolute paths, `..`/`.`, non-identifier segments, a trailing `.kp`, and reserved `std/...` with a "not implemented until MK3/MK4-S1-M1" message). Import cycles are rejected with the chain printed (`import cycle: a -> b -> a`), duplicate aliases within one file are rejected, and a module reached twice (diamond) is loaded once.
- **Merging, not a real module system.** Each module's top-level names are prefixed with the module's dotted path (`Circle` in `shapes/circle` becomes `shapes.circle.Circle`; the *entry* module is unprefixed) and `FunctionDecl.module` records the origin. Nothing else about the pipeline changed shape: infer → borrowck → one C translation unit → one `cc` call. `resolve.rs` rewrites a receiver's type name too, so `sig_key`'s existing `Type#name` scheme keeps working unchanged.
- **Strict module-qualified namespace** (chosen over a flat merge): a module's items are reachable from another module only as `alias.Item`, never bare, and a file's own items are reachable bare inside that file. `circle.Circle(r = 2.0)` and `circle.scale(x)` are parsed as method/field syntax and re-interpreted in `infer.rs::check_expr` when the base identifier is an `impl` alias that no local shadows so a local `val util = 5` still shadows a `util` module alias, exactly like any other name lookup. Type annotations use the same alias table (`fun describe(t: u.Tally)`). Unqualified references to an imported item get a targeted "did you mean 'prov.Thing'?" hint; so does a module used as a value.
- **`coral.toml`** (`name`, `version`, `entry`, hand-parsed no TOML dependency, unknown keys rejected): `kelpc build <dir>` uses the manifest's entry point, and `kelpc build <file>` walks up to find the manifest and requires the file to live under `<root>/src`. **A manifest is optional**: with no `coral.toml` found, the entry file's own directory is the module root, which is what keeps all 19 single-file fixtures and both `examples/` compiling with no manifest at all.
- **Codegen mangling**: `types::c_ident` turns `.` and `#` into `__` (`shapes.circle.Circle#area` → `kelp_shapes__circle__Circle__area`, struct tag `struct_shapes__circle__Circle`). Same low-risk/collision caveat MK1-S4-M2 recorded for `#`, now covering module prefixes too.
- Tests: 34 fixture/project tests (`cargo test` = 38 unit + 34) `shapes` (manifest, nested import inside an imported module, receiver methods on an imported type), `same_name` (two modules both declaring `Item` and `describe`, proving the prefixing avoids collisions), `alias` (`impl "util" as u` plus a qualified type in a signature), `loose` (manifest-less sibling import), and rejected `cycle`, `unknown_module`, `duplicate_alias`, `dotdot`, `bad_path`, `unknown_member`, `unqualified_import`, `stdlib_import`, `caps_clause`.
- **Deliberately not in MK2-S1-M1**: `pd` wiring, string templates, `%*alias*%`/`alias.kpconf`. Also worth remembering: **extension methods on an imported type are not expressible** `fun circle.Circle.helper()` cannot be parsed (the receiver grammar takes one bare type name), so helper methods must live in the module that declares the type. That is a v1 restriction, not a bug, and it is the natural thing to revisit if user-definable-cross-module extension methods ever matter.

### MK2-S1-M2 `pd` passdowns and string templates (DONE)

Shipped together because they meet in exactly one place: the syntax file's own example is a template that interpolates passdowns. Neither depends on the other otherwise, and each got its own fixtures.

**Passdowns**
- Syntax: `pd val name = expr`, `pd var name = expr`, `pd val name: T = expr`, in canonical position (after `impl`, before `datac`/`fun` enforced at parse time with a message naming that order). `pd` is now a keyword and the lexer emits `TokenKind::Pd`.
- **Wiring is real hidden parameters, not globals read in place.** A scope-aware AST scan (`PdScan`, run before any body is checked) records which passdowns each function actually names, honoring shadowing exactly as the checker does a parameter, receiver field, or local `val`/`var` of the same name hides the passdown, and a field name / method name / callee name is never a passdown reference. Only referencing functions get parameters, so `fun unrelated(n: i32).R: i32 = n * 2` is emitted unchanged.
- `infer.rs` resolves every passdown to `PdInfo { qualified, name, hidden, value_ty, param_ty, mutable, index }`, where `hidden` is `pd#<module-qualified name>` a spelling no user identifier can produce, which is what lets the generated C global and the hidden parameter share one symbol. `param_ty` is `implicit_borrow_wrap(value_ty, false)`: by value for `Copy` types, a **shared borrow** for a `datac` (reading a `datac` passdown by value would "move" it out of the global on first use).
- Call sites pass each hidden argument as `&<global>` (non-`Copy`) or `<global>` (`Copy`) see `PdInfo::arg`. Ordering is fixed by the callee's declaration order, so the generated C signature and the arg list agree. Receiver methods are wired the same way through their `Type#method` key.
- `codegen_c.rs`: one `static <ty> kelp_pd__...;` per passdown plus a generated `kelp_init_pds()` that assigns them in declaration order, called from `main` (after MK5-S2-M1 saved `argc`/`argv`). `main` itself is the one function that cannot take hidden parameters its signature is fixed at `int main(int argc, char** argv)` (MK5-S2-M1) so inside `main` a passdown reference takes the address of the global instead of naming a parameter (`Ctx::pd_global_borrow`). Since a call site also reads the global, this is the same value either way; the parameter is what makes the dependency visible in the callee's own signature. The function prototypes are emitted before `kelp_init_pds` because a `pd` initializer may call a function (`io`'s process-wide reader does).
- Diagnostics: writing a passdown inside a function is rejected with wording that distinguishes `pd val` from `pd var` ("read-only inside a function"); a `pd` initializer reading a passdown declared later says so (adding "a `pd` initializer can only use passdowns declared before it" to the generic undefined-name message); a `pd` initializer *calling* a function whose passdowns are not initialized yet is rejected rather than silently reading a zero-initialized global; naming another module's passdown says that passdowns are module-scoped; a name used for both a passdown and another top-level item in one module is rejected.
- `collect_pds` resolves declared types directly and infers unannotated ones from a type-only probe of the initializer, which is then re-checked for real once all passdown types and the wiring table exist the same "check twice, keep the second" pattern `check_method_call` already used for receivers.
- **Deliberately restricted in v1:** a `pd` initializer cannot read a *non-`Copy`* passdown (a passdown has to hold a value, and a `datac` one is handed around as a borrow), and `main` cannot be called from `.kp` code (it takes no arguments, so it could not receive its passdowns). Both are errors with messages rather than silent behavior.
- Borrow checking needed no new rules: hidden parameters are ordinary parameters to `borrowck.rs`, and a passdown parameter is `Copy` (a `Ref` is always `Copy`), so referencing one repeatedly can't look like a move. `pd` initializers are not walked by `borrowck.rs` at all they have no locals and no borrows (nothing to borrow with no top-level statement form).

**String templates**
- `"a$b c${expr}"` is lexed into a flat token run (`TemplateStart StrChunk TemplateExprStart <expr> TemplateExprEnd ... TemplateEnd`) by the same lexer pass, using a `next_token()` refactor plus a small pending-token queue. Splitting them in the lexer rather than re-lexing the literal text is what keeps each interpolated expression's spans **absolute** so `file:line:col` is right with no offset arithmetic and lets a template nest inside its own `${...}`. `$` followed by anything else (a digit, a space, `}` ) stays literal text, so `"cost $5"` needs no escaping; a string with no `$` is still the single `StringLit` token it always was, which is why no existing fixture changed.
- `infer.rs` accepts a template only as the single argument of `print`/`print!` and rejects it anywhere else: v1 has no owned string type, so a template cannot *produce* a value before MK3. Interpolated values obey exactly `print`'s existing printable rule (numeric, `bool`, `char`, `str`).
- `codegen_c.rs` emits **one** `printf` per template with a generated format string: literal chunks are escaped into it (`%` doubled, quotes/backslashes/newlines/tabs escaped), each value contributes its `printf_piece` specifier and argument, and `print` appends the newline to the format rather than making a second call. `print!` vs `print` is a flag on the `tir` node.
- Fixtures: `passdowns.kp` (read by two functions and by neither), `passdown_datac.kp` (a `datac` passdown read through its shared borrow, including a method call and `${...}` field access), `pd_shadowed.kp` (a local shadows a passdown), `templates.kp` (literal `%` and braces, `${...}`, `print!` without a newline), plus rejected `pd_var_write.kp`, `pd_forward_read.kp`, `template_not_printed.kp`, and the `pd_module_scope` project.

**MK2-S1-M3 `%*alias*%` substitution (`preprocess.rs`) (DONE)**

Shipped as one token-level pass, run once per file before the parser. This was the last, deliberately-textual piece of the original MK2.

- **Detecting a reference.** `%*name*%` lexes as `Percent Star Ident Star Percent`, and `preprocess.rs` recognizes that run only when its five tokens are *adjacent* in the source, so `a % * b * %` stays arithmetic. `alias` is not a lexer keyword a declaration is recognized structurally as `alias %*name*% = <raw text>` at a statement start (start of file, or after `newline`/`{`/`}`), which is what keeps `val alias = 5` working. The right-hand side is sliced out of the *source text* verbatim, which is why the RHS needs no separate expression grammar at all.
- **Expansion.** Replacement text is lexed, expanded recursively (a chain `%*a*%` → `%*b*%` works), then every produced token's span is remapped onto the `%*name*%` occurrence the user wrote a span is only meaningful inside its own file. Inside a string literal (or template chunk) the substitution is purely textual, which is the case `impl "%*shared*%"` needs; nothing is re-lexed there, so a `$` or a `%` inside a replacement stays literal.
- **The full example from the plan's tradeoff note:** `%*doubled*% = %*answer*% * 2` with `%*answer*% = 40 + 2` prints **44**, not 84. Pure text substitution does not add parens. Pinned by `aliases.kp` so it reads as documented behavior rather than a bug.
- **Two definition sites, one flat table.** `alias.kpconf` at the project root (one `name="replacement"` per line, `#` comment lines, no sections deliberately the zsh-alias-flavored format, not a config format) plus every inline `alias` declaration in every file the walk reaches. A second definition of the same name is an error naming both sites, since one global namespace is the point.
- **Cycles are rejected eagerly, used or not** the same rule imports follow. `AliasTable::check_cycles` walks the table after loading, so a cycle nothing references still fails.
- **Two spans, in two files where that is where they live.** `diag::Diagnostic` gained `notes` (`with_note`), so an error can carry a secondary location in a different module: an unknown alias or a cycle reports the `%*name*%` that failed as the primary span and `'%*name*%' is defined here` as the note. `alias_kpconf_cycle` is the fixture that proves both files print.
- **Loading had to change shape, and this is the part worth remembering.** An `impl` path may itself be an alias, so the file graph is only knowable *after* expansion, while the table is only complete *after* every file is known. `resolve.rs` now runs discovery rounds before the real load: discovery reads `impl` paths straight off the raw token stream (no expansion, no parse), so a file whose body cannot expand yet still contributes its own aliases and its unaliased imports; then a strict round expands and parses everything with the table built so far. If the strict round loads a file it reached through an *aliased* path, the whole thing repeats with a bigger table (bounded by `MAX_ALIAS_ROUNDS = 8`, which is a guard, not an expected limit); once a strict round loads nothing new, its errors are final. **That is what makes the table genuinely flat**: `alias_cross_file` uses an `alias` declared in an imported module, and the entry file's own alias may appear on a later line than its use.
- **Not implemented, deliberately:** no aliases inside comments (the lexer drops comments before preprocessing, so there is nothing to expand); no whitespace inside the sigil; no re-lexing of a string-bodied replacement; and a *path* alias whose target file is the same file that declares it cannot bootstrap discovery (a genuine chicken-and-egg, and not worth more machinery for a case with an obvious literal-path workaround).
- Tests: 12 new unit tests in `preprocess.rs` (reference detection, chains, adjacency, string expansion, stripping, unknown/duplicate/cycle rejection, `alias.kpconf` parsing) plus 6 end-to-end tests. `aliases.kp` (inline declarations, a chain, a reference inside a string), `alias_cycle.kp` and `alias_unknown.kp` (rejected), the `alias_kpconf` project (an `alias.kpconf` entry used as an `impl` path), `alias_cross_file` (cross-module inline alias), and `alias_kpconf_cycle` (the two-file cycle diagnostic). 62 unit tests, 50 fixture/project tests.

## MK3 heap and containers

Split three ways, on the same reasoning that split MK1-S4-M1 and MK2: the byte buffer plus its drop rules is an independently testable increment, and everything else about the heap (the second builtin type, `extern`, the stdlib modules) builds on it. MK3-S1-M1 and MK3-S1-M2 shipped; MK2-S2-M1 is what remains of the original entry.

### MK3-S1-M1 builtin owned `Bytes`, drop, and moves with runtime consequence (DONE)

- **The type.** `Ty::Bytes` is a compiler builtin (not a `datac`): `kelp_Bytes { unsigned char* data; size_t len; }` in the generated C, so it is the one type that may hold a pointer. It is non-`Copy` (`Ty::is_copy`), which is what makes MK1-S3-M1's move machinery apply to it with no new move logic at all: `val b = a` moves, using `a` afterwards is an error, and a `Bytes` parameter is a *borrow* (MK1-S4-M1's rule, now spelled out in `implicit_borrow_wrap`, which had to learn about owned heap types as well as `datac`s).
- **The builtins.** `Bytes.empty()`, `Bytes.from_str(s)` (associated, written on the type name), and `Bytes.len()`, `is_empty()`, `get(i)`, `set(i, v)`, `clone()`. `infer.rs` keeps them in a single table keyed exactly like a receiver method (`Bytes#len`), so call resolution, argument matching, and passdown wiring are unchanged; `codegen_c.rs` emits the bodies from a fixed runtime preamble, and a builtin the preamble does not define fails at `cc` rather than silently. `fun Bytes.helper()` is rejected with a message saying builtin methods are compiler-provided, and `datac Bytes` is rejected as a redeclaration of a builtin type.
- **Drops.** `borrowck.rs` already tracked moves and scopes; it now also returns a `DropPlan` a side table keyed by *span*, saying which owned locals die at the end of each block and which die before each `return`. Keying on spans rather than position is what lets `codegen_c.rs` walk the tree independently: the two passes genuinely differ in one place (`while` bodies are checked twice for MK1-S3-M1's double-move check but emitted once). A moved-out local is never dropped by the scope that declared it; a `return` drops the frame's live locals *after* evaluating the returned value (which may read through one of them); reassigning an owned `var` frees the old value after reading the new one and before storing it.
- **New `u8`, `u16`, `usize`, `isize`**, because a byte buffer cannot be described without them: `len` is `usize`, `get` is `u8`, indexing is `usize`. All four are ordinary numeric types for arithmetic and `print`.
- **Printing a `Bytes`** goes through `%.*s` with the buffer's length and pointer as two arguments, which is why it requires a *place*: a temporary has no address to take, and evaluating it twice would allocate twice. The diagnostic says so and suggests binding it to a `val` first. This is the one restriction MK3-S1-M1 adds to `print`.
- **The gate, met and mechanized.** The original gate said "a fixture that moves a `Bytes` into a function and uses it after the move is rejected" that spelling no longer exists, because MK1-S4-M1 removed move-taking parameters. The implemented equivalent is a *local* rebinding (`heap_use_after_move.kp` rejected, `heap_move_then_rebind.kp` accepted). And "no double free is expressible" is no longer just an argument: every heap fixture is rebuilt with `-fsanitize=address` and run as part of `cargo test`, so a double free, a use-after-free, or a **leak** fails the suite. That is what caught two real bugs during this milestone a branch merge that silently dropped the drop candidates, and a reassignment that leaked the overwritten buffer which is exactly what the gate was for.
- **Deliberately not in MK3-S1-M1** (all of them with an explicit diagnostic rather than silent behavior): owned values as `datac` fields, owned passdowns, owned values in growable buffers, and `String`/`str`/`path`/`fs`. A `datac` field of type `Bytes` is refused because dropping a struct means generating a recursive drop for its fields; a `pd` of type `Bytes` is refused because there is no drop point at process exit yet; and an owned `Bytes` returned from a function is fine, but a borrow *of* one that outlives it is not expressible either which is the `&str` return-elision question again, deferred with it.
- **Known remaining leaks, both safe.** `if c { b = a }` marks `a` moved for the code after the `if` (MK1-S3-M1's conservative branch merge), so the branch that did not move it leaks rather than risking a double free; and an assignment *through* a dereferenced borrow (`*p = value`) leaks the value it overwrote, since the drop plan only records plain bindings. Both are leaks, never a double free, and both are in the plan's ledger rather than hidden.
- **Two `datac` field rules tightened while the checker was open**: a field of an owned type (`Bytes`) is refused (dropping a struct is not implemented), and so is a *borrowed* field (`str`/reference) the latter is `syntax.md`'s own "a datac holds owned data only" rule, which nothing had been enforcing because v1 had no owned alternative (`datac_str_field.kp`).
- Fixtures: `heap_bytes`, `heap_param_borrow` (a `Bytes` parameter is a borrow: read through shared, write through `mut`), `heap_move_then_rebind`, `heap_returned`, `heap_scope_drop`, `heap_drops_in_control_flow` (loop body, `return` from inside a branch with another owned local live, block-as-value), `heap_reassign`, `heap_branches`, plus rejected `heap_use_after_move`, `heap_temporary_print`, and `datac_str_field`. 11 fixtures, 12 tests, all heap ones additionally run under AddressSanitizer.

### MK3-S1-M2 owned `String`, `extern`, and the first stdlib modules (DONE)

Shipped as one increment because the four pieces meet in one place: `String` is what makes the stdlib worth writing in Kelp, `extern` is what makes it possible, and owned `datac` fields plus an owned `pd` are the two places MK3-S1-M1's "dropping a struct is not implemented" wall actually stood.

**`String`**
- `Ty::String` is the second builtin owned type: the same `{ unsigned char* data; size_t len; }` shape as `kelp_Bytes`, kept a distinct type so text and raw bytes are not interchangeable. Non-`Copy`, dropped at the end of its scope, printed through the same `%.*s` path, and refused as a `datac` name next to `Bytes`.
- Builtins: `empty`, `from_str`, `from_bytes`, `len`, `char_count`, `is_empty`, `clone`, `into_bytes`. `char_count` is the reason `String` is not just a `Bytes` alias it counts non-continuation bytes, which is a real operation and not a cast.
- **`into_bytes`/`from_bytes` are ownership transfers, and that needed no new machinery.** Declaring the builtin's `self` parameter as plain `Ty::String` (not the `Ty::Ref` `implicit_borrow_wrap` would produce) makes the existing call-argument path read the receiver as a whole value, which MK1-S3-M1's move tracking already understands so the receiver local is marked moved and the buffer changes owner without a copy. `String.from_str("x").into_bytes()` therefore works and leaks nothing: the buffer moves pointer-wise into the result.
- `as_str`, `as_bytes`, and `slice` are *not* in the surface yet. Each returns a borrow of the receiver, and a function cannot return a `Ty::Ref` until MK2-S2-M1's `&str` return-elision rule exists (see the MK1-S4-M1 note on why `resolve_type` never produces one).

**`extern fun` and the stdlib**
- `extern fun name(params).R: T` parses as a fourth `FunctionBody` variant with no body at all (writing one is a parse error, and an `extern` receiver method is rejected a method body is exactly what the compiler cannot supply for an arbitrary type). `infer.rs` accepts the declaration only if `externs.rs` has a body for it, so user code gets "only compiler-shipped stdlib modules may declare 'extern fun'" instead of a missing symbol at `cc`.
- Bodies live in `externs.rs`, keyed by `(module id, bare name)` `("std/mem", "alloc_raw")`, `("std/str", "byte_at_raw")`. A body's C text has to use the mangled parameter spelling (`n` -> `kelp_n`), so `codegen_c.rs` writes a comment listing that mapping above each body rather than leaving it to be deduced.
- `resolve.rs` serves `std/...` ids from sources embedded in the binary (`stdlib.rs`, `include_str!`) instead of from disk, so `kelpc` stays one self-contained file and the stdlib version is pinned to the compiler version for free. Everything downstream lexing, aliases, parsing, prefixing, `impl`-cycle checks is identical to a project module, which is why `std/str.kp` can `impl "std/mem"` and `std/path.kp` can import both. A `std/...` module the compiler does not ship is still rejected, now naming what does ship.
- Shipped: `std/mem` (`alloc`, over one extern), `std/str` (`len`, `byte`, `is_empty`, `to_upper`, `to_lower`, `repeat`), `std/path` (`is_absolute`, `join`). Only three C bodies exist in total: a `malloc`-and-zero wrapper, a `strlen`, and a bounds-checked byte read. That is stdlib decision 3 in practice the policy is Kelp source, the unportable primitive is one line of C.
- Deliberately deferred with a note in the file: `str.replace`/`from_i64`/`from_f64` (**all shipped in MK5-S1-M3**) and `path.normalize`. `normalize` is the *same* function the MK4-S1-M1 capability matcher needs for its `..` rejection, so it should be written once, against the grant matcher, rather than twice that is the reason it is not here.

**Owned `datac` fields, and the recursive drop**
- A field of `Bytes`/`String`/an owned `datac` is now allowed. `Ty::needs_drop()` could only answer for a builtin (a `Ty::Struct` cannot know its own fields without the struct table), so it became the free functions `types::needs_drop(ty, owned_structs)` and `types::owned_structs(structs)`; because a `datac` may only name `datac`s declared before it, one pass in declaration order is already a valid fixpoint.
- `codegen_c.rs` emits `kelp_drop_<Type>` next to each struct's typedef when it owns memory, recursing into the fields that need it. Ordering is free: a struct's drop function is always defined before the struct that calls it.
- **Still a leak, and worth recording:** assigning a *field* of an owned type (`h.name = s`) overwrites a live buffer with nothing freeing it, because the drop plan only records plain bindings (the same shape as the `*p = value` leak from MK3-S1-M1). Also new in MK3-S1-M2: a non-tail expression statement that evaluates to an owned value (`String.from_str("x")` on its own line) is *rejected* rather than silently leaked, with a message telling the author to bind it.

**Owned `pd`**
- A `pd` of an owned type is allowed: the generated file-scope global stays, and `write_pd_globals` emits a `kelp_drop_pds()` that `kelp_init_pds()` registers with `atexit` v1's only drop point at process exit, which is what open item 3 was waiting on. A referencing function still receives it as a shared borrow, so `pd` remains read-only inside a function.
- An owned `pd` still cannot be read inside *another* initializer ("its value is not Copy"), which is unchanged from MK2-S1-M2 and now covers `String` as well as `datac`.

**A comparison rule the heap made necessary**
- `==`/`!=`/`<`/… on an owned value, a `datac`, or a `str` used to type-check and then fail at `cc` (`kelp_a == kelp_b` on two structs), or for `str` quietly compare *addresses* instead of text. `infer.rs::comparable` now restricts comparisons to the scalars C can compare directly plus `Ty::Ref` (comparing two borrows compares addresses, which is what the author asked for). Rejecting is the honest v1 answer; byte equality for `String`/`Bytes` is the obvious MK2-S2-M1 addition. Pinned by `compare_owned.kp`.

**Two bugs found while building it**
- **A module could not call its own items.** `resolve.rs` stores a non-entry module's top-level names with their module prefix, and `infer.rs` had always looked callees up by the bare name the source wrote so `fun alloc(n) = alloc_raw(n)` inside `std/mem.kp` failed with "call to undefined function 'alloc_raw'". Nothing had ever exercised a module's self-reference, because every existing project called its own items only through receiver methods (which resolve through the receiver's already-prefixed type name) or from the entry module (whose prefix is empty). Fixed with `Ctx::qualify_own`, which retries the lookup with the module prefix; `datac` construction goes through the same helper. Pinned by the `self_call` project.
- **Multi-byte UTF-8 in a string literal was mangled.** The lexer is byte-oriented and pushed each byte of a multi-byte character as its own Latin-1 scalar, so `"héllo"` became `"hÃ©llo"` `String.len` reported 8 bytes for 6, and `char_count` was meaningless on exactly the input it exists for. Such a bug is invisible until a type can *measure* a string, which is why it surfaced here and not in MK1-S1-M1. The literal path now reassembles the character from the (already validated) `&str`.
- Fixtures: `string_basic`, `string_field` (owned field, dropped with the struct, moved whole), `pd_owned`, `stdlib_mem`, `stdlib_str`, `stdlib_path`, plus rejected `extern_no_body`, `extern_receiver`, `compare_owned` (comparing owned values has no generated meaning), and `owned_statement`; the `self_call` project; and two new lexer unit tests. `string_basic`, `string_field`, `pd_owned`, and all three stdlib fixtures joined the AddressSanitizer pass, which is what proves the `atexit` drop and the recursive struct drop rather than asserting them. The harness now builds the instrumented programs to their own output paths instead of racing the individually-run fixtures for the same file. 63 unit tests, 73 fixture/project tests.

### MK2-S2-M1 `const`, stdlib-only overloading, and `&str` return elision (DONE)

Three things that were stdlib prerequisites, shipped together because `str`, `path` and `math` all needed at least one of them and none needed the others to land first.

**`const`**
- `const NAME: T = expr` at top level (type mandatory: a `const` is a declared contract, not an inferred binding), folded at its declaration and substituted at every use. `math.PI` is the literal `3.141592653589793` in the generated C no global, no initializer function, no runtime cost.
- An initializer may be a literal, an earlier `const` (same module or `alias.NAME`), and arithmetic/comparison/logic on those. That is a deliberate limit: folding is a single pass, so a `const` can only use constants declared before it, and a call in an initializer is a compile error rather than a deferred evaluation.
- `const` shares its module's top-level namespace with `datac`s, `pd`s and functions, so a clash is reported at the declaration. Canonical order became `impl`, `const`/`pd`, `datac`/`fun`.

**Argument-type overloading, stdlib-only**
- An overloadable name (`abs`, `min`, `max`, `clamp`) declared in a compiler-shipped module gets a *parameter-typed* signature key (`std.math.abs@f64`), so several declarations coexist; a call site probes its first argument's type and picks the single matching overload, with "no overload of '<name>' takes '<type>' — it is declared for …" otherwise.
- The mechanism is gated on `is_std_module`, which is what stdlib decision 4 asked for: user code cannot declare overloads, and cannot tell that the compiler has the machinery.
- The consequence to remember: `scan_all` (passdown wiring) and the body checker need the *same* key the call sites will use, so `check_program` now computes a `decl_keys` vector once and threads it, instead of every pass re-deriving `sig_key`.

**`&str` return elision**
- `&T` in a *return* position is a `Ty::Ref` whose lifetime is the function's first reference parameter (`str` counts as one: a `str` parameter *is* `&str`, modelled as a flat borrowed view). MK1-S4-M1's claim that "no surface syntax produces a returned borrow" is now false by exactly this much, and `borrowck.rs` enforces the rule at both ends:
  - a returned borrow must be rooted at that parameter or be a `str` literal, whose storage is static, which is what `fun classify(n: i32).R: &str = "pos"` needs, and what keeps the syntax file's own `when` example compiling;
  - a caller of a borrow-returning function keeps the rooted argument borrowed for the enclosing scope (`register_scope_borrow`), so moving or freeing the owner while the view lives is an error.
- Rooting is transitive through calls (`trim_start(s)` roots at `s`) and through `if`/`when` in value position (all branches must agree), which is why a `when` of literals works and a branch mixing a parameter with a literal does not.
- Representation: a `&str` is the `const char*` it already was, so a view and a `str` are the same value at runtime and interchangeable in argument matching and `print`. Only the type system and the borrow checker distinguish them.
- **The one design consequence worth stating**: a `&str` is a NUL-terminated C string, so a *suffix* can be a view but a *prefix* cannot (there is nowhere to put a terminator). `str.substring`/`trim_start`, `path.file_name`/`extension` are views; `str.trim`/`trim_end`/`prefix` and `path.parent` allocate and return `String`. That is a deviation from the plan's own `str` sketch, and the honest one the alternative is a length-carrying `&str`, which is a different type.

**The surface that shipped**: `str.len`/`byte`/`char_count`/`is_empty`/`substring`/`trim_start`/`trim_end`/`trim`/`prefix`/`starts_with`/`ends_with`/`contains`/`eq`/`index_of` (returning the `Match` error `datac`)/`to_upper`/`to_lower`/`repeat`; `String.as_str`/`Bytes.as_str` as builtins returning views; `path.is_absolute`/`join`/`normalize`/`file_name`/`extension`/`parent`; `math` with `PI`/`E`/`TAU`, the libm transcendentals, and the four overloaded families. Only three further C bodies were needed (a bounds-checked byte read, a slice-from, and a `strlen`).

**Also fixed here, because the stdlib made it bite**: printing or interpolating a *temporary* owned buffer (`print(str.to_upper(s))`) used to be a diagnostic telling the author to bind a `val` first (open item 16). Codegen now hoists the temporary into a C variable and drops it right after the `printf`, so the allocation is freed exactly once `heap_temporary_print` is in the AddressSanitizer pass to prove it.

### MK2-S2-M2 a `pd var` is writable (DONE)

MK2-S1-M2 resolved the `pd var` question by making a passdown read-only inside every function, which left a `pd var` with no way to be written at all `main` included. This replaces that with a rule that *keeps* the write path checked instead of removing it:

- A `pd` reference inside a function is a hidden **borrow** of the global, typed by the declaration: `pd var` → exclusive, `pd val` → shared. A read is `*borrow`, so reads and writes go through one pointer and `count = count + 1` is an ordinary assignment through an exclusive borrow.
- `main` and `pd` initializers have no hidden parameters, so they reach the generated global directly (`*(&kelp_pd__count)`), and `borrowck.rs` registers the globals as bindings so those accesses are tracked too otherwise `combine(tally, tally)` in `main` would alias two borrows of one global unnoticed.
- Diagnostics name the passdown rather than its hidden parameter (`cannot borrow passdown 'tally': already borrowed exclusively`), and writing a `pd val` keeps its own wording.
- **The cost, pinned by a fixture**: every reference to a `pd var` is exclusive, so one call cannot take it both exclusively and shared (`pd_var_double_borrow.kp`). Reading a *Copy* passdown by value is unaffected that is a read of the global, not a borrow of it (`pd_var_copy_read_twice.kp`).
- The alternative that would remove that cost propagate exclusivity transitively over the call graph so a read-only function keeps a shared borrow is recorded as an open item rather than built, because it needs a fixpoint over call edges that nothing else in v1 needs yet.

### MK4-S1-M1 Capability-based security (DONE)

**Grants**
- `impl "target" with caps(domain = ["pattern", ...])` parses (the MK2-era "not yet" error is gone), one clause per domain, empty pattern lists allowed.
- A capability set is **received, never self-declared**: the entry module holds everything (path domains `/**`, the name domain `*`), every other module holds exactly what its importers granted it, and a delegation must be covered by what the delegating module holds `pattern_covered` is deliberately syntactic and conservative (identical, or inside a `/**` root), because glob-to-glob inclusion is undecidable and being conservative can only *under*-grant.
- Patterns are validated at the `impl` line, by the vocabulary of the domain. `fs` and `process` name paths: absolute, `**` legal only as a whole segment, and a `..` segment refused outright a grant must not be able to name its way out of its own root. `net` names a host and an optional port (`api.example.com:443`, `*.example.com`, `*:8080`, `*`), with the split at the last `:` so an IPv6 literal is unexpressible rather than ambiguous (MK5-S3). `env` patterns are variable names (`HOME`, `LANG*`, `*`), and `time`/`rand` have no named resource at all, so their pattern list is unused.

**Enforcement, split the way the plan asks**
- *Reachability* is a resolution error: `infer.rs::check_capability` refuses to resolve an item of a gated module for a module that does not hold the domain. No runtime check is reached the name simply does not resolve, which is the whole point of the feature.
- *Matching* is a compiler-inserted runtime check at each gated **call site**, using the **calling module's** compiled-in allowlist, emitted as a statement expression so it works in value and statement position alike. Paths are lexically normalized, then symlink-resolved, then glob-matched in that order, and the order is the reason a link inside the grant that points outside it is denied. `env` matches names as written (no path structure to normalize). A denial panics with the `.kp` call site, the attempted value, and the granted patterns; the location comes from `diag::SourceMap`, threaded into codegen for exactly this.
- `extern` bodies inside a gated module are the *primitive* and are not themselves gated the check belongs at the boundary where a user module names the public function, which is also why `std/fs` needs no grant to call its own syscall wrappers.
- `path.normalize` and the capability check call the **same** C normalizer, so the security-relevant normalization exists once.

**What shipped behind the gate**
- `std/fs`: `read`, `read_text`, `write`, `write_text`, `exists`, `is_file`, `is_dir`, `size`, `remove`, `rename`, `mkdir`, `append`, `sync`, over twelve compiler-supplied syscall externs. `mkdir_all` needs prefix walking and is deferred. `append`/`sync` were added when a 20 GiB streaming write turned out to be the thing that needed them (see the note under `fs` in the stdlib section); `append` is the streaming primitive and needed no growable buffer, which is the part the plan had wrong when it pencilled `fs.append` in with the collections milestone.
- `std/time` (`now_unix`, `now_mono_ns`, `sleep_ms`) and `std/rand` (`u64`, `below`, `bytes`) are real, both gated. Sleep is gated only by accident of where it lives: the plan's classification is that sleeping is not a capability.
- `std/env` is the worked example of a *structurally gated stub*: the domain, the grant and the variable-name check are real, the bodies panic. `std/process` shipped in MK5-S2-M1 by reusing the `fs` path vocabulary (an absolute program path, symlinks resolved), and `std/io` shipped ungated; `std/net` shipped in MK5-S3 with a vocabulary of its own, which is the one domain whose patterns are neither paths nor plain names. `env`'s bodies are the last of the stubs (MK5-S5).
- **The entry module is still unrestricted.** The plan says main holds everything "until a later milestone adds a way to restrict main itself", and that is exactly what the `caps_granted`/`caps_denied` fixtures show: the restriction that bites is the one a *library* module received. Worth remembering when reading a fixture whose `main` reads `/etc` without complaint.

**Fixtures**: `caps_granted` (read + `exists` inside the grant), `caps_write` (write, size, rename, remove, mkdir), `caps_denied` (a path outside the grant, denied at runtime), `caps_symlink` (a link inside the grant pointing outside it, denied after resolution), `caps_ungranted` (resolution error), `caps_escalation` (over-delegation refused), `caps_bad_pattern` (`..`), `caps_bad_path_pattern` (relative), `caps_bad_domain` (`disk`), `caps_env` (granted stub: the name check passes, the body panics), `caps_time_rand`, `path_normalize`.

### MK3-S2-M1 collections: the builtin `List<T>` (DONE)

The last blocked-on-nothing item from "Not shipped, and known": with no way to hold *N* items, `fs.list`, `str.split` and argv were all unwritable. Shipped in two commits, because the type itself is independently testable and the stdlib on top of it is a separate increment (the same reasoning that split MK3-S1-M1/MK3-S1-M2).

**The type**
- `List<T>` is a compiler builtin, not a user-definable generic: one type argument, accepted in *type positions only* (`val xs: List<String>`), and the parser rejects arguments on any other name and more than one on `List`. `Ty::List(Box<Ty>)` is non-`Copy`, so MK1-S3-M1's move checking, MK1-S4-M1's borrowing and MK3's drop plan apply with no new rules at all `needs_drop` answering true for a `List` is the whole interface the drop machinery needed, and that is also what puts a list in a `datac` field and in an owned `pd` (dropped through the struct's generated drop function and the `atexit` handler, respectively).
- Elements are the types a flat growable array can hold: the scalars, `String`, `Bytes`, and a `datac`. A borrow or a `str` view is refused with the reason (an element has to outlive the list, and v1 has no lifetime syntax to say so), and nested `List`s are refused by the same check. A `datac` element works because its instantiation is emitted together with that struct, so the struct's typedef and its drop function are already defined.
- Constructors: `List.of(x)` infers the element type from `x`, and `List.empty()` takes it from the binding's written type (`var xs: List<String> = List.empty()`) which is also why the method-call path now passes an `expected` type down, information `when`/block checking already had. Methods: `len`, `is_empty`, `push`, `get`, `set`, `pop` (panics on an empty list, per the failure model), `clear`.
- `get` returns a **copy** for a `Copy` element and a **borrow** for an owned one. That is the one place an element type changes a signature, and it is the honest reading: copying a `String` out of a list would be a second owner.
- Codegen is monomorphized: `collect_list_elems` finds every element type the program mentions, and `write_list` emits one C struct plus one function set (`push`, `get`, `pop`, `set`, `clear`, bounds check, drop function) per element. Non-`datac` elements are emitted before the structs; a `datac` element's instantiation is emitted directly after that struct, in declaration order which is why `List<Circle>` is expressible while a *field* of `List<Circle>` inside `Circle` is not (the same "a datac may only name earlier datacs" rule, open item 12).
- Growth doubles with `realloc`; the element is stored by plain assignment, which *is* the move the checker has already marked the source binding moved, so nothing else frees it.

**Two borrow-lifetime refinements, both forced by lists being usable**
- A borrow produced by a **statement's temporary** (`print(l.get(0))`) now ends with that statement instead of with the block. Scope lifetimes are still lexical a *bound* borrow (`val p = l.get(0)`) lives as long as its binding but holding every temporary to the end of the block made the ordinary "read an element, then mutate the list" sequence fail with a conflict against a view that was already dead. The `if`-merge path rebuilds a scope's borrow list by design (both arms' scope-durable borrows are already released), so the release is clamped to what is still recorded.
- A **shared borrow of a temporary** is allowed as a call argument (`str.join(str.split(s, sep), sep)`, or a `datac` literal passed to a function that borrows it). The temporary lives for the whole enclosing expression, which is exactly how long a call-scoped borrow lasts; codegen hoists it into a C variable covering the call and frees it right after if it is owned, which is why the hoist happens at the *call* and not at the argument a GNU statement expression's temporaries die when it ends, before the call it is an argument to. A call that **hands the borrow back** still requires a place, because the result outlives the statement (`String.from_str("x").as_str()` bound to a `val` is rejected): that is the one case where a borrow of a temporary would dangle.

**The stdlib it unblocked**
- `str.split(s, sep) -> List<String>` and `str.join(parts, sep) -> String`, both ordinary Kelp. `split` copies each piece with a new `str.copy_range` (a middle range cannot be a view: a `&str` is a NUL-terminated C string); an empty separator splits into one piece rather than looping. `join` was written size-first-and-fill-once because `String` was fixed-size then; MK5-S1-M3 rewrote it as a `push_str` loop, which is the difference a growable buffer makes.
- `fs.list(path) -> List<String>`, gated like the rest of `fs`. The walk is one compiler-supplied `scandir`+`alphasort` extern (`.`/`..` dropped, entries newline-separated, sorted so the order is stable), and the Kelp wrapper turns it into a list with `str.split`. Entries are *names*, not paths `path.join` builds a path from one.

**Fixtures**: `list_basic` (grow, index, set, pop, clear), `list_owned` (owned `String` and `datac` elements; `get` as a borrow, `pop` moving one out), `list_field` (`List` in a `datac` field and in an owned `pd`), `list_datac_element` (a `datac` element, so the interleaved emission order is exercised), `stdlib_list`, `borrow_temp_arg` (accepted), and rejected `list_moved_element`, `list_borrow_element`, `list_no_element_type`, `borrow_temp_returned`; `list_pop_empty` panics at runtime with "List.pop: the list is empty". The `caps_list` project lists a granted directory and clears it recursively through `fs.list` itself, so the test is repeatable and owns everything it touches. Every accepted list fixture is in the AddressSanitizer pass.

### MK3-S2-M2 `Box<T>` and recursive `datac`s (DONE)

The plan called this "user-definable owned types, i.e. `Box<T>`-style owners beyond the two builtins ... a monomorphic single-parameter special case is hand-rolled", and that is what shipped: not generics, but the owner that makes a *user* type able to hold an arbitrary value and, with it, the one thing this language cannot be without: **a type that refers to itself**.

**The type**
- `Ty::Box(Box<Ty>)`, non-`Copy`, owns heap. `Box.empty()` is a cell holding nothing (a NULL pointer), `Box.of(v)` allocates and moves `v` in, `take()` moves the value out and leaves the cell empty, `get()` borrows it (a *copy* for a `Copy` element, like `List.get`), `set(v)` replaces the contents (freeing the old value, and reusing the cell), `is_empty()` asks. `get`/`take` on an empty box panic v1 has no `Option`, and `is_empty()` is the predicate to check first.
- Elements may be anything with a size, *including* another container (`Box<List<String>>`, `Box<Box<i32>>`) and any `datac`. A borrow or a `str` view is still refused (the box owns its value, and there is nowhere to put that lifetime), and `List<Box<T>>` stays refused because a list's buffer holds its elements inline the diagnostic names `Box<List<T>>` as the equivalent. Nesting inside a box is what the `ty_mangle` element naming and the depth-ordered emission exist for.
- `Box` is a *builtin*, monomorphized like `List` (`collect_containers`): a `datac` element's instantiation is still emitted with that struct's tag, so no user-declarable generics were needed. That is the honest state of MK3-S2-M2's "this wants generics" note: one more builtin container, still no way to *declare* a generic type (open item 34).

**Recursion, and the rule that keeps it finite**
- A `datac` may name itself, and any `datac` declared *later*, **through a container**; a direct by-value reference is still refused, now with the fix in the message (`val next: Box<Node>`). The struct table gets a placeholder entry for the datac being resolved (`TypeScope::in_progress`), replaced by the real definition in place, so declaration order and emission order are unchanged and the by-value case still gets the infinite-size explanation it deserves.
- The shapes that now work: `datac Node(val value: i32, val next: Box<Node>)` (linked list `Box.empty()` terminates it), `datac Tree(val value: i32, val kids: List<Tree>)` (tree a list of a datac is pointer-indirect at C level too), and a mutually recursive `Leaf`/`Branch` pair.

**One emission order instead of two**
- MK3-S2-M1 interleaved list instantiations with the `datac`s, which cannot express a list of a `datac` that is not declared yet. MK3-S2-M2 replaces it: (1) every `datac`'s struct tag is forward-declared; (2) every container typedef is emitted, outermost last, naming a `datac` element by its tag (`struct tag_Foo* data`) a pointer, so the element may be incomplete; (3) the `datac`s, each with its drop function (struct typedefs are now tagged); (4) the container function sets, innermost first, because their signatures need the element's complete type. Drop prototypes come before step 3, since a `datac` that owns a container drops it. A container inside a container is ordered by nesting depth (`container_depth`).
- The recursive drop is a chain of already-defined functions in the right order: `kelp_drop_Node` → `kelp_box_drop__Node` → `kelp_drop_Node` (the pointee). Two consequences worth knowing: the drop recurses on the C stack, so a very deep structure overflows it (the same limitation Rust has), and a recursive walk does too which is why an iterative cursor is worth having (open item 33).

**Two latent memory bugs, found because of what `Box` made expressible**
- **`x = f(x)`, where `f` takes its argument by value** the assignment's old-value drop fired even though the value had been *moved* into the call, freeing memory its new owner still held. Invisible until a by-value-taking function returned the same type it consumed, which is exactly `list = Node(next = Box.of(list))`. Fixed by reading the moved flag *before* `check_assign_target` reinitializes the binding.
- **Reading an owned field by value was allowed, and is a shallow copy** `var stolen = bag.xs` handed out a second owner of the same buffer, so mutating the field afterwards left `stolen` dangling: a real heap-use-after-free that predates MK3-S2-M2 by two milestones (it needs a `var` field, an owned field, and a realloc that moves). Now refused ("v1 has no partial moves, so this would give two owners of the same buffer use it through a borrow, or hold it in a `Box` and `take()` it"), with `owned_field_read.kp` pinning the rejection and `box_field_take.kp` showing the take/change/set round trip that replaces it. Assigning an owned *field* (`h.name = s`) still leaks the old value open item 15.

**One borrow rule relaxed**
- Reassigning a `var` that *holds* a shared borrow (`p = &two`) is now allowed: it rebinds the pointer and does not write through the borrow, so it needs no exclusivity. A *bound* borrow still lives to the end of its block, and a cursor over a borrowed recursive structure still needs borrow provenance through pointer locals (open item 33), so a walk is written recursively today.

**Fixtures**: `box_basic` (empty/of/get/set/take, a box of a `String`, a nested box, a box of a list, and the pointer-rebind rule), `box_recursive` (a 200-node list: build by prepending, recursive sum and depth, drop, `take`/`set`), `recursive_datac` (a tree through `List<Tree>`, plus a mutually recursive pair), `box_field_take`, and rejected `box_borrow_element`, `datac_self_value`, `list_container_element`, `owned_field_read`; `box_empty_panic` panics at runtime with "Box.get: the box is empty". All four accepted ones are in the AddressSanitizer pass.

### MK5-S1-M1 a growable buffer, and failing deliberately (DONE)

The first slice of the stdlib program: the piece everything else in MK5-S1–MK5-S5 was blocked on. Done as a part because the compiler change (a `cap` field and its invariants) is independently testable from the `.kp` surface built on top of it, the same reasoning that split MK3-S1-M1/MK3-S1-M2 and MK3-S2-M1.

- **One growth routine, two buffers.** `kelp_Bytes`/`kelp_String` gained a `cap` field (usable bytes at `data`, *excluding* the NUL terminator slot, so the allocation is always `cap + 1`). `kelp_buf_reserve(data, len, &cap, extra)` doubles from `cap` (or jumps to 8) until it fits, `realloc`s, and re-terminates at `data[len]` the single invariant that keeps `String.as_str()` handing out a valid `str` after any number of appends. Every constructor sets `cap`: `empty` 0, `from_str`/`clone`/`from_bytes`/`into_bytes` the buffer's real size, `kelp_bytes_alloc_raw` `n`. The extern bodies that build the structs field-by-field needed no edit: `fs.read_raw`, `fs.list_raw` and `path.normalize_raw` all go through `kelp_bytes_alloc_raw`; `list_raw` trims `len` below the capacity it allocated, which is exactly what `cap >= len` allows.
- **New builtins** (`infer.rs` table + runtime bodies): `Bytes#push`, `Bytes#append`, `Bytes#reserve`, `Bytes#clear`; `String#push`, `String#push_str`, `String#reserve`, `String#clear`, and the associated `String.with_capacity(n)`. All growth methods take `&mut self`, which is the entire safety argument for `realloc` moving the buffer: a live `str` view of the receiver is a shared borrow, so the borrow checker refuses the growth (`grow_while_borrowed`) and refuses it through a `val` binding (`push_to_val_string`).
- **`panic`/`assert` are free builtins.** The C already existed (`kelp_panic`); this added `kelp_assert` and two entries in the same table the builtin methods live in, keyed by bare name. `check_call` consults that table only *after* the program's own signatures, so a user function named `panic` or `assert` shadows the builtin rather than colliding with it.
- **One deviation from the sketch, forced by a gap in the language:** `String.push` takes `u8`, not `char`. v1 has no char literal and no function that returns a `char`, so the sketch's `push(ch: char)` is unwritable from `.kp` (and `fmt`'s `fill: char` will be the same problem in part 2). `char` is a type with no values see open item 53. `str.byte` already returns `u8`, so a program has a real byte source, and `Bytes.push`/`String.push` now agree on the same type.

**Fixtures**: `string_build` (push, push_str, reserve, clear, with_capacity, and a print after every growth), `bytes_build` (push, append of a borrowed view and of a temporary, reserve, clear), `panic_msg` and `assert_fail` through `assert_fixture_panics` with golden text, and rejected `grow_while_borrowed`, `push_to_val_string`. Both accepted fixtures are in the AddressSanitizer pass, because growth is where a leak or a bad `realloc` would hide.

### MK5-S1-M2 integer conversions (DONE)

Part 2 of the sketch assumed number formatting, `str.char_at`, `fmt.hex` and `fmt.bytes` were writable in Kelp ("arithmetic and byte shuffling"). They are not, and the reason is not small: **v1 has no numeric conversions at all**. Operands must match exactly, so `u64 % 10` cannot yield a value `String.push(u8)` accepts, a `u8` byte cannot index with `usize`, and UTF-8 decode cannot combine bytes into a `u32`. Every one of those functions therefore needed either a C primitive or a conversion, and the choice made deliberately is the conversion:

- **Every integer type has `to_<T>` for every integer type** (`to_i32`, `to_i64`, `to_u32`, `to_u64`, `to_u8`, `to_u16`, `to_usize`, `to_isize`), a method on an integer receiver: `(n % 10).to_u8()`, `digit.to_usize()`. 64 entries, generated by a loop in `BUILTINS`, not written by hand. `builtin_type_name` gained the eight integer names so a numeric receiver has an owner to resolve against, and the no-such-method diagnostic for a numeric receiver names the conversion surface instead of calling `u8` a `datac`.
- **Widening is a plain cast; anything that can lose a value is checked and panics** with the call's own `.kp` spelling (`panic: i64.to_u8: value out of range`), so a narrowing is never a silent truncation the same failure model the rest of the stdlib uses, and the reason `-1.to_u8()` is a crash rather than 255. `codegen_c.rs` emits the check inline as a statement expression (`int_bounds` in Rust decides which pairs need one; a signed source compares against the target's real minimum, which is where the first version of this had a bug that `int_conversions` caught `-7.to_i32()` panicked).
- **Implicit widening was considered and rejected.** It would make arithmetic "just work" across widths, but it is a type-system rule change with consequences far past MK5-S1 (which operand wins, what `i32 + u64` means), and it still would not have given `from_i64` its digit. A visible `to_*` is also where the overflow policy can be documented.

**Fixtures**: `int_conversions` (widening across `u8`/`u32`/`u64`/`i32`/`i64`/`usize`, in-range narrowing, a negative signed value through a signed target, and the two conversions a digit loop needs), `int_conversion_overflow` panicking through `assert_fixture_panics` with golden text.

### MK5-S1-M3 text you can build, numbers you can format (DONE)

The `.kp` half of MK5-S1, on top of part 1's buffer and part 2a's conversions. `std/str` gained `concat`, `from_i64`/`from_u64`/`from_f64`, `parse_i64`/`parse_u64`/`parse_f64`, `replace`, `byte_index`, `char_at`; and `std/fmt` is a **new module** (`stdlib.rs::source`/`shipped` plus the file) with `int`/`uint`/`float`, `hex`, `bytes`, `pad_left`/`pad_right`.

- **Only four new C bodies were needed**, which is the measure of how much part 2a bought: `snprintf("%.*f")`, `strtoll`, `strtoull`, `strtod` (each with a full-consumption check and `errno` rejection, so `"12x"`, `" 12"`, `""` and an out-of-range value are all `ok = false` rather than a partial parse), plus two `std/fmt` bodies (`snprintf("%llx")` and the byte dump). Everything else the digit loops, the replacement loop, the UTF-8 character index is Kelp.
- **`from_i64` is where the two live edges were found.** `i64`'s minimum cannot be negated in `i64` and cannot be converted to `u64` (the conversion checks and panics), so the digits are taken as `v % 10` with each remainder made positive first, and the sign is prepended afterwards; `u64`'s maximum has no literal spelling at all, so the fixture round-trips both through the parsers instead. A second, pre-existing borrow rule bit here too: `String.as_str()` may not borrow a *temporary* (the borrow would outlive it), which is why the negative branch could not be `concat("-", from_u64(mag).as_str())` until the digits were bound to a `val`.
- **`char_at` is arithmetic-only UTF-8.** v1 has no bitwise operators, so the lead-byte masks are subtractions (`b0 - 192`, `- 224`, `- 240`) and combining is `cp * 64 + (b - 128)`; `byte_index` is the primitive (a byte that does not continue a sequence starts a character, the same rule `char_count` uses) and `char_at` composes it. A truncated sequence and an index past the end both return 0. It returns `u32`, not the API sketch's `char` `char` still has no values (item 53).
- **`join` got simpler because of part 1.** MK3-S2-M1 sized the result first and copied once, because buffers were fixed-size; it is now a `push_str` loop, and the MK3-S2-M1 record's claim that it must be size-first is corrected there.

**Fixtures**: `stdlib_build` (concat, replace, `i64`/`u64` decimal including both edges), `stdlib_parse` (each parser's `ok`/`value`, the rejections, and the character-index pair), `stdlib_fmt` (numbers, hex, padding, the byte dump, and a built `String` viewed for `str.concat` the item-21 wart). All three are in the AddressSanitizer pass.

### MK5-S1-M4 the `List` ordering surface (DONE, so MK5-S1 is done)

The last piece: `List#sort`, `reverse`, `contains`, `slice`, `insert`, `remove`, all monomorphized into the per-element function set `write_list` already emits. This is where MK3-S2-M1's "monomorphization gives a per-element-kind comparator for free" note paid off one insertion sort per element type, plus one comparator.

- **Three of the six are conditional on the element type**, and the condition lives in `types.rs` (`list_sortable_elem` / `list_comparable_elem` / `list_clonable_elem`) so `infer::list_sig` and `codegen_c::write_list_s1` can never disagree: `sort`/`contains` need an order or an equality (scalars, `bool`, `String`, `Bytes`), and `slice` needs a copy (a scalar, or `String`/`Bytes` via `clone`). A `datac` element falls through to a diagnostic that says which capability is missing and why "a 'datac' element has no order, so it cannot be sorted" rather than a signature codegen would fail to emit.
- **The comparator is length-aware for `String`/`Bytes`**, not `strcmp`: an embedded NUL would truncate a `String` comparison, and the same helper is what `contains` uses (length, then `memcmp`). `bool` sorts `false` before `true`; an owned element's shifts are moves, so reordering a `List<String>` neither copies a buffer nor frees one twice ASAN proves that on a three-word sort with an insert and a remove.
- **`contains` borrows an owned needle** (a `Copy` element is taken by value), because taking a `String` by value would move it into a membership test.
- **`index_of` was deliberately not shipped.** The sketch listed it with a `-1` sentinel, which is exactly the sentinel convention the plan rejected in stdlib decision 2; open item 42 recommended `contains` now and `index_of` when `Option` exists (MK5-S6-M1). That is what shipped.

**Fixtures**: `stdlib_sort` (numbers, `bool`, an empty list, and a slice mutated to prove it is a copy), `list_slice_insert` (a `List<String>` sorted, searched, sliced, inserted into and removed from in the ASAN pass, because every shift is a move), rejected `list_unsortable_element`, and `list_slice_bounds` panicking with "List.slice: range out of bounds".

### MK5-S2-M1 `io` and `process`: the first real programs (DONE)

**`io`: one type over a descriptor**
- The sketch's `File` is what shipped, with no reader/writer hierarchy added: a file, a pipe, a socket and a terminal are the same fd at the POSIX level, and without traits or generics that is the only honest abstraction available. `read` (one `read(2)`), `read_into` (fills a caller-sized buffer at an offset, 0 at end of file), `read_all` (grows a buffer until end of file), `write`/`write_text`/`write_str`, `close`, `flush`, `set_nonblocking`, `wait_readable`/`wait_writable` (`poll`, which is MK5-S7-M1's event-loop primitive arriving early because a `run` that drains two pipes needs it), and `is_open`. `io.stdin`/`stdout`/`stderr` are ordinary `File`s no special cases anywhere below them.
- `flush` is a **no-op**, and says so: a `File` has no userspace buffer, every write is already a syscall. It exists so the stream contract is complete for a caller that does not know what it holds.
- `write_str` is the one addition to the sketch: a write of a borrowed view is what `eprint` and `io.print_bare` need, and doing it with `strlen` only (the `str` definition) keeps it distinct from `write_text`, which is length-aware on a `String` and so survives an embedded NUL.
- `BufReader` is an owned `datac` as recommended (open item 49): `file`, `buf`, `start`, `end`, with `read_line_into` as the primitive, `read_line` as the `Line`-returning wrapper, and `read_all` draining the buffer before reading on. The one process-wide reader over stdin is a module-scoped `pd var` which also made `pd var` of an owned `datac` the first thing a *stdlib* module holds, and exposed a codegen ordering bug: `kelp_init_pds` is emitted by the pass that writes the passdown globals, so a `pd` initializer that calls a function had no prototype in scope. The function prototypes are now emitted before it.
- `io.read_line`/`read_lines` go through that `pd`; `io.read_all()` reads fd 0 directly and therefore does **not** share its buffer, which is documented on the function rather than fixed, because two readers over one descriptor is the user's mistake to avoid (the same shape as closing a `File` twice).

**`process`: the grant is a program, not an argument list**
- `run(program, args)` and `spawn(program, args)` take the executable as its own argument, so the grant is one absolute path (`process = ["/bin/sh"]`) rather than a pattern over `argv`. `run` closes the child's stdin immediately, drains both output pipes with a 50 ms `poll` slice on each until both report end of file, waits, and returns `RunResult(code, out, err)` both streams buffered whole, which is the documented memory cost of the one-liner; a child with unbounded output is what `spawn` is for. `spawn` leaves all three pipes open in a `Child`.
- `Child` gained `exited`/`code` beyond the sketch: `wait` and `is_running` share that state, so a second `wait` returns the first result instead of calling `waitpid` on a reaped pid, and `is_running` is a `WNOHANG` reap that *records* the exit it observes (which is why it takes `mut` where the sketch wrote a shared receiver). `kill`, `exit` and `getpid` are the sketch's, unchanged.
- The externs stop short of knowing any struct: `spawn_raw` sets four `mut i32` out-parameters (pid and three descriptors) and `reap_raw` returns a code, so `Child` and `RunResult` are built by ordinary Kelp. The one place C has to name a Kelp type is `execvp`'s `char*[]` marshalling, which spells `kelp_List__String` and `kelp_String.data` literally commented there, and the reason a real generic container would remove a wart.
- `run` is written in Kelp on top of `spawn`, which needed one compiler rule changed: a gated module's functions were unreachable **from inside that module** (`std/process` holds no grant, so its own `spawn` did not resolve). The gate now exempts a call whose callee is declared in the calling module the gate exists to stop *other* modules naming the resource, and nothing outside the compiler can declare a gated item (`stdlib::domain_of` only knows stdlib ids), so the exemption cannot widen a user module's authority. `std/net` uses the same shape (`net.send_all` calls nothing gated, but `std/net`'s own internals are reachable from inside it).

**argv, the one compiler change the sketch predicted**
- The emitted entry point is now `int main(int argc, char** argv)`, and both values are saved into two runtime globals that only `std/process`'s externs read (`process.arg_at` hands out a `&str` view of one, which is safe because they live as long as the process). `main` itself stays uncallable from `.kp` and still takes no hidden passdown parameters. That is open item 50, closed.
- `arg_count` plus `arg_at` build `process.args()` as an ordinary Kelp loop; a `String` per argument is the cost of an owned list, and `&str` is not an element type.

**Three bugs this milestone found**
- **An empty buffer held a NULL `data`.** `kelp_Bytes__empty`/`kelp_String__empty` set `data = NULL` with `len = 0`, so `Bytes.empty().as_str()` returned NULL and `print` of an empty owned buffer passed NULL to `printf`. Invisible in the existing suite; AddressSanitizer caught it on the first `io.read_all()` of an empty stream, because the ASAN pass gives the child no stdin. Both constructors now allocate the single NUL byte the invariant always claimed `data[len] == 0` *including* `len == 0` so `as_str`/`%s`/`strlen` can never be handed NULL.
- **A `File` write and the builtin `print` did not interleave.** `print` and templates go through stdio's buffer; a `File` writes straight to the descriptor, and stdio block-buffers a pipe, so `print("a")` followed by `File.write_str("direct")` was observed as `directa`. The write primitives now flush the matching stdio stream first (`kelp_io_flush_stdio`), which restores call order in both directions without making `print` unbuffered.
- `Child` and `RunResult` cannot be partially moved, so a library module returns the whole `RunResult` and reads `r.out` through a borrow; `Line` is the same shape, which is why `BufReader.read_line_into(out)` exists next to `read_line()`. Not a new rule, but the first API designed around it.
- **A grant with an empty pattern list emitted no allowlist.** `generate` skipped the generated `kelp_caps_<module>_<domain>` array when the pattern list was empty, but a module *can* hold a domain with no patterns that is precisely how `process.args`/`process.exit` are reachable without granting any program and a call that names a resource still needs an array to deny against. The generated C then referred to an undefined symbol and `cc` rejected the program. The empty list is now emitted as `{ NULL }` and denies with `granted: (nothing)`, which is what makes `with caps(process = [])` a usable grant; `process_argv_only` pins it.

**Fixtures and tests**: `io_stdio` (read one line, then `read_lines` for the rest, a `File` write on stdout, `eprint` on stderr, `wait_writable`) run twice once with four lines piped in and once with nothing, so the end-of-file path (`ok = false`, zero lines) is pinned as well as the data path; `io_streams` (a caller-held `BufReader`, then the same reader's `read_all`, `read_into` at end of file with the buffer untouched, and a zero-timeout poll); `process_spawn` (argv marshalled through to the child's own `$1`/`$2`, an exit code, separated stdout/stderr capture, `spawn` with a write to stdin and a read of stdout, `is_running`/`kill`/`wait` on a child that cannot exit by itself, a failed `exec` reported as code 127 rather than a panic, and our own `argv`/`getpid`). The test harness gained `assert_fixture_runs_with_stdin` (and a `run_fixture_with_stdin` form with a distinct binary name, because two tests over one fixture would otherwise race for one output file), plus `assert_project_runs_with_args` for the argv case. Project `process_run` puts the calls inside a granted library module and checks the granted path plus `process.args`; project `process_argv_only` grants `process = []` argv and `exit` reachable, nothing executable and is run with two arguments, which also pins the empty-allowlist emission; project `process_denied` grants `process = ["/bin/true"]` and calls `/bin/sh`, so the denial is a *grant* denial rather than a missing grant, and the message names `runner`, the call site and the pattern list. All three fixtures are in the AddressSanitizer pass. Two deviations from the test sketch: the "helper `.kp` binary read from a scratch file" argv case is replaced by `sh -c 'printf %s-%s "$1" "$2"' sh one two`, which proves the same property (the child sees the marshalled array) without a second binary and without a scratch file; and the grants name both `/bin/**` and `/nix/store/**`, because on this NixOS machine `/bin/sh` is a symlink into the store and the check resolves it before matching (the `caps_symlink` rule, now exercised on `process` as well as `fs`).

### MK5-S4 keep-alive, the connection pool, and the HTTP client (the payoff)

*Deliverable*: `http.get("http://host/path")` returns a parsed response; redirects, timeouts and header lookup work; the body is `Bytes`; and a `Pool` keeps connections **alive and reused**, so N requests to one host cost one handshake instead of N. *Gate*: `net` (the module holds it, delegated by the importer see the capability section for how a library module is governed by the patterns it received).

*Decisions recorded before this milestone, all of them the owner's*:

- **Order is keep-alive → framing → pool.** Pooling before keep-alive is a no-op: the client shipped in MK5-S4's first sketch sent `Connection: close` and closed after one request, so there was nothing to keep. Keep-alive is mostly "stop asking the server to close, frame the body, honor the server's own `Connection: close`, retry a stale socket once".
- **The pool ceiling is configuration, not an API argument**: `coral.toml`'s `http_pool = <n>` (default 4; `0` disables pooling). This is the first *numeric* manifest value, and MK5-S4's only compiler-side change.
- **The pool is lazy.** Connections open on first checkout and stay open. "A number of connections always open" is read as *never closed on release*, not *pre-warmed at startup* an eager pool makes startup **worse** by N handshakes, which is the opposite of what a pool is for. `mut Pool.warm()` exists for a caller that knows when the next request is coming.
- **Pooling buys steady-state latency, not startup.** One handshake and one slow-start ramp per `(host, port)` instead of per request: ~0.05–0.2 ms on loopback (invisible), but 100 requests to a 50 ms-RTT host save ~5 s of pure connection setup. TLS (MK5-S4b-M1) is what makes the pool genuinely valuable, and it is that much more expensive per connection.
- **No concurrency in MK5-S4.** Threads come first (MK6-S1-M1), then multithreaded downloading (MK6-S2-M1). Poll multiplexing is recorded as the MK5-S4c fallback that needs no language work at all if MK6-S1-M1 slips.
- **Chunked encoding is no longer deferred.** With keep-alive, a chunked body is the one kind you cannot frame any other way, and the read-to-EOF fallback would block until the peer closed. So the chunked decoder ships *in* MK5-S4 instead of panicking a reversal of the plan's earlier "deferred, and an explicit panic", for a reason that only appeared once keep-alive was decided.

*The pool owns descriptors; a lease is a ticket.* The sketch had `Lease` own a `Socket` that does not survive v1's rules: a parameter is a borrow, so a `release(lease: Lease)` could never move the socket back *out* of it, and there are no partial moves to take a field out of a local either. What shipped instead is the standard shape: `Pool.idle` is a `List<i32>` of descriptors, `checkout` pops one (or connects a new one), `release` pushes it back or closes it, and `Lease` carries only the descriptor and `reused`. The ownership property the milestone is *for* survives intact `release` consumes the lease, so releasing twice or using a lease after release does not compile and the exchange itself never names the pool, which is what keeps poll multiplexing and a future worker thread possible without redesigning the API.

*`size` is a ceiling on what is kept, not on what may be open.* A request that arrives while every kept connection is busy gets a fresh one and the pool decides afterwards whether there is room to keep it, so a program never fails because its pool was small the same reading Go gives `MaxIdleConnsPerHost`. `checkout` therefore has no failure path at all, which is why it needs no `Ok`-shaped result in a language with no `Option`.

*Honest framing of what is and is not new here.* The pool itself is not an idea Kelp invented Go's `MaxIdleConnsPerHost`, reqwest's `pool_max_idle_per_host`, Python's `HTTPAdapter(pool_maxsize=…)` and OkHttp's default pool are the same design, which is a good sign (the semantics are known-good) and a reason not to market it as a language feature. What Kelp adds is that a lease is *owned*: `checkout` moves the socket out and `release` moves it back, so using a returned lease, releasing one twice, or holding one past its pool's lifetime are **compile errors**, with no lock, no refcount and no GC involved. That falls out of the memory model for free. The pitch is "connection leases are ownership-checked", not "we have a pool".

*Why threads are not the answer to this particular problem, even once MK6-S1-M1 exists.* Downloading is I/O-bound: the bottleneck is the network, not the CPU, so N threads mostly buy N idle stacks in a blocking `recv`. For a downloader the ranking is poll multiplexing (one thread, many sockets, no context switches), then an event-loop/async shape, then threads. Threads win when there is CPU-bound work to overlap (parsing, decompressing, hashing) or when blocking code is worth more than throughput. Two further honest caveats, recorded so they are not discovered later: **N parallel downloads from the *same* host are often slower than one keep-alive connection**, because per-connection server limits and TCP fairness decide the outcome and bandwidth is the ceiling parallel wins *across many hosts*, where latency dominates; and the win has to be measured, not assumed. That is why MK6-S2-M1 is a milestone with a benchmark gate rather than a feature announcement.

*Compiler work*: three changes, and the last two are the reason this milestone is worth reading. (1) **Config plumbing** (planned): `coral.toml` gains a numeric `http_pool` key the manifest parser accepted only double-quoted strings and rejected `[sections]`, so a bare integer is new and the value replaces `__KELP_HTTP_POOL__` in `std/http`'s shipped source before lexing (`stdlib::source_configured`, with the default substituted on the `source()` path so `is_some()` stays a plain "is this module shipped"). (2) **`\r` was not an escape.** The lexer's fallback passed an unknown escape through as the bare character, so `"\r\n"` decoded to the letter `r` followed by a newline: every request this client built was malformed, and nothing said so. `\r` is now decoded, and an unknown escape is a diagnostic naming the five that exist instead of silently becoming a different string. (3) **`codegen_c::c_string_literal` did not escape CR** with (2) fixed, the *generated C* contained a raw carriage return inside a string literal, which is not a string literal; CR and every other control byte are now escaped (`\r`, and three-digit octal for the rest, never `\x`, which would swallow following hex digits). Both escape defects are pinned as byte values by `escapes.kp`, and the rejection by `unknown_escape.kp`. So MK5-S4's own claim ("adds no compiler work at all") was wrong twice over, and the honest summary is that a protocol needs a lexer that means what it says.

*Risks*: parsing without a view type allocates a header line's *name* prefix is not expressible as a view (open item 22), so a 20-header response allocates ~40 `String`s; acceptable at v1 scale, and the reason a length-carrying view is the highest-value language item after generics (open item 44). The chunked decoder is genuinely new surface: it is the first place the client must *interpret* a body rather than accumulate it, and it needs hex parsing (`str.parse_u64` is decimal only, so the size line is decoded by hand). Redirects are where the capability model gets *good*: a redirect to another host is a request the code did not name, so it re-runs the connect path and panics unless the grant covers the new host that is the feature working, not a limitation. Still absent, deliberately: gzip/brotli, HTTP/2, cookies, proxies, `Expect: 100-continue`, idle-connection reaping (a reaper needs a clock, which would make `std/http` hold `time` as a second capability open item 56).

*Deviations the language forced, all recorded because they cost real time.* A shared borrow created in a **binding initializer** stays live to the end of the block, so `val h = host.clone()` is fine but nothing may mutate the pool in the same block after reading one of its fields as a `&str`; the pool's fields are copied into locals first, and an idle count is read inside a `{ }` block (the workaround open item 30 documents). No **partial moves** means a helper cannot *return* a field of a local `datac`: the sketch's `Redirect(follow, url)` became `follow_url(...) .R: String` returning an empty string for "do not follow", and a `Next`-shaped datac could not carry the request body at all, because a parameter is a borrow and a borrow cannot be moved into a struct. A `mut` receiver needs a mutable place, so `var pool = http.pool(...)` a pooling client cannot be a `val`, which is the borrow checker saying something true. And the harness's scratch directory is now `/tmp` literally rather than `std::env::temp_dir()`: a capability pattern is *source text* (`/tmp/kelp_caps_<name>/**`), so a `TMPDIR` pointing elsewhere had the harness preparing one directory while the program read another a latent fragility in the MK4-S1-M1 tests that this milestone's first full-suite run exposed.

*The bug the example found, and why the projects could not.* Locating the end of the header block was `str.index_of(buf.as_str(), "\r\n\r\n")` and `Bytes.as_str()` **validates utf-8**. The buffer holds whatever arrived alongside the headers, so the first response with a binary body panicked before the headers had been found, with `Bytes.as_str: input is not valid utf-8`. All four projects above send ASCII bodies (`hello`, `chunk!`, `byebye`, `got:payload`), so they were green; a 200 KB image is what exposes it, and writing the example is what wrote that test. The scan is byte-level now (`find_head_end` compares four bytes through `Bytes.get`), and the header text is extracted by copying into a buffer that `String.from_bytes` validates and *adopts*, so a malformed header block is loud rather than a `String` that lies about its own invariant. The general lesson, worth applying to every future parser in this stdlib: **a framing scan is byte work, and the first non-ASCII byte that shares a read with the frame will reveal whether you knew that.**

*What MK5-S4 must not close off* (the owner's "build it as open as possible"): no global mutable state anywhere in `std/http` no `pd var` pool, because a single global pool would serialize every future thread behind one exclusive borrow; a `Lease` that is an owned movable value, so a thread can own one once move-taking parameters exist; no `panic` where a retry is the right answer, because `kelp_panic` is process-wide today and would kill every other in-flight download in a future worker thread; and no borrow of a pool held across an exchange.

*Tests*: a loopback server is **required**, and the harness owns it. The client blocks inside `send` until a response arrives, so one process cannot be both ends the way MK5-S3's `net` fixtures could. `kelpc/tests/compile_and_run.rs` therefore gained a `CannedServer` (bind `127.0.0.1:0`, hand the port to the program through `argv`, serve canned bytes per connection, count what it accepted, and give up after 20 seconds so a wrong client *fails* rather than hangs) plus `assert_project_served`. The connection count is the assertion that matters: it turns "the pool reused the socket" into a test result instead of a timing inference, and it is the only way to observe a connection that was *not* reused. Four projects, all loopback, never the internet: **`http_get`** (`http_pool = 2`; five requests a framed `200` with a header, the same URL again, a chunked body, a `404`, and a `Connection: close` body read to end of file which must arrive on **one** accepted connection, with `pool.len()` at 1 and then 0 because the close response is not kept); **`http_redirect`** (a relative `Location` followed on the *pooled* connection, then a POST through `http.post_text` on a second one two connections, asserted); **`http_pool_off`** (`http_pool = 0`: the same two requests now cost **two** connections, which is also the regression test for the compiler's config substitution); and **`http_redirect_denied`** (the server answers `301` with `Location: http://localhost/a` under a grant naming `127.0.0.1:*` → the second hop is denied before any connection, and the test asserts the capability message, the capability model working rather than a limitation). Not shipped from the sketch: a timeout case `net_timeout` already pins `Socket.set_timeout`'s "timed out" panic, and the pooled path applies the same timeout through `connect_configured`. Fifth test, and the one that paid for itself: `the_download_example_writes_exactly_what_it_received` compiles `examples/download.kp`, serves it a body holding a NUL and invalid utf-8, and compares the file on disk **byte for byte**. It failed on the first run on a real bug (below) that all four synthetic projects missed, because every one of their bodies was ASCII.

### MK5-S5 maps, fs/OS breadth, and the real `env` (DONE)

*Deliverable*: a keyed container, the filesystem functions that are cheap once `List` exists, and `env` bodies that are not stubs. *Gate*: none for `Map`; `fs`; `env`. Shipped in three commits (the code in `42d6eca`, `6641e6c`, `df2df76`; this record in the commit that follows them).

#### Part 1 the builtin `Map<V>`

`Ty::Map(Box<Ty>)`, a `map_sig` beside `list_sig`, a `write_map` beside `write_list`, a `Map#` arm in codegen's call-naming switch, and a drop that frees each key, then each value if it needs freeing, then the table. The sketch's shape held: `String` keys, a monomorphized value type, FNV-1a over the key's bytes, open addressing with tombstones, insertion order from `keys()`, `get` borrowing an owned value and copying a `Copy` one, `insert` copying the key and moving the value in, `remove` moving the value out, `get_or` cloning the existing value and dropping the fallback it did not need.

*The one design choice worth recording*: insertion order is a requirement, not a nicety, so entries live in a **dense array in insertion order** and the hash table is a separate **open-addressed index of `entry index + 1`** (`0` empty, `SIZE_MAX` tombstone). A removal marks the entry dead and tombstones its index slot rather than shifting anything, so the order is stable and the entry indices the index points at never move. The value is held through a pointer, which is what lets the map typedef still be emitted before every `datac` (the same emission-order constraint `Box`/`List` taught in MK3-S2-M2); a `datac` value is named by its forward-declared struct tag.

*Two gates the element check forced*: `get_or` and `values` copy or clone a value *out*, which a `datac` cannot do, so they are offered only for a clonable value type (`types::list_clonable_elem` the same gate `List.slice` uses). `Map<Map<i32>>`/`Map<List<i32>>` are impossible by `is_map_element`, which delegates to `is_list_element`; `Map.of` does not exist because a map starts empty, and `Map.new()` takes its value type from the binding because it cannot name it (`Map.new()` with no annotated type is a diagnostic that says so).

#### Part 2 fs breadth and path polish

Nine fs functions and four path ones, all ordinary Kelp over six new externs. `mkdir_all` is one recursive C extern on purpose: the public call is checked against the grant once, on the whole path, and a recursive Kelp version would have had to check each prefix including the prefixes *above* the granted root, which is exactly what a grant on `/var/lib/app/**` does not admit. `remove_all` is the recursive Kelp walk `caps_list` already proved, now shipped; `walk` is stack-driven DFS with fresh joins per entry (see the borrow note below); `copy` is one `sendfile(2)` loop; `touch` is `open` + `utimensat`; `open` returns `std/io`'s `File`, which is the bridge from a path to the descriptor API (and works without the caller importing `std/io`, because method resolution reads the type's owner from the merged module table); `read_lines` is `read_text` + `split`, dropping the empty string a trailing newline would leave; `temp_path` is `mkstemp`; `metadata` is five `stat`s behind one `datac`, because an `extern` returns one value and a `datac`-returning body would have to name the generated struct. `path` gained `stem` (owned a prefix cannot be a view, so the sketch's `.R: &str` was not expressible), `has_extension`, `split` (non-empty components only) and `join_all`.

*Two capability-matcher gaps this part flushed out, both earlier code, both now pinned.*

1. **`fs.open`'s mode string was being matched as a path.** The `fs` domain matched *every* `str` argument as a path (which is what makes `rename` and `copy` check both ends), so `fs.open(path, "r")` normalized `"r"`, found it not absolute, and denied it. `fs` now names its resource arguments per call (`stdlib::fs_checked_args`), the shape `net` already used for `net.send_text(s, text)`-style mixed signatures. The rejection is loud at the call, which is the right place.
2. **A trailing `/**` did not admit the granted directory itself.** `kelp_glob_match` matched `**` as "one or more segments below", so `/tmp/app/**` denied `/tmp/app` and `fs.mkdir_all`/`fs.remove_all` walk up to (and back down to) exactly that path. This was invisible in every existing test because the *entry* module holds the whole-resource wildcard `/**` (which matches everything by construction), and the delegated modules only ever touched paths strictly below their root. A trailing `/**` is now zero or more segments, so a grant on a tree covers the tree's own root. Both gaps are the kind MK5-S4 warned about: a check that is never exercised on the path that matters is not a check.

*The borrow rule that shaped `walk`, recorded because it cost three rewrites*: a shared borrow created in a binding initializer or a condition stays live **to the end of the block** in v1, so a local that has been `as_str()`ed cannot later be moved in the same block, and `x.as_str()` on a *temporary* is rejected outright (`require_place_for_borrowed_arg`). `walk` therefore builds three fresh joins per entry one moved into `out`, one probed with `is_dir` and left to drop, one moved into the pending stack and `path.join_all` tracks a `first` bool rather than reading `out.as_str()` back. This is the MK5-S4 "binding initializer borrows last to the end of the block" note again, now pinned by a working pattern rather than a workaround.

#### Part 3 the real `env`

The domain, the grant and the runtime name check were already real; only the bodies were stubs. They are now `getenv`/`setenv`/`unsetenv` behind four externs, and `env.unset` (which the sketch had and the stub module never declared) joined the surface. The point the milestone proves is the ordering: the check is on the **name**, *before* the call, so a grant on `PATH` does not let the holder ask whether `HOME` exists the denial is a property of the name, not of the answer. `env.names()` stays absent: listing is reading all of it. `caps_env` now proves the real behaviour (read `HOME`; set, read, unset and confirm-gone `KELP_ENV_PROBE`), and `caps_env_denied` proves the denial names the attempted variable and the granted pattern.

#### Tests

Six `Map` fixtures (scalar and owned values, a `datac` value plus a `datac` field that owns a map, `get`/`remove` panics, three rejections), with the allocating ones in the AddressSanitizer pass; `caps_fs_breadth` (one delegated grant on a scratch directory, created and removed by the program: `mkdir_all` three deep, `read_lines`, `metadata`, `copy`, `open` + `read_all`, `touch`, `walk`, `temp_path`, `remove_all`); `path_polish`; and the two `env` projects. The suite is **65 unit tests and 160 end-to-end tests**, all green; the fs-breadth project was also run under AddressSanitizer by hand.

*Deviations from the sketch, all recorded*: `path.stem` returns `String`, not `&str` (a prefix is not a view; open item 44 is what would make it one). `Map.get_or`/`values` are clonable-only. `fs.metadata` costs five `stat` calls. There is no `Set` and no `env.names()`.

### MK5-S6-M1 cheap half the error-`datac` convention, and `errno` in a panic (DONE)

MK5-S6-M1 is the `Option`/`Result` decision point, and it stays open: tagged unions, a way to take a value out without leaking, and generics for the payload are three language features, not stdlib work. What shipped is the half the milestone itself named as cheap, and the reason to do it first is that it makes the eventual migration mechanical.

- **The error-`datac` convention is documented, and the audit changed no code.** `basicstructure.md`'s naming rules now state it: `ok: bool` first; the success payload named for its type (`value` for a number, `text` for a `String`, `bytes` for a `Bytes`, `at` for an index or offset); a `message: String` when the failure is textual. Every error `datac` the stdlib already ships conforms, so each one becomes a `Result` carrying the same field names inside `Ok`/`Err`, with the old name kept as a wrapper. The set is small and closed: `Line(ok, text)`, `Match(ok, at)`, `ParseInt/ParseUint/ParseFloat(ok, value)`.
- **A failed syscall now names its cause.** `codegen_c`'s runtime gained three printers: `kelp_panic_at(msg, code)`, `kelp_panic_errno(msg)` (which is `kelp_panic_at(msg, errno)`), and `kelp_panic_gai(msg, rc)`. Each prints the unchanged `panic: <msg>` line and then a detail line `errno N: <strerror(N)>`, or `getaddrinfo: <gai_strerror(rc)>`. The prefix line is byte-identical to before, which is what keeps every existing golden assertion (all of them `needle` assertions on the message) passing untouched; the detail is additive.
- **`kelp_panic_at` takes the code because cleanup clobbers `errno`.** Six call sites clean up between the failing call and the panic (`fs.read`'s two `fclose`s, `fs.sync`'s `close`, `fs.copy`'s three `close`s) and `net.connect`/`net.listen` sweep a whole `addrinfo` list, so the failing code is captured into a local (`int e = errno;` / a `last` updated in the loop) before any of that runs. `kelp_panic_errno` reads `errno` as its argument, so the `fprintf` inside the printer cannot clobber what it is about to report.
- **`getaddrinfo` reports through its return code, not `errno`.** All three call sites (`net.connect`, `net.listen`, `net.resolve`) now capture the `int` and pass it to `kelp_panic_gai`. Without that, a typo'd host would have printed `errno 0: Success`, which is worse than no detail at all.
- **What deliberately did not change**: argument-validation panics (`str.byte` bounds, `fs.open`'s mode string, `path.normalize`'s absolute-path rule, `process.arg_at`, the two `unknown address family` cases) have no `errno` to report; the short read/short write cases (`fs.read`, `fs.write`, `fs.write_text`, `fs.append`, both `rand` reads) are ambiguous between an error and a short count on a descriptor that was just sized, so they stay on plain `kelp_panic`; and `net.recv`/`net.recv_into`'s `EAGAIN` path keeps its specific "timed out" message, which is the diagnosis, not the `errno`.

**Tests**: `tests/fixtures/fs_errno.kp` (`fs.read` on a missing path) with the new `assert_fixture_panics_all(name, &[needles])` helper, which is `assert_fixture_panics` generalized to require several needles; the test asserts both the stable prefix and `errno 2: No such file or directory`. The suite is **65 unit tests and 161 end-to-end tests**, all green.

### MK8-S1-M1 part 1 `enum` tagged unions and pattern `when` (DONE)

Part 1 of MK8-S1-M1, which the roadmap had parked as backlog item A-1 (now `backlog.md`'s A-1): the language work `Option`/`Result` was blocked on. The decision came first, because `syntax.md` is the authority on syntax and had none: **`enum` with payload-carrying variants**, chosen over a `sum` keyword and over teaching `datac` a second layout. Three questions were settled together, and each answer removed work. The two `when` forms never collide, because the boolean form has **no scrutinee** (`when { cond -> value }`) while the pattern form has one (`when s { Variant(bind) -> value }`) — so no lookahead, no new keyword, and the boolean form keeps its parser desugar. A payload **binds as a copy when it is `Copy` and as a shared borrow otherwise**, so a pattern never partially moves the scrutinee, which v1 has no machinery for. And an enum is a `Ty::Struct` at the type level, so nominality, `Copy`-ness, drop and the borrow checker needed no new type dimension — only a declaration table, a pattern checker and a C layout.

- **One merged declaration order (the structural piece).** A `datac` field and an `enum` payload may each name a type declared *before* them by value, so the two declaration lists had to become one sequence: the parser numbers every `datac` and `enum` with a shared counter, `resolve.rs` renumbers them into module-load then local order, `types::owned_types` walks that order for one-pass drop analysis, and codegen emits typedefs in it. `types::owned_structs` became `owned_types(structs, enums)`; `Ty::Struct`'s tag/typedef/drop-function naming needed no change, which is the payoff of the shared representation.
- **Layout.** `typedef struct tag_Shape { int32_t kelp_tag; union { struct { double kelp_r; } kelp_v_Circle; ... } kelp_v; } struct_Shape;` — the tag is the variant index, each payload lives in a struct of its own inside the union, and a payload-less variant still gets a member with one `char` field (an empty struct and an empty union are both invalid C, and `enum Flag { On Off }` would produce both). Construction is a C compound literal — `(struct_Shape){ .kelp_tag = 0, .kelp_v = { .kelp_v_Circle = { .kelp_r = 2 } } }` — and a payload-less variant needs no initializer beyond the tag, since C zero-initializes what the designators do not mention.
- **Drop is a tag switch.** `write_enum` emits a drop function that switches on the tag and drops only the live variant's owned payloads; a variant with none contributes no case. `owned_types` marks an enum as needing drop if *any* variant does, because the switch is the only thing that knows which one is live. Pinned by ASAN: `enum_owned` (an owned `String` payload, a payload inside a `datac` field), `enum_recursive` (a `Box` chain), `enum_container` (an enum carrying a `String` inside a `List`, plus a `remove`).
- **Pattern matching lowers in `infer.rs`, not in codegen.** `check_when` checks the scrutinee, resolves each arm's variant, checks arity, checks each payload binding, then folds the arms into a chain of TIR `if`s whose condition is a new `EnumTag` node (`<base>.kelp_tag == i`) and whose arm body is preceded by `let`s built from a new `EnumField` node (`<base>.kelp_v.kelp_v_Circle.kelp_r`) — a *place*, which is what makes the owned-payload borrow work through `borrowck`'s existing rules with no new case in the drop plan. **The last arm becomes the base `else` and gets no tag test of its own**: after every other test has failed only its variant can be live, and (unlike a chain that can fall off the end) the `if`-as-a-value lowering then assigns its temporary on both paths.
- **Exhaustiveness, and what is refused.** Every variant must have an arm or an `else` must be present, and the message names the missing variants. Also refused with a real message, each a fixture: an unknown variant (the message lists the variants), a variant matched twice, a binding count that does not match the payload, an `else` arm that is not last, a scrutinee that is a temporary (a payload borrow has to outlive the arm, so bind the value to a `val` first), a scrutinee that is a `datac`, `Shape(...)` (an enum is constructed by naming a variant), `Shape.Circle` without a call (the message shows the call to write), `.field` on an enum value, a method on an enum, an `enum` and a `datac` sharing a name, an enum payload naming the enum by value, and an arm whose body type differs from the others.
- **`when` as a call argument (a lexer interaction the change flushed out).** Inside `(` `)` the lexer emits no newline tokens at all, so an arm there had no possible separator and *any* `when` used as a call argument failed to parse — pre-existing, and invisible until the pattern form made `when` an ordinary expression worth passing. The arm separator is now optional: an arm is `head -> value` and `->` appears nowhere else in the language, so the next head is unambiguous either way. `when_in_args` pins it.
- **`Map.empty()` generated a call to a function that did not exist (a second pre-existing bug).** `infer.rs` accepted both `Map.new()` and `Map.empty()`, but only `Map.empty()`'s key was distinct and codegen only ever emitted `__new` — so `Map.empty()` compiled to `kelp_Map__X__empty()` and `cc` rejected it. Nothing had asked for it until a `Map<Shape>` did. Both spellings now lower to one key.

**Tests**: three accepted enum fixtures (`enum_basic`, `enum_owned`, `enum_recursive`), two more covering containers and `when`-as-an-argument (`enum_container`, `when_in_args`), and thirteen rejections driven from one list. The allocating ones are in the AddressSanitizer pass, so "only the live variant's payload is freed" is a test result rather than a claim. Two parser unit tests pin the declaration form, the shared `datac`/`enum` declaration counter, the pattern `when` AST, and `else` parsing as a catch-all. The suite is **67 unit tests and 167 end-to-end tests**, all green.

*What this milestone deliberately did not do*: no generics (so no `Option<T>` — that is A-2, MK8-S1-M1's next part), no nested or literal patterns, no guards, no `where`-style binding, and no methods on an enum. Each is a separate decision, and none is needed by the code that exists.

### MK8-S1-M1 part 2 user-declarable generic *types* (DONE)

Part 2 of MK8-S1-M1, backlog item A-2, and the first half of it: `datac` and `enum` declarations may now carry type parameters, and every use site monomorphizes into a concrete type. This is the piece that makes `datac Pair<A, B>` and `enum Option<T>` expressible, which is what MK5-S6-M1's `Option`/`Result` decision was waiting for. What did **not** land, and is now the whole of the remaining work in A-2, is generic *functions* (`fun f<T>`): the syntax is refused with a message that says so, and the type-argument inference machinery it will need is already here.

- **The syntax decision came first, because `syntax.md` is the authority.** The spelling is the one `List<T>` already used, extended to declarations: `datac Pair<A, B>(...)`, `enum Option<T> { ... }`, and `Pair<i32, String>` / `Option<i32>` at a use site. `syntax.md` gained §9.3 (and the `datac`/`enum` grammar lines it had been missing since A-1); its "no generics" bullets in §7.2 and §17 now say what is actually true — generic *types* exist, generic *functions*, receiver methods on a generic type, and explicit type arguments at a construction do not.
- **A declaration is a template, not a type.** `GenericTemplate` keeps the fields *as written* (`ast::FieldDecl`), because a type parameter has no type until an instantiation binds one; the field types are resolved for the first time inside `TypeScope::instantiate`, with a `params` map that is checked before every other name, so `datac Pair<A, B>`'s `A` is the argument and never a type that happens to share the name. `Ty::Param` does not exist — the parameter dimension never reaches the type representation, which is why `needs_drop`, `c_ident`, `Ty::is_copy` and the borrow checker needed no new case at all.
- **An instantiation is an ordinary named declaration.** `Pair<i32, String>` is a `Ty::Struct` key like any other, and `types::c_ident` learned three more manglings (`<` → `__l__`, `>` → `__g__`, space dropped) so it becomes a valid C identifier. Everything downstream therefore works unchanged: field access, `needs_drop`/`owned_types`, the generated drop, `List`/`Box`/`Map` elements, `when` patterns, and the C typedef writer. `Pair<i32, String>` and `Pair<String, i32>` are different C structs with different functions, which is the whole point.
- **The instance tables are shared and filled on demand.** `TypeEnv` holds the templates and an `Rc<RefCell<InstanceState>>`, because every function's `Ctx` is a clone (with its own copy of `structs`/`enums`) yet an instantiation discovered in one body has to be visible to every other and to the final `tir::Program`. `Ctx::struct_def`/`enum_def`/`is_enum` are the three lookups that consult both tables; the raw `ctx.structs`/`ctx.enums` reads were all replaced. An instantiation is marked in-progress *before* its fields are resolved and stored only after, so `datac Node<T>(val next: Box<Node<T>>)` terminates on the key instead of recursing forever, while a field of the same type *by value* is still caught as an infinite size.
- **Reading the fields of a template cannot report its own span.** A field is written in the template's file, but the error is found while checking some other module's function, and the caller attributes the error to *its* own module — so `instantiate` re-points the span at the use site and prefixes the message with the instance (`in 'Holder<str>': field 'x' is a borrowed type`). Without that, the diagnostic would print a location in the wrong file.
- **Type arguments are inferred, and the expected type is consulted first.** `Pair(first = 1, second = "x")` binds `A` and `B` from the arguments' types; `Option.Some(value = 7)` binds `T`; and `val x: Option<i32> = Option.None` — the payload-less case, where the expression itself determines nothing — binds `T` from the expected type. Order matters: the expected type is applied *before* the arguments are probed, which is what makes `xs.push(Option.Some(value = 7))` infer `Option<i64>` from the list's element type rather than defaulting the literal to `i32`. Each argument is also probed against a *field hint* resolved from the bindings so far, which is what lets `Node(value = 1, next = Box.empty())` know the box holds a `Node<i32>`.
- **One topological order for the C typedefs (the structural piece).** A hand-written type may contain an instantiation by value (`datac Holder(val o: Option<i32>)`), and an instantiation may contain another, so the two declaration sets are merged and given a DFS post-order over by-value `Ty::Struct` dependencies (`order_declarations`); dependencies through a container are ignored, because a container holds a pointer and is emitted before every declaration with a forward-declared struct tag. Ties break on the incoming declaration order, so the emitted C stays deterministic. `types::owned_types` and `codegen_c`'s typedef loop both just walk the resulting order.
- **One real compiler bug the change produced and then fixed**: the first cut of the receiver guard called `qualify` unconditionally, which turned an already-canonical receiver (`std.io.File`, rewritten by `resolve.rs`) into `unknown module alias 'std'` and broke every multi-file project test. The guard now tries both spellings and leaves a name that resolves through neither to the ordinary path.

**Tests**: three accepted fixtures — `generic_type_basic` (a datac and an enum, inference from arguments and from the expected type, a nested instantiation, and the same template at two element types), `generic_owned` (an owned payload, an instantiation held by value inside a hand-written `datac`, and instances as `List` elements and `Map` values), and `generic_recursive` (`Node<i64>` and `Node<String>` from one recursive declaration, plus a recursive generic enum through two boxes) — and ten rejections driven from one list: a generic type without arguments, an arity mismatch, an un-inferable parameter, a receiver method on a generic type, `fun f<T>`, a parameter shadowing a builtin, a duplicate parameter, a generic/non-generic name clash, a parameter bound to a borrowed type, and a self-reference by value. The two allocating fixtures are in the AddressSanitizer pass. The suite is **69 unit tests and 171 end-to-end tests**, all green.

*What part 2 deliberately did not do*: generic **functions** (the parser refuses the syntax with a message naming what is missing), receiver methods on a generic type (`fun Pair.first()` — the receiver has no way to say which instantiation it belongs to), explicit type arguments at a construction site (`Pair<i32, String>(...)`, which would need an ambiguity-free expression spelling; inference covers the cases that exist), and type-argument inference through a nested generic constructor (`Box.of(Tree.Leaf)` with nothing to pin `T` — annotate the binding). Each is part of the remaining A-2 work, and none is needed by `Option<T>`/`Result<T, E>` as declarations.

### MK8-S1-M1 part 2 (continued) generic functions, generic methods, explicit type arguments, and generic `Map` keys (DONE)

The rest of A-2, in three commits after the type declarations (above). With these, MK8-S1-M1 part 2 is closed and open item 34 is resolved: `datac Pair<A, B>`, `enum Option<T>`, `fun first<T>(xs: &List<T>).R: T`, `fun Pair<A, B>.first().R: A`, `Pair<i32, String>(first = 1, second = ...)` and `Map<i32, String>` all work.

- **A generic function is a template, and a call site instantiates it.**
  `FuncTemplate` keeps the declaration's parameters, return type and body as written, because a type parameter has no type until an instantiation binds one — the same reason a generic *type* is a template. The type arguments come from the argument types and from the expected type, inferred by the same `bind_type_params` the type side uses, which grew two cases to make that useful: it looks through a borrow on either side (`fun is_some<T>(o: &Option<T>)` called with an `Option<i32>`), and it pairs a written `Pair<T, T>` against an instantiated `Pair<i32, i32>` by reading the instance table's origin. A parameter neither determines is an error that names it, with the fix.
- **The worklist, and why the signature is registered before the body is queued.** An instantiated signature goes into a shared `FunctionState` *before* its body is checked, so a recursive call inside that body resolves to the same instance instead of instantiating again; `check_program` then drains a queue of pending bodies, and checking one can queue another. A generic function that is never called is never checked, which is what makes a body that only makes sense for one instantiation fine as long as that is the one it is used at (`fun Pair<A, B>.first_len().R: usize = first.len()`, called only on `Pair<String, _>`). `main` may not take type parameters, a generic and a non-generic function may not share a name, and a parameter must not shadow a builtin type; each is a fixture.
- **Passdown wiring is the template's.** The passdown scan runs over declarations, and which passdowns a body names does not depend on its type arguments, so `wired` stays keyed by the declaration and a call to an instance looks the template up through the instance's origin. A generic function that prints a passdown is in the suite.
- **A method on a generic type takes the type's parameters.** The receiver writes them (`fun Pair<A, B>.first_of()`), must write exactly the type's own and in order, and a rename or reorder is refused with the spelling to write — the body names them, so anything else would make `T` mean something the declaration does not say. The type arguments are the receiver's *instantiation*, so there is nothing to infer: the call resolves the type template through the instance's origin and instantiates `Pair#first_of` for the receiver's arguments. The instance's key (`Pair<i32, String>#first_of`) is what the call names — the first cut destructured `instantiate_function` down to its signature only and let the call name `Pair<i32, String>#first_of` from `format!("{owner}#{method}")` instead, which `cc` caught as a call to an undeclared function. `receiver_field_ty` now reads through `struct_def`, so the implicit-`self.field` fallback (`fun Pair<A, B>.first_of().R: A = first`) sees an instantiation. An `enum` still carries no methods, generic or not (A-1's rule), and that is now refused at the declaration instead of at the call.
- **Explicit type arguments, and the one ambiguous spelling.** `Name<...>(` in an expression is recognized only when the `<` is written *against* the name and the `(` *against* the `>`, because `a < b > (c)` is a valid comparison chain and the two must not collide. The parser attempts the form speculatively and restores its token position when either half is not adjacent, so a comparison can never be misread as a call; the deliberate consequence is that `a<b>(c)` without spaces *is* read as an instantiation and then fails on `b` not being a type, which syntax.md states as a rule rather than hiding. An explicit instantiation bypasses inference entirely (arity checked, then the parameters bound from the written arguments) and is refused with a real message on a non-generic type, a non-generic function, or a method, whose parameters come from its receiver. A payload-less variant cannot take one — there is no call to attach it to — so `Option.None`'s parameter comes from the expected type.
- **Nested-constructor inference (pinned, not implicit).** `Tree.Branch(label = 9, left = Box.of(Tree.Leaf), right = ...)` binds `T` from the first field and then hands `Box<Tree<i32>>` down as the expected type for the next one, so no annotation is needed anywhere in the tree. It already worked once the bindings accumulated left to right and the field hint was resolved from them; the fixture is what makes it a result rather than a coincidence.
- **`Map<K, V>` — the last piece of "a `Map` with a real key type".** `Ty::Map` gained a key, `Map<V>` stayed valid as the shorthand for `Map<String, V>` (so all 147 pre-existing uses, the stdlib's included, are unchanged and mean exactly what they did), and the key set is closed to `String`, the integers and `bool` because the two operations a map needs — a hash and an equality — are *generated by the compiler* from the key type: FNV-1a over the key's bytes plus a length-aware `memcmp` for `String`, `kelp_map_mix` over the widened value plus `==` for a scalar. A float is refused (`nan != nan` would make an inserted key unfindable) and a `datac`, container or borrow is refused (v1 has no equality for them); a key of the user's own type would need a trait (A-12) or a comparator function (A-4), and that is the honest limit of what generics alone could reach here. `keys()` returns `List<K>` rather than `List<String>`, the map's generated name carries both type arguments, and the entry's key sits inline as the key type itself. The codegen rewrite is one function: `write_map` builds two closures (hash and equality) from the key, and every other line of the map's function set is key-agnostic.
- **One latent generator bug the map flushed out, and no others.** `hash_arg` and `hash_stored` are not the same expression — a `str` view's length comes from `strlen`, a stored `kelp_String`'s from its own `len`, and the equality/drop helpers take the stored key as an *lvalue* rather than a pointer (a scalar key compared or dropped by address is a different expression, and `cc` refuses it as a pointer/integer comparison and a always-true conversion). Both were mine, both were one line, and the second was only reachable through the scalar path.

**Tests**: the type-declaration half shipped with 3 accepted fixtures and 10 rejections; this half adds 7 more accepted fixtures (`generic_function_basic`, `generic_function_owned`, `generic_method_basic`, `generic_explicit_args`, `generic_nested_inference`, `map_key_types`, plus the earlier ones now covered), 12 more rejections, two parser unit tests (the declaration form and the adjacency rule), and the allocating fixtures in the AddressSanitizer pass. The suite is **71 unit tests and 181 end-to-end tests**, all green.

### MK5-S6-M1 `Option`/`Result`, `if let`, `?`, and the stdlib migration (DONE)

The milestone the whole MK5 program was pointed at, and the last of the three language features A-3 named (`A-1`'s tagged unions, `A-2`'s generics, and now the propagation surface). Four commits, each one a phase: `if let`, `?`, the two stdlib modules, then the migration off the error-`datac` convention. The language half and the stdlib half were chosen together, because the migration is what proves the surface is usable.

- **`if let` is a parser desugar, and that is the whole of it.** `if let Circle(r) = shape { ... } else { ... }` becomes `{ val #iflet0 = shape  when #iflet0 { Circle(r) -> { ... } else -> { ... } } }` — the pattern form of `when` (A-1) with one arm and an `else`, so infer, borrowck and codegen needed no new case. Binding the scrutinee to a local first is what makes a **temporary** legal here; a bare `when` needs a place, because an owned payload binds as a borrow of it. `let` is read as the pattern form only directly after `if`, so nothing is reserved and the only cost is that a binding *named* `let` cannot be an `if` condition without parentheses.
- **`?` is defined on a *shape*, never on a name.** The operand must be an enum held by value with exactly two variants named `Ok`/`Err` (the failure carries a payload) or `Some`/`None` (it does not) — so `std/result`'s `Result`, `std/option`'s `Option` and a program's own declaration all work identically, and the compiler knows neither module exists. The enclosing function must return the same shape, and for `Ok`/`Err` the same failure payload type: v1 has no error conversion, so `Result<i64, String>` cannot leave a function returning `Result<i64, IoErr>`. `tir::ExprKind::Try` carries both enum instantiations and both variant indices; codegen emits a statement expression that evaluates the operand once, rebuilds the failure on the failure tag, and is otherwise the success payload. The temporary is deliberately never dropped — exactly one variant's payload moves out on either path, so dropping the rest would free what moved — and `borrowck` treats `Try` as a whole-value read, which moves a named operand and still refuses an owned *field* as a partial move. An early return drops the frame's locals (that was already true), so `a?` mid-function leaks nothing, and the ASAN pass proves it over owned payloads.
- **`std/option` and `std/result` are Kelp, and thin on purpose.** The enums are the point; the helpers are `is_some`/`is_none`/`unwrap_or`/`unwrap`/`expect` and `is_ok`/`is_err`/`unwrap`/`unwrap_err`/`unwrap_or`/`expect`/`expect_err`. What is missing is documented in the modules: `map`/`and_then` need function values (A-4), and anything that hands a payload out by value needs a move-taking parameter or a clone, so those helpers are offered for a `Copy` payload and are a compile error at any other instantiation — the rule `List.get` already follows.
- **Two language gaps the modules forced, both fixed rather than worked around.** First, *divergence*: a function body whose tail is `panic(...)` now satisfies any declared return type, which is the only way a "this cannot happen" accessor is expressible at all; `infer.rs` accepts that tail, `codegen_c.rs` writes it as a statement rather than `return kelp_panic(...)`, and the panic printers are `_Noreturn` so no missing-return warning is left. It is deliberately narrow — a `panic` cannot be an `if`/`when` arm — and it is the whole divergence rule. Second, *name resolution*: a bare name inside a module is that module's own item, but the call-resolution order tried the unqualified key first, so a bare call inside `std/str` could resolve to a same-named function of the entry module (`index_of(s, needle)` there picked up a test fixture's `index_of(&List<String>, &str)`). `check_call`, `resolve_overload` and `func_template_named` all try the calling module's own spelling first now, which is what the strict module-qualified namespace always said. Type-argument inference needed the matching fix: a written type resolves against the module the *declaration* was written in, so `r: &Result<T, E>` inside `std/result.kp` is `std.result.Result<T, E>` no matter who calls it.
- **The migration, and the one rule it needed.** `Line(ok, text)` became `Option<String>` (end of file is not a reason), `Match(ok, at)` became `Option<usize>` (same), and `ParseInt`/`ParseUint`/`ParseFloat(ok, value)` became `Result<T, ParseErr>` with `enum ParseErr { Empty Invalid }` — a real reason, two variants wide, with `Invalid` covering everything the C conversion refuses including an out-of-range value, because the primitives report one bit. That is the rule the two modules state applied for real: **a failure with no reason is an `Option`, one with a reason is a `Result`**. No old names survive as wrappers: a wrapper would keep the old call shape compiling and hide the point of the milestone, and the repo has no external callers to protect. Call sites became `if let`/`?`: `str.contains` is one line, `std/http`'s five `index_of` sites are `option.expect(o = ..., message = ...)`, and the four HTTP test projects' `server_port` is `result.expect(...)`. The one deliberate non-migration is `http.content_length_of`'s `-1` for an absent header — absence is not a parse failure and the value is a count whose every non-negative value is meaningful.

**Tests**: `if_let_basic` (place and temporary scrutinees, `_`, `else`, `else if let` chains, the no-`else` `Unit` form, an owned payload), `try_operator` (Result and Option, chained across two frames, an owned payload through both, `?` mid-expression), `stdlib_option_result` (both modules, `?` through two frames, `if let` over both, and the same-name-in-two-modules regression), `panic_tail`, and the migrated `stdlib_parse`/`stdlib_build`/`string_views`/`io_stdio` fixtures; 8 rejections across the three features; two parser unit tests (the `if let` desugar and the `?` adjacency rule). The allocating ones are in the AddressSanitizer pass. The suite is **72 unit tests and 187 end-to-end tests**, all green.

*What is left of A-3*: `?`'s restriction to an identical failure type is the honest edge of a language with no traits — an error conversion (`From`-shaped, or `?` lifting into a `Box<dyn Error>`) is A-12's work, and so is `map`/`and_then`. Neither is needed by any code that exists.
